# 蜘蛛案例后续开发计划：从跨版对齐到 web 版连续翻译

日期：2026-10-18。基线：`6884698`（P8）。

设计更新（2026-10-18）：后续采用 [独立版本索引与翻译管线接入设计](translation-independent-edition-index-design.md)。P9.3–P9.6 的实施顺序以该文档 D1–D6 为准：双方独立建索引，先做 L2 区块关联和 L1 范围实体匹配，精确范围对齐仅在复用译文/平行示例/参考式评测时按需执行。下文原有的范围核验约束继续适用于这些精确用途；跨版全文作为语言参考另按新文档的用途与可见性策略准入，不要求先逐段对齐。这是设计调整，尚不代表相应功能已经实现。

本计划将高难度样本拆为可独立验收的阶段。目标是以日文 web 版为主文本，利用经核验的文库中文版局部参考，并在无法安全复用或内容不同的范围继续翻译。计划不假设两版能完全对应，也不以全书知识抽取作为翻译启动条件。

样本结构盘点与数据边界详见 [跨版对齐设计](translation-spider-alignment-design.md)。本地 `artifacts/translation/spider-alignment-preflight/` 是忽略文件下的只读派生数据，不进入 Git。

## 目标和完成定义

最终产物是独立分支下按 web 阅读顺序组织的中文译稿及可追溯索引。每个 web 条目都必须有明确处置：已核验的既有译文范围、从日文新译的范围、正文之外的独立处理内容、待解决的数据问题，不能把未对应范围直接算作无需翻译。

文库版中文的使用按用途区分：

- 对于经核验的 `equivalent` 范围，可作为既有译文或有明确标注的双语参考；若目的是盲测模型能力，当前目标范围的文库中文必须封存。
- 对于 `partial` 范围，只能使用通过逐段核验的重合部分；不能把整章摘要或相邻的后续内容带入。
- `rewritten`、`unresolved`、`edition_mismatch` 范围不得作为逐句翻译依据；其中可单独核验并允许使用的专名译法可进入术语参考，不携带剧情事实。
- 被屏蔽的中文原标题原样保存，屏蔽位置作为注记；由日文原题恢复出的名称只能作为有证据的规范化字段，不改写来源原文。

最终完成并不要求“全书零疑点”。它要求输入、译文、对齐、知识和审校都有稳定身份与来源；高风险问题保留为待复核，不以猜测填满。

## P9.0：冻结输入与准入报告

建立专用的 `work_id=spider` 与固定输入 manifest，显式纳入日文 web EPUB、中文 1–16 卷和 Ex；卷号按数值排序，Ex 独立。记录文件 SHA256、EPUB OPF/spine/TOC、href、原生顺序、标题、抽取器版本、段落数和空内容。

检查日文 EPUB 的正文、系统提示、前言/后记和特殊页面；检查中文卷 15/16 人物档案以及 Ex 设定等无法由当前 `<p>` 抽取器读出的布局。将图片文字、表格、空页和真正的爬取缺页分开记录；需要 OCR 时保留页图、OCR 置信和人工校订来源。不要因为正文抽取器没抓到就把条目删掉。

屏蔽文本遵循本项目的双字段约定：`raw_title/raw_text` 永不变；另存 `mask_spans`（原始偏移、掩码字符、检测方法）以及可选 `normalized_candidate`、证据来源和复核状态。日文原题可提供恢复候选，但需逐项匹配，不能进行全局字符替换。索引和展示默认可保留原样，搜索时可使用带通配位置的规范候选，同时记录此变换。

验收：同一输入重跑得到相同 manifest；输入文件 hash 不变；未知类型被保留；屏蔽位置可精确映射回原字符；图片或结构性缺页产生明确 issue。

## P9.1：版本感知语料模型与读取层

给每段内容稳定标识：`work_id / edition_id / document_id / entry_id / revision_id / paragraph_id`。日文 web 与中文文库有各自阅读顺序，中文每卷章号只作为原始标题字段，不再成为全书主键。去重、切段和规范化均通过派生层完成，源文本和 EPUB locator 可回溯。

单独表示条目类别：叙事正文、幕间/侧线、状态/技能清单、作品说明、插图/人物档案、后记、特典、访谈、设定集和未知。类别可多标签，不能把视角标签等同于角色身份。Ex 不自动进入正文顺序。

同时实现范围索引：对齐对象可以是一个或多个章节中的段落范围，必要时精确到段内偏移。允许一个范围局部重叠多个候选但未审核前不进入已确认主映射；经审核的主映射要防止同一段被冲突地重复消耗。添加 schema 与读写测试，确保现有 Tenken 流程仍按原模式运行。

验收：同名卷内章号不碰撞；复合章节和空标题仍可定位；revision 变化会使旧范围失效并告警；现有 P8 测试通过。

## P9.2：人工小型基准集与标注协议

先造小而有代表性的基准，不需要先让模型总结 600 个条目。开发集约 30–50 组候选/负例，另留一份不参与阈值调试的保留集。标注双方精确范围、是否同一事件、逐段覆盖、内容差异、原文阅读位置、中文阅读位置、允许用途和理由。

样本层必须包括：

- web 开篇与中文第 1 卷的序、主线第 1 章、S1 重排和拆分/删改；
- 若干 S/Y/血/鬼/人物独白片段，用来检查叙事线重排与相似事件误配；
- 技能/状态高密度段落和普通战斗/对话对照，确认状态文本不会单独支配匹配；
- web 中部与文库对应卷的候选，以及中文缺页、格式/屏蔽文本样本；
- web 末段与文库 15–16 卷中的真正共同片段、明确改写和结局不一致负例；
- Ex 设定和特典，用于验证它们不会被误并入主线。

双人复核可先用于最危险的负例和范围边界；如果只有一位人工标注，报告应注明。分歧标记为 `unresolved`，不通过多数模型投票制造真值。

## P9.3：全库廉价候选召回，不做自动对齐

离线将两版本都切为段落窗口并生成多语言向量。先小批验证 embedding-3 或当前配置模型在日中场景检索上的表现，再冻结所选模型与参数。向量输入对重复系统提示、模板化技能清单降权或另建索引；正文、标题、专名、列表特征分别保留，候选打分可组合但不输出未经校准的“概率”。

对每个 web 窗口做跨全中文文库的 top-k 检索，同时反向查询；补充标题数字/线标签、屏蔽位置通配候选、稀有词和相邻窗口召回。跨卷、跨条目，不以章号硬过滤。重复叙述可关联多个候选，不要求双向唯一。

报告 Recall@1/5/10、每个正例是否被召回、负例排名、窗口尺寸/重叠对候选的影响以及请求/存储成本。只在开发集上调整参数；保留集只作一次冻结后的评估。高风险正例召回不足时先改召回，不把责任推给 LLM 审查器。

## P9.4：候选核验、范围对齐及审查工具

实现面向人工可读的候选报告：日中原段、邻段、目录/卷位置、召回特征和来源 hash。LLM 可以根据同一材料提出对应范围与差异，但输出必须引用输入段落 ID；无引用、越界引用、主体/结果冲突和模糊范围均转为待审，不自动确认。

对齐关系分为 `equivalent / partial / rewritten / unresolved / edition_mismatch / no_candidate`，与结构拆并关系独立保存。`allowed_uses` 分别标注 `parallel_example / terminology / style_reference / evaluation`；不允许因为故事大意相似便把整章中文准入 few-shot。无候选也要可区分“还没搜到”“源文/译文缺页”“疑似改写”“超出所选文库范围”。

审查人可以确认、缩小或拆分模型范围，添加反证和缺口原因。所有审查作为不可变 patch 保存，corpus hash 或源 revision 变化时旧确认自动失效。

验收重点：人工保留集上的已确认关系 precision 优先达到预设 0.98；若当前能力达不到，就提高弃权并报告覆盖，不降低标准掩盖冲突。列出全部 false positive，尤其是相同技能列表、相同战斗主题、同一事件的不同视角/重复回忆、结局负例。样本较小时同时报告分子/分母和不确定性，不把百分比包装成全书保证。

## P9.5：翻译前的可见性过滤和参考 API

实现 `get_reference_spans(source_span, purpose, web_cutoff, reserved_targets)`。只返回已审核且满足用途的精确中文范围、关系类型、差异、证据和版本。默认拒绝 `rewritten/unresolved/edition_mismatch` 作为逐句参考。术语卡片可从这些范围单独提取，但要与剧情事实、身份别名分开。

可见性以 web **出版阅读位置**为界，故事时间和中文文库阅读位置不能替代它。索引器可以离线访问全库寻找候选；翻译、审校、裁决能接触的字段则经服务端白名单投影。任何被匹配中文范围若附带后续揭露，必须切除后续段，无法切干净则不给事实摘要。屏蔽标题的规范候选只可作为词面检索；不得用它顺带暴露未公开身份。

建立对抗性泄漏测试：把未来真实身份、未来事件和结局分别放入中文候选及索引 metadata，要求当前 web 位置查询不到；跨窗口、压缩摘要、术语检索、审校工具查询也一并验证。安全策略失败就停止翻译集成。

## P9.6：三个窗口的翻译试点与消融

只在 P9.5 通过后调用翻译模型。先做三种窗口，不做全书开跑：

1. 开篇：web 前 30 个条目与中文第 1 卷，测序章、S1 重排、边界拆并和双线语气。
2. 中段：含复杂视角切换、回忆/独白和高密度技能清单的 10–20 个条目；具体范围从已完成召回中选，不能因章号臆测映射。
3. 末段：web 最后约 30 条目对中文 15–16 卷候选，重点检查是否存在只能部分对应或明确终局分歧；Ex 单独做术语/资料检索实验。

每个窗口设置可比小臂：A 仅 web 日文和冻结 web 前文；B 加已核验历史术语；C 再加当前范围的合格双语片段。做“模型生成质量”评测时隐藏目标范围中文；若直接使用 approved equivalent 现成译文，则记为复用覆盖，不能把它计入模型质量得分。其他 prompt、模型、采样和输出上限保持相同，保存完整输入输出与哈希。

人工复核：日文事实忠实度、指代/叙事揭示时点、双线声音、术语一致、技能名/等级准确、标点与中文可读性。分别统计可复用译文覆盖率、人工错误等级、错误强配、剧透、每万字请求成本；不能只用 BLEU/模型自评得出结论。

进入全量前需要：已确认片段无严重剧透泄漏；困难负例未错误复用；至少在一个适用窗口中参考上下文提升了术语/一致性且未损害原文事实。如果参考没有可测增益，可仍继续 web-only 机器翻译，但要关掉低价值注入路径。

## P9.7：全量 web 版分段连续翻译

先冻结目标范围和预算，然后使用 P8 SequenceEngine 思路创建独立 `spider` 运行数据库。新译文目标只依据 web 日文。已有文库译文段落必须在对齐清单里标记为“复用”或“参考”，不可复制进分支却伪装成 LLM 新译。

按 web 原顺序逐批运行，默认每批约 10 个完成条目，边界以实际 entry ID 和源阅读序号记录。每章/条目提交后，才成为后续上下文。增量生成层级摘要和术语候选时保留源段范围、译文范围、知识出处和可见性 cutoff；对于双线叙事，不把视角猜测提升为事实。技能系统消息作为专门列表类型保留，不在摘要中反复膨胀为实体卡片。

恢复与压缩沿用 P8 机制：冻结实际模型 token 配置及预留系数；记录上下文 checkpoint、索引成员、预算累计和恢复次数。失败范围保留原文并标清原因，不让下一章跨过缺口继续形成虚假连续性。每批完成后审计未映射、未译、未覆盖范围。

在全量启动前设总调用/输入/输出预算、每条目最大重试、最大修订轮数和停止条件。先实测 P9.6 各窗口成本估计总账；达到预算上限就暂停并交付已完成前缀与待办位置，不静默扩大预算。具体费率/是否使用云端模型以开跑前配置为准，本计划不预估金额。

## P9.8：审校、覆盖审计和 EPUB 组装

审校需同时看到 web 日文、已封存的对齐证据、当前可见 web 历史和定向词条。裁决只能以当前允许证据确认修改；发现可能涉及未来身份或文库改写，标为待核对而不是用文库最终答案纠正 web。

封存译稿后生成覆盖账：每个 web 段落对应 `reused_equivalent / translated / nonnarrative_handled / unresolved / extraction_issue` 之一。所有正文缺口必须有原因。抽查按风险分层：普通叙事、对话归属、叙事诡计揭示点、状态/技能、跨线回忆、改写/结局。译文最终组装成**新文件**，不覆盖原始 EPUB。

发布前门槛：结构章节顺序一致；正文段覆盖无静默丢失或重复；内部引用均可定位；被屏蔽来源字段未被规范化值覆盖；未解决问题清单可读；独立人工抽样中严重事实错误均已修复或显式标注。

## 工程实现顺序与每次变更的验证

建议分成几次小 PR/提交，顺序如下：

1. 更新 Spider 计划、测试清单与专用语料配置；不触发 API。
2. 实现 manifest reader 与 edition-aware schema；运行现有全量测试和语料 ID 测试。
3. 实现屏蔽字符 span annotation 与来源旁路字段；测试原文哈希不变、候选恢复不覆盖源文。
4. 实现窗口切分、列表分轨和日中候选召回；用 P9.2 基准计算 Recall@k。
5. 实现对齐审核与 sidecar 查询；检查 revision 过期、拆并、不重叠及显式弃权。
6. 实现可见性投影与剧透测试；负例泄漏任一处失败都不得发翻译请求。
7. 完成三窗口模型试点和人工报告，确认策略后冻结全量翻译预算。
8. 分段连续运行、审校、恢复、最终覆盖审计及 EPUB 导出。

每次 API 实验只处理明确冻结的短窗口；记录完整 messages、响应、模型名、token 用量、文件和索引 hash。全量开发中若 prompt 或 schema 改变，另开运行版本，不能拼接成一次模型质量对照。

## 不在首个最小可用版本中做的事

- 不建全书人物关系/时序图谱，不在翻译前要求抽取所有技能实体。
- 不试图全自动判断所有双线角色身份或解开叙事诡计。
- 不要求两版章级完整覆盖，不以强制单调路径处理跨线重排。
- 不全局替换被屏蔽的字符，不将恢复候选覆盖原始标题。
- 不把文库版最终结局或人物档案默认注入 web 前期 prompt。
- 不用自动评分或模型自审替代人工抽样。
