## 3. P8.1：连续翻译与增量索引

先运行 400–402 三章，再在同一分支继续；分段只是观测点，不重置调用账本或把失败任务换个 ID 重跑。一个章节提交后的全文进入后继上下文，旧章尚未提交的草稿和修订版本不冒充最终译文。

复用 `advance_sequence(stop_after=...)`、`materialize_pending()`、`resume_sequence()` 和 `explain_context()`：

- 到实际 L2 边界时，基于本分支新译文和完整日文生成摘要、实体、事件、状态及知情候选。同父 L2 按顺序携带前驱摘要。
- 中文作为本分支译法记录，不作为日文事实权威；引文异常单条隔离，候选不自动晋升为固定规则。
- 未完成或失败的抽取继续保留全文；不能因为节点存在就宣布范围已经压缩。
- 摘要超长记录软警告，实际消息超预算、缺失覆盖、无效证据和严重错误继续按原门槛处理。
- 每章导出完整翻译 IO、最终工作版本、映射、规则信号、审校／裁决、修订链、知识增量及实际／预留用量。

至少在 402、409、419、429、439、450 后保存观测结果；按实际规划边界记录节点，不用整除章号假定索引已闭合。结束后调用 `materialize_pending(seal_tail=True)` 保存开放尾部；51 章不整除 10，一章尾块允许标记最低大小例外。

## 4. P8.2：真实上下文压缩

主实验保留真实模型容量。若自然触发检查点，就记录自然触发的原因和前后预算；若未触发，则在 **main:429 提交后、main:430 翻译前** 显式调用 `checkpoint()`。必须标明为强制压缩实验，不声称是 1M 自然窗口越界。

该时点已连续生成 30 章，通常可得到三个十章 L2：近期保留全文，近块保留详细摘要，更远的生成块进入父级概括，前史仍有明确表示。实际边界以规划器为准。压缩前后必须记录：完整 messages、共同提交前缀、覆盖清单、知识集、摘要修订、token 估计／校准、安全预算、角色输出预留、缓存 usage 及 `compression_target_reached`。

如果压缩后仍能放入硬预算、但没有达到目标占用，记录未达目标并继续；硬预算失败则停止且保留完整未发送诊断。超长短概括不自动失败；生成后比原摘要更大时保留原规范摘要。

为观察语义影响，对 main:430 做一个最多两次调用的共同前缀配对：

- U 表示：压缩前完整会话。
- H 表示：同一组已提交译文和知识，改为压缩后的表示。

两者使用相同模型、源文、温度与输出预算，不携带目标参考；它们只比较上下文表示，不能各自用不同的前 30 章生成译文。配对输出单独冻结，不以较流畅者自动替换主分支。主分支继续 H；可复用完全相同请求的已保存 H 输出，避免额外付费。若 U 确实放不下，保留诊断而不谎称完成两臂对照。

在一个中间观测点正常退出并重新打开数据库，验证不重复已保存请求、不重复工作提交、索引成员和活动检查点一致；结束后再做一次零调用恢复审计。
