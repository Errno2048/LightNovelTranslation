# 蜘蛛 Web / 文库版对齐试点结果

日期：2026-10-18。代码基线：`6884698`。本轮新增内容尚未提交。

已经实现版本隔离语料、段落窗口、跨全库候选召回和带引文的候选复核，并在真实 EPUB 上运行。当前产物是一份**待复核的部分对应候选集**，没有任何范围被自动批准为可复用译文，也没有宣称全书对齐完成。本次恢复工作复用了保存的向量和模型响应，新增 API 请求为零。

正文窗口以最多 2,400 个 Python 字符、相邻 1 个片段重叠划分；过长段落按句末或硬边界拆分。窗口保存段落 ID 和段内字符偏移。检索为全库余弦 top-8，加反向排名；条目层最多汇总 5 个候选。没有强制卷序、章号或全局单调路径。候选分数不是等价概率，互相命中也不是接受条件。

本次 LLM 试点选择 5 个 Web 窗口，每个窗口挑选最多 5 个不同中文条目的候选，共 25 对。这里的“5 个”不是连续 5 章，也不是全书抽样覆盖率；同一中文条目内的其他候选窗口没有都送审。

这些例子支持采用范围级部分对应：Web 序章和后续条目可分别落在同一个文库章节内；S 线可以独立定位；中段正确候选不一定排在第一。它们没有证明整章、整卷或任意重排都能准确对齐。

例如 C019 的证据引文为：

```text
JA: 迷宮に入ってから５日目。 / 俺たちは迷宮の半分を走破していた。
ZH: 进到迷宫的第五天。 / 我们已经走过半个迷宫。
```

双语短引文均已逐字验证并回查冻结语料的段落/偏移。**这些偏移只覆盖引文，不等于共享内容说明中所有事件的完整对应范围。** 下一步仍需扩展并核实两侧完整边界、覆盖与缺口。

## 暴露的问题

### 主题相似会产生高分假阳性，模型复核也可能误收背景重合

Web 序章的 top-1 是第 6 卷的另一场景，而真正的开篇重合排第 4。蜘蛛、魔王、勇者、迷宫等高频设定能带来较高相似度，不能直接设置一个相似度阈值就批量接受。

25 对的原始模型判定是：20 对 `unrelated`、4 对 `partial`、1 对 `equivalent`。程序将同时报告增删差异的 `equivalent` 降为 `partial`，因此有效建议为 20 对无关、5 对部分对应。

其中 **C016 仍是疑似误报**：Web `S25` 的具体队伍行进场景，被模型与第 11 卷 `SS 艾尔罗大迷宫的冒险者们` 的背景介绍判为部分对应。模型自己的差异说明已经承认“具体场景不同”，共享信息只剩迷宫庞大、危险等设定。这不能成为逐段双语对应。该候选没有获得允许用途，后续应在人工基准中作为“同设定、不同事件”的困难负例保留；有引用和 `high/medium` 自报置信度均不能替代语义核验。

本轮没有独立人工开发集/保留集，因而**不报告 Recall@k、全书 precision 或可复用覆盖率**。上面的模型关系计数不能当作这些指标。

### 结尾召回不足，尚不能定位分歧边界

Web `web-main:OPS/page599.html` / `エピローグ` 的末窗口，选中的 5 个中文条目候选均被模型判为无关。这些候选主要来自较早卷次，未定位到可信末卷重合。

这只能说明本次候选池未给出可信对应，不能据此证明文库没有相关内容，更不能确认两版结局从哪里开始分歧。下一轮应扩展末段窗口及 top-k，并定向检查第 15–16 卷；仍保留全局候选，卷范围只作为补充召回，不能强配。

### 列表过滤已起效，但尚无纯列表检索样本

保存的窗口累计识别 1,552 次系统/列表片段，检索文本较原窗口累计少 65,303 字符；计数包含重叠窗口，不是去重后的段落/正文删除量。原始证据文本始终保留。

全部 2,103 个窗口都混有叙事，因此轨道均为 `narrative`；不是检测器零命中。实现支持纯列表窗口的 `status` 轨道，但本次语料没有产生这种窗口，不能声称已完成独立技能清单召回效果验证。单项技能、列表表头等也未被当前保守规则穷尽识别。

### 非正文布局与屏蔽仍需保留边界

问题清单有 17 个空标题/封面条目、8 个疑似标题屏蔽标记、11 个纯图片或布局条目。后者包括第 15/16 卷人物档案及 Ex 设置等，当前没有 OCR，也没有擅自记为正文缺页。标题里的 `N/Q` 只记录原始偏移，未全局替换。

## 本轮工程修正与验证

- 窗口按版本内全局阅读顺序排序，段落按原生顺序排序，避免卷内编号在跨卷时交错。
- 缓存统计区分成功缓存响应的原始用量与本次新增用量，重跑不再将历史输入 tokens 覆盖为零。
- 冻结配置检查前不覆盖窗口；离线候选重建验证窗口文本/轨道指纹、向量覆盖和文本 hash。定位刷新只允许改定位元数据，并保留原嵌入批次顺序。
- 重复出现而无法消歧的引文、损坏的定位元数据和未覆盖的引文字符会被拒绝。双语引文不能只返回真实字符串却没有段落定位。
- 复核脚本默认按原实验保存的候选/prompt 回放，核对当前窗口正文和版本；离线重建后的相似度微小数值变化不会改写旧实验输入。有旧原始响应但未解析完成时停止重复付费请求，要求先检查该响应或另建实验目录。

离线审计核对语料版本指纹、窗口嵌入输入指纹、保存的完整 prompt/response、候选输入以及 5 对双语引文到原始段落的 17 个范围。全部通过；`approved_for_translation=0`。

窗口定位刷新、候选重建和原响应回放均已实跑，新增模型请求为零。相似度重算在本机出现约百万分之一量级的浮点差异，25 对试点的候选排名未变；机器复核继续绑定原请求中的分数与正文，报告中的试点分数也保留原值。

## 产物与复现

相对运行目录的重要产物：

- `corpus/{manifest.json,entries.jsonl,paragraphs.jsonl,issues.jsonl}`：来源与版本隔离语料。
- `main/{windows.jsonl,candidates.jsonl,entry_candidates.jsonl,candidate_report.md}`：正文候选；`extra-reference/` 单独保存 Ex 召回。
- `request_configuration.json`、`requests.jsonl`、`window_vectors.jsonl`：嵌入冻结配置、请求账本与本地向量。
- `llm-review-pilot/request_response_raw.json`：完整 system/user 输入、原始响应与 token 用量；`review.json` 保存候选全文和解析结果。
- `offline-audit/{audit.json,reviewed_candidates.jsonl,report.md}`：本轮离线复核、候选关系表和模型报告的重合/差异。`reviewed_candidates` 仅表示机器复核，状态仍为 `pending_human_review`，用途为空。

以下命令不发起 API 请求：

```powershell
.venv-test/Scripts/python.exe scripts/audit_spider_alignment.py
.venv-test/Scripts/python.exe scripts/rebuild_spider_candidates.py
.venv-test/Scripts/python.exe -m pytest -q
```

`review_spider_candidates.py` 在当前缓存存在且输入一致时只重新解析；新目录/无缓存时会调用模型。`run_spider_alignment.py` 的非 `--corpus-only` 模式允许按预算发起嵌入请求，故本轮没有重跑。窗口排序规则修正后，重新构建整套运行应使用新目录；现有冻结产物继续按保存顺序复现。
