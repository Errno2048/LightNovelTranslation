# P6：局部事件、人物状态、知情边界与对白分析

日期：2026-10-16。

状态：已有局部分析原型，已完成第1200章两轮真实试验，尚未通过P6抽取与翻译收益验收，详见 [P6试验结果](translation-p6-results.md)。本文后续各节保留目标设计，不能视为所有接口均已实现。P5代码基线为 `85a9d4a`，标签 `p5-baseline`；当前工作位于 `p6` 分支。

当前实验揭示的待解决问题和建议优先级见 [P6剩余问题与优化方向](translation-p6-open-issues.md)。

2026-10-17 近期范围调整提案见 [P6最小可用方案](translation-p6-mvp-design.md)：延后独立抽取语义审查，优先实现有界重试、三角色按需查证和数字信号裁决。本文的完整目标设计继续保留；历史未通过验收的结论不变。

## 1. 本阶段要解决什么

P6在既有分层前情之上增加有原文证据的局部状态与场景工作集，帮助翻译模型判断当前是谁、发生了什么、谁知道什么，以及一句话可能由谁说出。重点处理因人物、事件或信息边界缺失造成的歧义。

[P5最新试验](translation-p5-audit-v2-results.md)显示，当前模型仍有局部含义漏检、错误裁决、重复位置漏修和证据误用。P6可以改善资料组织与推理输入，但不能承诺修复一般日中语义能力问题。“寝息→打鼾”一类错误继续留在P5回归集中；不能通过增加知识卡片就把它记为已解决。

本阶段可以在P5工程接口已具备、质量验收未通过的条件下推进。P6生成的真实译文仍是 `draft_for_review`，接受规则继续由P5执行。P6工程通过、知识抽取质量、翻译收益、真实译文接受分别报告。

首版范围：

- 复用现有100章一级／10章二级的懒索引和邻近完整双语；标题与摘要继续承担导航。
- 从少量相关原文窗口提取场景、明确事件、人物状态观察、实际译名用法，以及对白候选。
- 按故事锚点和人物视角查询；允许未知、冲突、多个候选以及弃权。
- 实现精确可执行的正文取证，使“需要某个技能的用例”可以先搜索，再定位具体段落。
- 使用可替换的模型角色配置，分别测资料抽取和翻译利用能力。

全书精细事件抽取、通用世界模拟、嵌套“甲知道乙相信丙……”推理、完整梦境／平行世界推演、连续翻译自动调度及压缩仍不在首版范围。后两项归P7；P6保存其所需的增量和依赖接口。

## 3. 数据契约与时间语义

每条记录带 `schema_version`、稳定ID／修订ID、来源版本、精确段落或字符范围、依赖闭包和审阅状态。实体ID使用不暴露身份的内部标识；中文姓名、别名及身份对应独立保存。

| 对象 | 必需内容与首版用途 |
| --- | --- |
| `EntityMention` | 原文形式、出现位置、候选实体、消歧证据；同名不同人可并存，别名不自动全局合并。 |
| `Scene` | 源段范围、时间锚点／分支、地点观察、在场候选、叙述视角、转场和未决事项。 |
| `StoryAnchor` | 场景／事件／明确日期的锚点；分支ID；未知时不编造日期。 |
| `TemporalConstraint` | 锚点间的before／after／during／overlaps／same约束，原文依据、推导链及冲突组。 |
| `Event` | 事件类型、参与者和各自角色、时间约束、来源位置；多方事件不压成一条无角色的关系边。 |
| `Proposition` | 可引用的命题身份：主体、谓词、对象／值、否定和适用范围。人物可以对同一命题持不同态度。 |
| `StateObservation` | 某实体在某锚点被观察到的地点、所属、持有物或能力状态；记录适用范围和最后观察点。 |
| `PerspectiveAssertion` | 世界叙述／人物声称／相信／怀疑／明确不知／获知等，持有者、命题、通道、时间及证据。 |
| `UtteranceAnalysis` | 原文话语范围、说话者／受话者候选、表达通道、指代候选、正反证据和弃权理由。 |
| `TranslationUsage` | 双语中的实际译法、作品内描述及适用人物／说话者／区间；历史出现不等于全书规范。 |
| `StateBundle` | 本次选中的场景、事实、候选、译法证据、未决需求、遗漏理由、预算和完整依赖。 |

首版状态谓词采用小型登记表：位置／在场、所属或明确关系、持有物、能力可用性。人物知情单独建模。模型不能任意新增一个谓词再假定它具有永久持续、互斥、对称或传递性质；不支持的类型保留为候选说明。

### 3.1 三条独立轴

1. **故事时间**：事件何时发生，或某状态在什么场景成立。
2. **揭示位置**：原文在什么章节、段落向读者提供该证据。
3. **知识版本**：系统何时接受、修正或撤销这条记录。

第70章回忆第10章之前的事件，不能因为后来读取就覆盖第70章的当前状态。对第20章的可见前缀查询也不能使用第70章才揭示的证据。知识纠错用修订关系表示，人物离开公会用新的事件及状态区间表示；两者不能共用“删除旧边”的语义。

### 3.2 首版时间求解范围

实现same锚点归并、after转before，以及同一故事分支内严格before的传递查询；严格顺序环构成冲突。during／overlaps保留有证据的直接约束；端点可比较时校验区间，否则返回不确定，不扩展成通用时间逻辑求解器。

约束图出现冲突时保留相关边及证据，并隔离受影响结论；不按置信度自动删除一条边来“修好”年表。不同分支之间没有明确桥接关系时不可比较。回忆需要映射到主线的过去锚点；梦境、假设和被转述的故事先使用独立分支，无法确定则返回 `unsupported` 或 `uncertain`。

`valid_to=None`不能统一解释成永远有效。区分明确结束、观察时仍成立、结束未知和整个时间未知。没有足够证据证明目标时点适用时，可以返回 `last_observed`，但不能把“上次看见在王都”输出成“现在仍在王都”。持久状态只有在明确登记的持续规则和已知范围内才可推导，推导项带规则与依赖；不以“未抽取到离开事件”证明一直没有离开。

## 4. 知情与对白：保留不确定性的具体规则

世界事实、某人的说法、某人的信念和系统推断分别存储。`A说p`只支持“发生了该发言”，不会自动确认p。A说了假话也不自动证明A蓄意撒谎；还可能是误解、转述或试探。

知情查询返回有依据的态度集合及 `supported / contradicted / conflicting / unknown` 状态。没有记录某人知道，不推出其明确不知道；“明确不知”需要原文证据。听到一个命题不自动等于相信，更不等于命题为真。同场人物也不自动听到念话、内心独白或悄声对话。

对白首版采用两步：

1. 确定性标记可能的话语范围和邻接原文，模型区分对白、内心活动、念话、转述、引用和被括起来的技能名。跨段对白保留范围链，不能通过补闭引号修改原文。
2. 模型给出说话者、受话者和指代候选，并为每项列出可定位依据。动作和明确发言标签优先；称呼、自称、语气和人物状态提供辅助线索。

不以“只有甲应该知道这件事”强行排除其他人物：对方可能猜测、撒谎或引用。人物不在场也不能单独排除远程通信。角色语气资料须来自有可靠归属的原段，不能依据性别或角色类型创造口癖。

每项分析区分 `explicit / inferred / ambiguous / unsupported`。只有明确原文或经过审阅的消歧依据才可作为强约束；其余以候选提供。中文能保留原文含混时，保持含混，不补“某某说道”、性别或身份说明。不能把候选列表第一项当成确定答案。

## 5. 可见性、准入和来源管理

资料能否读取、事实是否适用于故事时点、译文是否应显式写出，是三次判断。翻译整章可以读取本章完整日文，但某句中人物的知情状态必须按那句所在场景判断；章尾揭晓不能被前面的角色提前知道，也不能被翻译模型提前加进原文含混的表达。

P6沿用顺序前缀策略：允许的历史原文／中文、本章日文；目标中文、保留来源和未来正文继续隔离。历史摘要若混入未来或隐藏内容，不能因为只取一条元信息而复用。折内检索排序、实体合并、别名选择和图投影都必须在允许范围内完成。

实现时不能直接把P4的 `hidden_source_ids` 当作P6的“隐藏目标译文”：旧接口会连目标原文一起屏蔽。P6使用与NarrativePolicy一致的源／译访问区分，通过显式适配器读取历史知识和任务原文；旧策略含义不改。目标原文的overlay走任务来源验证，目标中文始终禁止。历史提交接口拒绝混入当前任务overlay，工作集指纹同时绑定历史提交与overlay身份。

准入分三层记录：

| 状态 | 可以做什么 | 不代表什么 |
| --- | --- | --- |
| 格式有效 | 存储并读取结构化候选 | 关系或时间正确 |
| 证据绑定 | 该标签确实指向允许的原段 | 原段支持模型的解释 |
| 语义审阅通过 | 在明示范围内作为已审知识使用 | 跨全书永久成立或所有人物知晓 |

初版真实窗口的确认知识采用具名原文审阅，模型可以提出复核意见但不能仅靠同模型自我确认晋升。审阅者如为开发代理，应记录为开发审阅，不称独立人工金标准。另一条实验臂可以注入证据已绑定的模型候选，必须清楚标为未审候选，并独立衡量它带来的错误。

旧P4 assertion不具备新契约要求的全部审阅信息，不自动迁移为P6确认事实。旧摘要和实体卡作为线索；实际译法仍须回到允许的双语正文。关系变化、别名身份揭示和旧记录撤销均保留版本，派生查询和bundle检查完整依赖闭包。

## 6. 检索和懒构建

固定保障仍是完整近章、既有分层前情和核心人物的有限描述。细粒度抽取按需要执行：本章出现的实体、当前场景中的状态变化、影响代词或敬称的歧义，以及有具体证据缺口的术语。

执行链：标题／摘要／实体线索 → 允许范围内的正文搜索 → 返回稳定证据ID及邻段 → 分析或明确未决。标题未命中不会阻止正文召回；“没有命中”只说明当前检索和覆盖情况，不说明作品不存在该事实。首次以精确形式、允许的别名和字符检索为主，embedding不是前置条件。

针对P5的技能译名失败，新的需求应可表达为：`search_evidence(query="虚言の理", languages=["ja"], purpose="historical_usage")`。服务返回实际章号和段落，再读取对应允许中文；不让模型生成“涉及某技能的章节”来冒充可执行章号。

读取已建摘要、读原文、搜索和状态查询均为零生成调用；缺二级索引时可直接读命中原文。只有显式enrichment计划可以付费构建或抽取，并列明范围、模型、用途、输入／输出预留及缓存身份。本阶段试验不新增全书摘要，不重建已有一级索引。

每个分析任务最多一次取证后的模型续答，实际工具动作和字节／token量另设上限；同一问题重复请求去重。默认每个窗口最多4个不同查询、每次最多8个候选命中，再读取选中证据及有限邻段。历史未决需求随结果保留，预算用尽不写成“没有问题”。这些是P6独立计划的上限，不更改旧P5修订链的两次查询限制。

### 6.1 两类分析prompt

事件／状态抽取输入为：允许资料的证据标签表、相关已审实体描述、本章完整日文、最近2章的可见完整双语，以及命中的少量历史原段。既有一级／二级摘要用于选取线索；需要加入时明确标记未审和覆盖范围，不让模型从概括直接复制出确认事实。日文支持事件和世界状态，中文仅支持实际表达用法。当前待审草稿和目标参考中文都不进入抽取prompt。

任务要求按场景检查动作执行者、体验者／受益者、对象、否定、条件、时间表达和信息获得通道，输出有证据的最小记录。没有变化或不足以确定时允许少输出；不要求每章填满人物关系表。每条记录绑定现有段落标签，涉及具体台词时绑定原文字串或经校验的字符范围，程序生成ID与hash，模型不计算这些值。

对白分析输入同一原文和邻段，以及前一步分区标记的场景、状态候选与未决项。候选仍是候选，不能因为由前一步提供就变成前提事实。要求列出候选依据、反证和表达上是否需要消歧，不要求给每句强行指定唯一说话者；最终只翻译的模型不接收开发评估答案。

输出沿用有版本的平面记录：`@@SCENE / @@EVENT / @@STATE / @@PERSPECTIVE / @@USAGE / @@UTTERANCE / @@NEED / @@SUMMARY / @@END`，不同任务只开放必要记录类型。枚举、引用和列表字段分别校验；未识别类型隔离，缺少完整结束或覆盖声明不能当作成功。格式转录只处理可证明内容完整的记录，不补人物、日期、引用或缺失字段的语义值。语义审阅与格式恢复使用不同产物。

## 7. 对外API与上下文形式

以下是P6目标API，尚未实现。读接口无模型调用或知识提交；返回值包含 `status`、`coverage`、`evidence_refs`、`dependencies` 和 `view_fingerprint`。

```python
commit = state.commit(review.historical_items, branch=..., expected_head=..., idempotency_key=...)
overlay = state.freeze_overlay(review.task_items, task_id=...)  # 当前章分析
# snapshot_id与branch_commit二选一；重开视图，绑定新提交及当前任务overlay。
task_view = state.open_view(
    branch_commit=commit["commit_id"], analysis_overlay_id=overlay["id"],
    policy=..., target_position=..., story_anchor=..., perspective=...,
    purpose="translation",
)
bundle = state.compile_context(task_view, source_ranges=..., mode=..., token_budget=...)
```

图是以上状态查询的投影：节点为实体、事件和必要命题，边携带时间、视角、证据和状态。默认1跳，最多2跳、64节点、128条记录；达到上限返回明确的截断与遗漏信息。与入选事实相关的冲突不得被截掉后只展示单边结论。原始历史无需画成一张所有边同时有效的大图，首版不引入图数据库服务。

CLI按 `python -m translation.state` 提供 `plan / analyze / review / timeline / state / information / dialogue / compile / explain`。模型读工具使用有限枚举动作和真实ID，不能执行模型给出的Python或SQL。旧 `KnowledgeBase.open_view` 收到不能处理的时序／视角参数时须明确报未支持或转入新视图，不再静默忽略。

编译顺序为现有固定规则／三层前情 → 近章完整双语 → P6相关状态和对白说明 → 目标原文及翻译任务。P6块分别展示已审事实、实际译法、未审候选和未决问题；不把推断与事实混成一段无来源的故事介绍。

默认P6增量软预算为8000 tokens，先取相关核心人物、当前场景和能影响表达的证据；预算不足时列出遗漏项。关键约束、相关冲突和必要原文无法容纳时明确失败，不静默截断。底层上下文上限仍按所用模型配置计数；现有1048576预算不因这个增量软预算被改小。新模型使用自己的已验证上下文／输出配置。

稳定历史资料前缀继续复用，当前场景与对白分析放在尾部。状态快照或来源变化后生成新bundle身份，不为保留缓存继续使用旧事实。P7再处理跨章追加、压缩和检查点。

## 8. 模型替换与实验分工

角色分别为 `state_extractor`、`dialogue_analyzer`、`translator`、`reviewer`、`adjudicator`；可指向相同提供方，也可独立替换。配置保存公开模型身份、端点、prompt版本、温度、思考参数、token计数器和预算，密钥只通过既有本地配置／环境变量读取。

当前模型先作为可复现基线，不继续靠无限prompt迭代要求它通过P5。更换模型时只改变指定角色，不同时更换摘要、知识和翻译配置。新端点先用小请求验证实际能力与参数；未配置第二模型时标记“未做跨模型验证”，工程开发与mock验证继续进行。

P6中模型抽取的错误不能成为解释翻译失败的盲点。因此同一开发窗口设置三臂：

| 实验臂 | 输入差异 | 用途 |
| --- | --- | --- |
| `B` | 冻结的既有分层或近章上下文 | 同批次重新生成基线，旧草稿只作历史对照。 |
| `D-reviewed` | B加依据相同可见原文、经过开发审阅的P6工作集 | 检查翻译模型能否利用正确资料；工作集不包含理想中文译句或错译答案。 |
| `D-candidate` | B加模型自动抽取、证据绑定但未作语义确认的P6候选 | 衡量完整自动链路的收益和污染风险。 |

原计划D的名称保留；本轮清单明确 `base_context=H-tiered` 或 `H-near`，不能把不同基础上下文混为同成本对照。若新目标没有合法的完整分层前缀，两臂统一使用H-near；不能复用包含未来内容的摘要，也不能悄悄删掉必需的一级块。

归因口径：D-reviewed有效而D-candidate无效，优先分析抽取／证据准入；两者均无效，检查工作集选择与翻译利用能力；正确资料进入prompt后仍被错误表达，登记为模型利用或指令执行失败；被裁决模型忽略则单列审校问题。不把任何一类失败简单归为“图谱不够大”。

## 10. 验证集与验收条件

### 10.1 离线必测场景

| 场景 | 必须得到的结果 |
| --- | --- |
| 第10章加入、第40章离开、第70章回忆此前相识 | 分别回答故事时点状态和读者可见证据；第20章前缀看不到第70章证据。 |
| 再次加入同一组织 | 两次关系区间并存，不抹掉离开事件。 |
| 状态只有最后观察点 | 未来时点不冒充确定仍成立；显示最后观察及未知。 |
| A声称p而相信非p，B听到A发言 | 不把p确认为世界事实，也不把B听见当成相信。 |
| 没有记录C知道p | 返回unknown，不能返回明确不知。 |
| 多人在场但使用念话／内心独白 | 不将内容传播给所有在场者。 |
| 后文揭晓化名或同名两人 | 早期视图不泄漏规范身份，不进行无条件全局合并。 |
| 对话有两个合理说话者 | 保留两个候选和证据；中文不被迫增加人名／性别。 |
| 两条时间约束构成严格环 | 保存冲突并阻断受影响确定结论，不静默选边。 |
| 摘要／别名排序依赖隐藏来源 | 抽取、排序及编译均拒绝这条依赖，不能只在最终字符串过滤。 |
| 原文修订、知识撤销、已接受译文失效 | 派生状态／图／bundle需要重建；不能继续命中旧有效缓存。 |
| 不存在的证据ID、截断、格式损坏、预算耗尽 | 明确失败或未决；原响应保存，失败不得被算作空结果成功。 |

### 10.2 真实样本与评价顺序

首轮3个开发窗口：第1200章、第1233章，以及一个从既有开发范围选择、原文确有回忆或关系变化的窗口；每个以一个目标章及有限邻章为单位。选章时仅查看允许原文，记录选择理由。P5旧问题用于回归，不把这两章冒充新验证。

每个窗口的固定完整邻章从前2章开始，不加入目标章之后的正文；目标章本身提供完整日文。远处证据通过本阶段有界取证补充。旧分层上下文的来源闭包仍完整登记，不能因为P6只抽取了几个段落而缩小其实际依赖。

另选3个P6验证窗口，在开发prompt冻结后使用，覆盖有证据的时间／关系变化、知情不对称和无标注多人对话。不得挪用此前划定的P8最终保留来源。P6.0先检查可用来源是否足以覆盖这些类型；不足时报告缺口，不用没有相关现象的章凑数。冻结样本ID、来源hash、政策和基础上下文，验证输出产生前完成原文标签。

开发窗口执行B／D-reviewed／D-candidate三臂；验证窗口执行B／D-candidate两臂。所有配对共享目标源文、允许历史范围、翻译模型与输出设置。目标参考中文只允许在生成完成后通过单独评估入口读取，不能反馈到本轮工作集。语义评估优先原文，参考译文不是唯一正确答案。

分别统计：抽取关系／角色错误、时间适用错误、人物知情错误、实体误合并、对白候选覆盖与弃权、错误显式化、译文目标错误减少及新增错误、取证成功／失败、每窗口实际调用量与tokens。只在确有标签的子集统计准确率／召回率，正文其余部分仍可能有未标注错误。

### 10.3 三个验收结论

- **工程验收**：上述离线场景通过；隐藏资料进入模型为0；读操作触发生成调用为0；确切缓存重放新增HTTP为0；无未经记录的事实晋升、静默截断或原响应覆盖。
- **知识质量验收**：真实样本中每条注入的已审事实均可核对其原文支持、时点和视角；错误确认项一旦发现即修订并让依赖失效。候选的正确率单独报告，不把候选多解释为覆盖完整。
- **翻译试验验收**：对3个冻结验证窗口给出完整配对错误表；新增的严重时间／身份泄漏／错误知情为0，P6目标错误总数下降且未以新增其他严重错译换取。若不满足，P6功能可以完成工程交付，但保持可选，不标质量通过。即使满足，也只记录小样本改善信号，P5自动接受门槛不变。

如有第二模型配置，另开同输入对照，只替换一个角色，并增加一次单独冻结的预算计划。当前计划不以更换模型为开始开发的前置条件，也不把现有模型的单次成功当作稳定能力证明。
