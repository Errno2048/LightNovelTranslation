# 分层剧情摘要方案评估

日期：2026-10-15。结论：值得作为下一轮知识构建方案试验。正文容量支持按篇章完整阅读；效果仍需验证，不能从上下文上限推出摘要完整性或翻译质量。

设计更新（2026-10-16）：采用“近章完整双语、近块整体及详细摘要、远块整体摘要”的确定性编译方案，已完成 P4.1 工程与单章真实对照，质量收益尚未证实。正式契约见 [分层叙事索引设计](translation-hierarchical-context-design.md)，实际成本、摘要修复与负例见 [P4.1 结果](translation-p4.1-results.md)。本文保留原容量评估，不代替质量试验。

原容量评估轮仅下载公开文档和 tokenizer，并在本地计数，生成、embedding、在线分词请求均为 0，未改变 P4 冻结产物或运行配置。后续 P4.1 生成调用另在结果报告计账。

## 1. 实测范围与方法

使用 `tenken-cache-clean/corpus`，仅统计 narrative 条目的 body 段落，排除前后记、独立附录、重复正文、网站按钮及译者注；不纳入两份日文人物/技能资料页。保留正文空段形成的换行。此为容量统计，不授予任何章节新的知识或评测使用资格。

使用 ModelScope 的 `ZhipuAI/GLM-5.3-Flash` 公开 tokenizer，核对下载文件 SHA-256，仅用 `tokenizers` 读取数据，无远程代码执行。计数为公开 tokenizer 对文本的本地结果，不包含服务端聊天模板、工具定义和输出；不是 API 账单。

原始结果、逐章计数、语料哈希和 tokenizer 来源见：

- `artifacts/translation/tenken-cache-clean/verification/summary-feasibility/measurements.json`
- 同目录 `measure.py`、`tokenizer-provenance.json`、`sources.json`

## 2. 模型与端点边界

本轮读取的官方 GLM-5.3-Flash 文档标称 1M 上下文、128K 最大输出；同时注明思考模式仅支持 enabled。公开模型能力不等于已经对用户当前 Coding 端点完成 1M 实测。P4 的短请求成功记录不能证明长请求的时延、超时、完整输出或工具循环能力。

当前 provider 配置及 P4 历史运行中的 thinking 设置需要在下一次试验前与现行接口约定核对；本轮不修改历史配置，也不由文档差异推断过去请求失败。输入预算应使用选定模型 tokenizer，并为系统消息、摘要导航、输出（包括供应商计入输出预算的推理）和工具结果留出余量。

官方页面快照在测量目录 `model-doc.md`、`pricing.md`、`coding-faq.md`，来源和哈希在 `sources.json`。部分页面在网页检索工具中超时或不支持 Markdown，快照通过 HTTP 读取；模型规格另以国际站官方页面交叉核对。

## 3. 推荐结构

采用自然语言摘要树即可启动，不依赖完整人物图谱：

```text
可见范围的块目录
  → 各块整体摘要与人物/术语检索线索
    → 连续章节区间摘要
      → 完整原文和已审查的双语证据
```

保留用户提出的 `(全段总结, {章节区间: 摘要})`，增加少量定位字段：节点 ID、精确章节列表、来源 revision、可见截止位置、人物原名索引、重要未决问题。概述负责叙事理解，区间摘要负责检索，原文负责确认细节。

索引与注入层级分开：近章注入完整正文；近块注入整体和区间详细摘要；远块全部保留整体摘要。全书总览或更高层压缩是未来可选扩展，不替代初版的远块覆盖要求。

每块首次读取完整正文，直接同时生成块总览和区间摘要，避免先对每一话独立总结再反复压缩造成过多层级。更高层总览可读取子摘要；其来源依赖必须包含子摘要的全部来源。需要关键事实时回到原文取证，不能只引用另一份摘要。

建议以 20～50 话或约 40K～150K 日文 tokens 为首轮候选大小，用标题提出边界，再核对边界附近的正文。50 话极端窗口约 155K，预算应按实测 token 执行，不能按固定话数硬推。1M 保留给自然篇章特别长的情况和对照试验。

本地 EPUB NCX 为平面逐话目录，没有嵌套篇章分组；标题边界需要新增识别步骤。不能把 `Side` 视角切换一律判为新剧情，也不能把相似标题作为同一事件的充分证据。

## 4. 摘要应保留的内容

全段总结保留主要人物、目标、冲突、发展和结束状态。区间摘要额外保留对翻译有帮助的身份线索、关系变化、能力/物品作用、回忆与当前事件的区别、人物声称和叙述事实的区别，以及尚未解决的问题。

人物原名应保留；已有审查译名可并列。摘要自行生成的中文人名不自动升级为翻译约定。事实依据日文，译名/语体依据可靠双语范围；现有译文的漏译和增义不会因进入摘要而变成事实。

“曾经是同伴，后来敌对”可以自然语言保存顺序，不需要立刻推导复杂状态图。摘要引用必须指向具体章节或段落。缺少线索应记录未知，不能为了连贯补出动机、性别或说话人。

## 5. 基本保障：固定三层上下文

默认由应用编译器提供最近 `N_chapter` 章完整原文和允许的完整译文、最近 `N_block` 个可见块的整体及详细摘要、其余全部可见块的整体摘要。初始试验值为 3 章、2 块，均按目标前方计数；当前块若有已读前缀，占一个近块名额。缺译时保留完整原文并登记缺失，不扩大局部双语审查的资格。

按“规则/核心实体插槽 → 远块总览 → 近块总览及详情 → 完整近章 → 目标原文”组织上下文。当前只预留全局重点实体卡接口，不新增角色描述抽取。近章覆盖的详细摘要可按完整区间去重，整体摘要保留；预算不足时明确失败或重新规划，不能静默丢弃远块、减少 N 或裁剪正文。

这个顺序是待验证的上下文组织选择，不保证局部注意力模型可访问所有远程信息，也不保证 KV 缓存命中。完整规则、来源政策和失败行为见 [新设计第 2–5 节](translation-hierarchical-context-design.md)。

主动读取保留为后续扩展：模型可通过 `read_summary`、`read_chapters` 等有界接口确认细节，但摘要完全遗漏的线索可能不会触发提问。现有 `HTTPProvider.generate` 尚无工具循环；本阶段不依赖它，不用“模型认为信息充分”取代三层覆盖检查。

## 6. 可见性和更新

真实续译时使用截至已读位置的前情。某块完整摘要包含块末事件，不能自动作为块首的“此前已知事实”。跨块回忆保留揭示位置；当前人物的知情范围不能由全段叙事总览直接推断。

遮蔽实验必须先排除目标中文及其派生物，再构建摘要；当前政策禁止的验证/盲测资料也不能进入全书总览。生产版全书摘要与实验摘要分开。优先日文事实摘要可减少目标中文污染，但仍须遵守该实验对日文的可见范围。

节点保存依赖，更新原文或遮蔽某章时，只重建受影响节点及依赖它的产物。当前块按精确可见前缀生成和缓存，不从完整块摘要切片。已完成块可复用；增长前缀仍可能反复读取，须单列成本，增量前缀优化留给 P7。

相关研究可用于设计试验：RAPTOR（2024）验证了分层摘要检索在长文问答任务中的作用；Lost in the Middle（2023）提示需要测试长输入中不同位置的信息利用情况。两者都没有直接验证当前 GLM-5.3-Flash 的小说翻译效果，不能据此断言本方案必然提升。论文来源见 `sources.json`。

## 7. 成本

官方标准 API 页面当前列示 GLM-5.3-Flash 输入 0.8 元/百万 tokens、输出 2.8 元/百万 tokens、缓存命中 0.23 元/百万 tokens。该价格仅用于方案估算，不是本轮账单，也不能换算为当前 Coding 套餐的积分消耗。官方 FAQ 对自建应用 API 集成指向标准 API 服务。

全书日文裸正文单遍输入按上述标准价约为 2.34 元；加标题约 2.35 元。这不是知识库构建总价，还需加边界重叠、提示、摘要合并、输出与推理、复核和重试。

例如假设计费输入 3.5M、计费输出 0.2M（包含需计费的推理），标准价约 3.36 元；这是算术情景，不是测得的质量/成本承诺。使用更贵模型或多轮复核按实际单价和用量另算。

后续重复注入也要算：10K 总览注入 1000 次就是 10M 输入 tokens，未命中缓存时约 8 元，高于全书裸正文单遍输入。缓存命中率不能由固定前缀假定，P4 尚无实测缓存收益。

## 8. 先验证什么

先选前部 3～4 个连续允许区块，在可控范围内同时覆盖近章、近块和远块；包含回忆、关系变化及角色称谓问题。固定来源、可见性和模型，比较 P4 C、`H-near`（相同约定＋完整近章）、`H-tiered`（H-near＋三层摘要），分别观察完整近章与摘要的作用；不占用 P6 已定义的 D 名称。晚章缺少更早块总览时，只能标作局部试验。具体任务、预算和验收见 P4.1 计划。

检查摘要事实能否回查、人物/关系/否定/不确定性是否保留、关键问题能否定位到正确原文，以及翻译中的译名、指代、增义和漏译。分别记录总输入、计费输出、额外读取轮数、时延与首次构建成本。

后续可增加不同 N 值、同预算完整前文对照，以及少量 100K 与 300K～600K 块的质量对比，不以输入成功代替保留细节的证明。对有可靠参考的问题记录“原文有线索→摘要保留→实际注入→模型采用→翻译正确”，定位失败层级。主动详情读取作为后续单独消融。

建议推进这一方案的小规模试验。当前容量和标准价测算支持先阅读完整剧情区块；是否能提高翻译质量，仍由上述对照结果决定。
