# 跨版本续译起点定位设计

日期：2026-10-19。状态：0.4.0 已实现参考集排序、续译定位 API、有界摘要与正文查证、持久预算和完整 I/O。蜘蛛 1–3 卷、7–9 卷的真实验证见[实测报告](translation-continuation-results.md)。本文保留完整设计目标，当前 MVP 的范围见第 9 节。

本设计补充[独立版本索引设计](translation-independent-edition-index-design.md)，目标是在提供日文 Web 与部分中文文库之后，推荐 Web 续译起点，并说明重复阅读、历史缺口与版本分歧。它不改变翻译阶段以 Web 为事实依据的约束，也不等同于恢复一个已创建的翻译任务。

## 1. 结果应回答什么

跨版本不存在必然唯一的“中文最后一章对应的日文章”。需要区分：

| 问题 | 输出 |
| --- | --- |
| 中文已讲到哪里？ | 各叙事线的共同事件锚点、已覆盖/部分覆盖的事件、披露方式 |
| 从哪里继续最合适？ | 推荐的 Web 章 ID、候选起点区间及依据 |
| 为了衔接需要补什么？ | 起点之前的 Web 独有内容、状态差异、需要补读/补译的范围 |
| 能否直接接续？ | 可建议、歧义、明显分歧、证据不足或没有剩余 Web 内容 |

默认目标为 `goal=after_latest_reference`：“在已提供参考中，阅读顺序最后的主线正文结束后，按 Web 阅读顺序继续”。参考可以是前 1–3 卷，也可以只有 7–9 卷；后者以第 9 卷为目标终点，不要求先补齐 1–6 卷。它既不等于“寻找 Web 最早一条未翻译内容”，也不要求先补齐所有历史 Web 独有支线。无法兼顾的情况返回多个方案及差异。

“未提供早期中文”不意味着这些剧情未被翻译、用户未读过或 Web 历史不存在。参考文件的可用范围、读者阅读经历和跨版本剧情覆盖分别记录，不互相推断。具体排序契约见[参考集整理设计](translation-reference-ordering-design.md)。

不能使用 `max(有共同事件的 Web 章号) + 1`：文库末尾可能是插叙、未来预告、另一条叙事线，相关 L2 也可能只有一个共同事件。

## 2. 当前能力与缺口

现有公共库提供 `Index.build/read/build_parent/associate`。双侧 L2 已抽取摘要、事件、时序和知情状态；可以复用这些材料定位候选，并按段落引用回读。

`associate()` 只判断显式 L2 候选之间的共同事件。内部 `match_blocks()` 始终记录 `search_scope=explicit_candidate_nodes`、`search_complete=False`；关联解析成功不代表已搜索全书，更不代表共同事件所在的整块都被中文覆盖。新增的 `plan_continuation/locate_continuation` 单独处理末端定位。

现有摘要只要求有限关键事件，实体也不穷尽。`processed_all=yes` 不能证明每件事都进入摘要。未抽到事件与未召回区块均不能用于证明中文没有这段剧情。

当前公共 L1 由已有 L2 汇总。不能假定调用 `build_parent()` 会低成本阅读全书正文或自动建立缺失 L2。冷启动成本必须在规划中如实展示。

现有 `import_book()` 保留传入 paths 的顺序，`InputSpec` 按显式 `input_order` 排序；`volume_hint` 用于标记卷边界，不会自动解析并排序卷号。格式标准化之后的结构校验禁止改变源块顺序。因此，文件级排序应先生成显式导入清单，再调用标准化模块；不能在导出结果上直接重排并覆盖既有任务。

## 3. 推荐流程

### C1：检查输入与定位范围

1. 先整理参考集：识别卷、分册和章节顺序，生成有证据的排序清单；冻结 source、references、参考集清单、阅读顺序、输入指纹和已有索引版本。
2. 分别记录前缀缺失、内部缺卷、卷内缺章与末端截断。7–9 卷属于连续局部窗口，1–6 卷未提供本身不阻断接续定位；7、9 卷则另有内部缺口 8。必要的衔接证据缺失时才影响定位结论。末卷正文是否完整仍需单独检查。
3. 区分正文、后记、广告和预告。正文中的尾声、间章、另一视角不能因标题或位置被自动排除。无法分类时保留待核对项。
4. 使用稳定 chapter ID，展示标题与位置。标题数字、`position`、`edition_order` 不互相替换。

同底本并具有已核验覆盖范围时，优先复用已有平行映射；跨版本进入下述流程。不能凭一个平行末章推断更早所有章节均已覆盖。

### C2：识别中文末端剧情，而非只取最后一条记录

先确定最后一个已提供主线卷及其中最后的可用正文范围，作为 `reference_endpoint`。初始读取该范围最后一个正文 L2 及其前驱；若覆盖多条叙事线，扩展到必要的卷内范围。已有摘要可直接使用；没有则显式计划构建。

前 1–3 卷优先检查第 3 卷，必要时向第 2、1 卷扩展；仅有 7–9 卷优先检查第 9 卷，必要时向第 8、7 卷扩展。不隐式加载目录中其他中文卷。如果第 9 卷大量使用回忆或承接更早阶段，需要联合已提供各卷的事件判断 Web 边界；卷序最后的卷不一定包含故事时间最晚的事件。

针对末端提取少量用于定位的事件：参与者、具体行动、对象、原因、结果、发生/披露方式、未结束的行动、必要的前置状态，以及段落引用。区分“当前展开”“回忆重述”“预告”“未知”，不依靠作品记忆解开匿名角色身份。

窗口不是固定一块：如果某条主要线的最后进展在更早位置，需要在已提供参考内向前扩展。缺少更早中文时仍可用 Web 上下文解释候选，但不能据此推定缺失中文的内容。预算耗尽或必要证据不在提供范围内时，标记该线末端尚未确定，不能将其当作已完成。

### C3：召回 Web 候选

先检索已有 L1/L2 摘要及事件，目录标题序列和 embedding 仅辅助召回。用多个有区分度的事件寻找候选，避免只匹配人物、迷宫、技能或战斗主题。

使用局部阅读顺序增强判断：同一叙事线的多个事件及其因果通常比单个标题更有区分度，但不能将全书强制为单调映射。回忆和叙事重排允许次序不同，记录原因。

候选不可靠时扩展邻近或其他父范围。没有已有全局摘要时，目录只构成搜索提示；需要逐步补建或扫描必要范围。陌生标题、任意重排且缺少语义索引的输入，无法保证只检查末尾少量内容就能找到全书正确位置。不能对“覆盖/未覆盖”使用全书二分搜索。

每次记录搜索过、只检索到、已读正文及尚未搜索的范围。命中一个候选不能声称全书搜索完成；存在重复场景且无法排除其他候选时降低确定性。

### C4：事件核验与分线覆盖

复用 L2 关联生成候选，再针对候选及邻块进行专门的边界核验。此核验使用双方局部正文，不只比较摘要。

每个事件保留 `shared / partial / conflicting / no_match_in_scope / uncertain` 之一，以及双方事件 ID、正文引用、搜索范围。`no_match_in_scope` 只说明在已声明范围内未找到，不能写为全书不存在。

覆盖核验同时检查：

- 是同一具体事件，还是相似场景再次发生；主体、行动、原因与结果能否对应。
- 中文是完整展开、简短提及还是预告；提到事件结果不代表覆盖了 Web 的完整叙述和信息披露。
- 后续所需状态是否一致，例如角色存亡、所在地点、阵营、已知信息及行动目标。只检查接续所需关键状态，不构建全书状态图。
- 同一线的邻近事件能否支持同一定位；不同线分别保留覆盖情况，不用一条线的最远事件代替其他线。

状态一致必须有实际证据；没有抽到差异不能等同于状态一致。正文引用可定位也不等同于模型理解正确。

### C5：细化到章节边界

对少量候选 L2 展开章级正文，阅读最后可靠共同事件所在章与前后若干章；证据不足则扩大窗口，仍受预算限制。

输出推荐章与候选区间，分别记录最后可靠共同事件、起点中的重复内容、需要补读的历史内容。若一章前半已覆盖、后半有新剧情，MVP 从整章开头开始，报告可预期的重复，不增加段落级截断翻译能力。

按 Web 原始阅读顺序创建后续连续窗口。不因为某些中间章已有相关文库内容，就在任务中跳过这些章。需要更早补译的非连续范围单独报告，后续可创建独立连续任务。

## 4. 版本分歧和多线的处理

例如 Web 阅读顺序为 `A1 → B1 → A2 → B2 → A3`，中文已展开 `A1/B1/A2`，末尾只预告 `A3`。不能跳到 A3 之后。应核对 B2 是否已覆盖，通常将 B2 所在章作为继续候选，并注明预告与历史缺口。

若中文与 Web 的共同事件之后，关键人物状态或结局路线已改变，即使能找到相似后续场景，也不应标为可无缝接续。返回：

- 最后可靠共同剧情范围；
- 分歧内容及双方证据；
- 可选择从 Web 分歧前章节重新阅读/翻译的方案。

推荐重新阅读的起点与“中文后面正好接这一章”含义不同。没有足够依据定位分歧边界时，保持未决。

中文已覆盖整个 Web 的情况下可以返回 `no_remaining_source`，但必须完成足够的末端和版本分歧核验。中文卷数完整、标题写有终章或某个 Web 末章匹配均不足以单独得出该结论。

## 5. 结果契约与自动采用条件

结果至少包含：

```text
status: suggested | ambiguous | diverged | insufficient_evidence | no_remaining_source
goal: after_latest_reference
reference_set: 清单指纹、排序状态、prefix/window/gapped/unknown、已提供卷段
reference_endpoint: 目标卷、最后可用正文ID、volume_end/chapter_end/fragment_end/unknown
reference_availability_gaps[]: prefix/internal/intra_volume，已知缺失与未知范围
recommended_start: {chapter_id, title, position, edition_order} 或 null
candidate_ranges[]: 起点范围、理由、重复内容、风险
last_shared_anchors[]: 双侧事件与段落引用
thread_coverage[]: 叙事线、共同事件、未决内容
gaps_before_start[]: 已核实的版本独有内容或尚未核实的剧情衔接问题
state_conflicts[]: 影响接续的关键状态差异
search_coverage: 已检查/未检查范围、召回方式、补建清单
evidence_level: summary_only | passage_checked
auto_eligible: boolean
decision_reasons[] / unresolved_questions[]
input_fingerprints / policy_version / generation_ids / usage / fingerprint
```

`suggested` 仍是模型建议。证据等级和是否允许自动采用由工程条件计算，不直接采信模型自报的置信度百分比。

默认仅在参考顺序与目标终点可确定、候选已局部正文核验、多个有区分度的事件一致支持、前后边界与主要叙事线已检查、没有影响接续的已知状态冲突或关键未决缺口、搜索范围足以支持该选择时，标记 `auto_eligible=true`。7–9 卷缺少 1–6 卷不会单独令该值变为 false；“末端所在章疑似被截断”则直接影响能否声称在卷结束后接续。这些条件降低风险，不能保证语义真值；应通过实测校准。

部分搜索只能给受限建议；未排除其他合理起点、必要范围尚未索引或分歧未解时，保留多个候选并设为 false。到达预算上限返回已取得证据及待办，不猜一个章号完成流程。

## 6. 公共接口

以下方法已在 0.4.0 实现；`plan_reference_set` 也从模块根导出：

```python
from lightnovel_translation.ingestion import plan_reference_set

# paths 仅包含本次用户提供的参考文件，例如顺序打乱的第 9、7、8 卷。
reference_set = plan_reference_set(
    paths, edition_id="spider-ln-07-09", language="zh", order="auto",
)
# 未解决的排序冲突需通过显式 overrides 修正；不能强行导入。
zh = project.import_edition(reference_set.to_input_spec())
index = project.index([web, zh])
plan = index.plan_continuation(
    source=web, references=[zh], reference_set=reference_set,
    goal="after_latest_reference", endpoint="latest_mainline",
)
# 仅本地规划：缓存覆盖、待建节点、候选策略和预算缺口。

result = index.locate_continuation(
    plan,
    max_new_nodes=20,
    max_requests=30,
)
# 显式允许补建与调用模型；数量为示例上限，不承诺可在此预算完成。
```

定位调用同时受配置中的 token/请求/尝试总限额约束，不创建绕开持久账本的新调用路径。复用已构建摘要、已付费响应及已有匹配，保存原始输入输出。缓存身份包括正文、索引、候选/检索覆盖、协议和模型身份；搜索范围扩大后应产生新决策版本。

参考集清单以源文件 ID、内容指纹和逻辑卷范围绑定导入结果。`plan_continuation()` 验证清单确实描述本次 references，不能将 1–16 卷的索引仅加一个“7–9”显示过滤器后用于该场景。子集摘要若曾携带范围外前驱，也必须视为受污染缓存并重建；缓存复用以全部上下文依赖为准。

定位与创建翻译任务分开：使用者或 agent 选定建议后，用现有 `web.chapters()` 根据稳定 ID 找到位置，取后续连续 ID，传给现有 `create_job(chapters=..., mode='cross_edition', ...)`。定位不会偷偷开始翻译。

后续接入时，将定位结果指纹与实际选择写入任务 provenance；固定用户选择，恢复任务时不重新猜起点。不自动将定位关联升级为平行译文，也不把全书定位阶段见到的未来摘要、身份解释直接注入生成上下文。

## 7. 最小实施与验证顺序

1. **规划与报告**：先支持显式候选 Web 范围，复用已建 L2，输出正文核验结果和起点建议，建立离线协议与缺材料状态。
2. **边界核验**：增加小范围事件覆盖、披露方式、关键状态比较和整章起点选择；不要先建设完整时序图或重新穷举所有实体。
3. **自动召回与懒构建**：从中文末端提取定位事件，检索已有摘要，按预算扩展候选和补建。覆盖不足明确返回未决。
4. **库与 skill 接入**：公开上述接口、完整 I/O 与报告；agent 对 `auto_eligible=false` 的结果展示有依据的候选和待查项，不能凭作品常识补结论。

先用原创小样本验证：顺序对应、拆合章、缺卷、多线重排、结尾插叙、预告、重复场景、章内混合覆盖、状态分歧、没有后续以及缺索引/预算耗尽。关键断言是不能因一个共同事件或预告跳过尚需翻译的剧情。

真实测试首先使用蜘蛛前 1–3 卷和仅 7–9 卷，分别运行定位；完整中文只用于离线人工核对，不混入该次参考子集索引或模型输入。另以最后提供卷测试结局分歧是否正确保留未决。测试前为每个窗口人工标出共同锚点、可接受起点区间与分歧，不以模型互相认同代替验收。

指标包括：起点是否落入可接受区间、是否跳过必须内容、需重复阅读的长度、分歧/歧义是否被保留、引用能否定位、请求与 tokens。相比章号差值，错误跳过剧情和错误宣称可无缝接续应优先计为失败。缺乏全书搜索的实验必须报告候选范围，不能宣称全书定位准确率。

## 8. 蜘蛛样本的明确验证契约

源文固定为 `out_syosetu/蜘蛛ですが、なにか？.epub`。两组中文使用独立 edition 与索引作用域：

| 场景 | 测试传入顺序 | 规范阅读顺序 | 参考终点 | 缺口处理 |
| --- | --- | --- | --- | --- |
| prefix-03 | 3、1、2 | 1、2、3 | 第 3 卷的正文末端 | 无前缀卷缺失；仍需检查卷内结构 |
| window-09 | 9、7、8 | 7、8、9 | 第 9 卷的正文末端 | 1–6 未提供，不转为补译任务 |
| gap-09 | 9、7 | 7、9 | 仍以第 9 卷为目标 | 8 为内部缺口；不足以判断时返回待查 |
| partial-09 | 7、8、第 9 卷前半 | 7、8、9 的部分正文 | 最后可用章节，不宣称第 9 卷结束 | 明确 partial；根据用户指定目标报告证据不足或局部接续 |

本地元信息检查发现：各 EPUB 的包元数据标题都是同一书名，卷号在文件名与卷首目录项中；普通字符串排序会得到 1、10、11、…、2。另有 Ex 文件，不能自动作为第 17 卷或最新主线终点。

第 3 卷尾部目录依次包含“幕间 支配者与妹妹”“11 蜘蛛VS.地龙亚拉巴”“幕间 魔王的地龙回忆录”“终章 离开迷宫喽！”及后记。第 9 卷尾部包含“鬼 拉斯”“7 抵达日本”“邪神不嗤笑”“妖精笑了”及后记。这些只是初始核验入口，不能用标题直接宣布 Web 章号或判断叙事时间。

两组按用户明确卷范围生成的现行 `InputSpec` 已通过本地 `inspect_input()` 检查，卷号分别保留为 1/2/3 与 7/8/9，输入位置均为 0/1/2。这验证文件存在、格式与清单可读，不代表自动排序器或语义定位已实现。产物：

清单路径以仓库根目录为 base；用于其他工作区时显式传入 base 或更新路径。它们由已知卷范围准备，未测试通用自动排序，不包含模型推断的续译起点。

实施顺序细化为：R0 本地参考集排序/缺口清单 → R1 显式候选的末端正文核验 → R2 自动召回与有界补建 → R3 运行两组真实场景并核验起点 → R4 接入创建任务与 skill。R3 的验收同时检查输入顺序无关性、缺前缀仍可定位和完整 I/O 中没有范围外中文；若两组建议不同，不能只凭这种差异判定语义正确。

## 9. 0.4.0 的实施边界

已实现文件级参考排序、一个中文参考版本的最后可用正文选择、末端两个 L2 的事件摘要、全书目录最多三个候选召回、候选 L2 懒建、整章正文核验及按 `REQUEST` 有界扩展。所有定位摘要、召回、重试和查证使用同一持久预算，重新调用会复用已保存响应。定位摘要使用独立 profile，不隐式创建术语映射或翻译任务。

结果以 `boundary` 保存重复内容、缺失上下文、状态兼容和叙事线检查，以 `last_shared_anchors` 保存带 relation 的双方引文，以 `search_coverage` 保存已读章与未完成请求。第 5 节的多候选区间、独立结构化分歧/历史缺口清单、自动绑定任务 provenance、可靠的卷内缺页检测仍为后续目标；不能把当前 `end_integrity=unknown` 解释为完整卷认证。

长输出截断时先执行配置内的有限重试，均失败后可仅使用已付费可见残文、实际绑定引文与候选全文请求补全。局部补全过程仍严格校验引用，不提升为自动采用；没有足够可见内容则保持 `insufficient_evidence`。不读取或保存模型隐藏推理链。

全书标题只是召回提示，`search_complete` 始终为 false。即使返回 `suggested`，也只说明存在受限的正文依据；不证明全书唯一边界，更不证明所有旧支线都已由中文覆盖。`auto_eligible` 是保守的工程门槛，仍需外部语义验收。
