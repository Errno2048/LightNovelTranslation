# 参考集排序、局部卷与终点选择

日期：2026-10-19。状态：0.4.0 已实现文件级排序器、显式覆盖、缺卷与重复/冲突检查，并接入续译定位。与[续译定位设计](translation-continuation-design.md)配套；复杂合本和文件内部乱序仍由既有标准化修复处理，未自动推断逻辑卷。

## 1. 职责与输入输出

增加一个本地 `plan_reference_set()`，负责把用户提供的一组文件组织为有序参考集，并生成现行标准化模块可接受的 `InputSpec`。不调用模型，不移动原书，不扫描并自动加入同目录其他卷。

顺序整理解决“第几卷、卷内先读什么”；续译定位解决“这些内容之后从哪个 Web 章继续”。不能用事件发生时间重排书籍，也不能将卷序换算成 Web 章号。

输入可以是多卷 EPUB、每章一个文件或合本 TXT/EPUB。先检查文件级顺序线索，标准化后再绑定卷与章节范围；单文件合本缺少明确卷边界时，使用已有分章、`set_volume` 等修复能力，未解决前不声称已经识别末卷。

## 2. 三种位置必须分开

| 字段 | 示例：仅有第 7–9 卷 | 含义 |
| --- | --- | --- |
| `volume_ordinal` | 7、8、9 | 原书卷序，不能重新编号为 1、2、3 |
| `input_order` / `available_order` | 0、1、2 | 本次所提供文件/逻辑单元的位置 |
| `edition_order` / `chapter_id` | 导入后生成的顺序与稳定引用 | 语料内部阅读位置及引用 |

原始卷名、原始章节名保留。解析得到的数字只用于排序；章节标题的 S1、Y1、血1 等可能在卷内并行且跨卷重置，不能按数字重新排列 EPUB spine 或 TXT 正文。

逻辑卷与物理文件不是一一对应：一卷可拆成多个文件，一个文件也可包含多卷。逻辑单元记录来源范围，文件级排序只能在不拆开正文的前提下处理可确定的顺序。

## 3. 顺序证据与规则

按以下顺序收集证据，而非遇到高优先级字段就忽略冲突：

1. 用户/manifest 的显式卷号、分册号、顺序覆盖与主线/特别卷分类。
2. 包内明确的卷序元信息、卷首标题、目录的卷级分组。
3. 文件名中有明确作用域的卷、册、章编号；同书统一命名模式也可提出候选。
4. 原始传入顺序只作为保留/人工确认选项；目录枚举顺序、mtime、路径字典序不构成小说顺序证据。

匹配时可使用 NFKC 处理全角数字，解析常见中文数字与明确编号语境中的阿拉伯数字；保留原文，不对小说正文做兼容字符归一化。不把文件名中的年份、ISBN、版本号和章节号误当卷号。

例如样本的 `转生成蜘蛛又怎样！ 7.epub` 与包内卷首目录项 `转生成蜘蛛又怎样！ 7` 相符，允许形成第 7 卷候选；包元数据只有书名，表示该证据缺失，不是冲突。若文件名写第 7 卷、内部卷标题写第 8 卷，则记为冲突，不能无声采用其中一方。

自动排序只在选定同一书系、同一参考版本的范围内比较。不同译本、修订版或其他作品的文件不能因书名相近而混合；明确相同版次的声明优先，疑似混入保留冲突。特别卷 Ex、外传、短篇集单独标记，其系列位置未知时不能参与最大主线卷选择。

分册只在同一卷内部比较上/中/下、前/后及显式 part 编号；没有依据时不能擅自把未标记单卷当作“上”。对于独立章节文件，可信卷内章序可以排序，遇到重号、间章、序章或尾声归属不明时保留待处理项，不按标题字母顺序猜。

文件内容哈希完全相同时可报告精确重复，并在计划中保留一个逻辑输入及全部来源路径。只有标题相同、卷号相同或正文部分重合时，不能直接去重；可能是修订版或残缺副本，应明确选择来源。覆盖策略写入计划，不删除文件。

## 4. 参考集数据契约

```text
schema / reference_set_id / fingerprint / policy_version
edition_id / language / series_label / version_label
ordering_status: resolved | needs_resolution
ordered_sources[]:
  source_id / path / content_fingerprint / input_order
  raw_volume_labels[] / volume_ordinal / part_ordinal
  volume_kind: mainline | extra | unknown
  evidence[] / conflicts[]
logical_units[]:
  unit_id / source_ranges / volume_id / chapter_ids
  available_order / original_order_labels / endpoint_eligibility
availability:
  scope: prefix | window | gapped | unknown
  available_runs[] / unavailable_prefix / internal_gaps[]
  intra_volume_gaps[] / end_integrity
endpoint_candidate / excluded_or_unplaced[]
input_spec / issues[] / overrides[]
```

文件扫描阶段尚无章 ID 的字段保持未绑定，标准化后以 source ID、来源范围和指纹绑定；不得伪造 chapter ID。排序清单和导入结果不一致时拒绝用于定位。

`source_id` 应由稳定文件身份生成，不由本次枚举位置生成；单纯把输入列表打乱不应改变排序后的清单、语料指纹和模型请求。显式 overrides 与被替代的原始证据一并保存，确实改变顺序时产生新的指纹与导入分支。

原始调用的文件枚举顺序作为审计信息单独保留，不参与规范阅读顺序的语义指纹；规范清单中的证据与重复来源列表也按稳定键序列化。文件内容、采用的顺序证据或显式覆盖改变时仍应使相关缓存失效。

## 5. 缺失范围的语义

| 提供内容 | 可用范围 | 目标终点 |
| --- | --- | --- |
| 1、2、3 卷 | prefix | 第 3 卷最后可用正文 |
| 7、8、9 卷 | window；前面未提供 | 第 9 卷最后可用正文 |
| 7、9 卷 | gapped；内部缺 8 | 仍是第 9 卷，缺口影响证据充分性 |
| 第 9 卷仅有第 1–4 章 | 部分卷 | 第 4 章末，不能声称第 9 卷结束 |
| 7、8、9、Ex | 主线窗口 + 特别卷 | 默认第 9 卷；Ex 的使用另有范围说明 |
| 卷序无法确定 | unknown | 不自动选择终点 |

只有已知编号规则时才列出具体缺卷号。否则报告“起始之前的范围未知”，不能臆造从第 1 卷起的所有卷。`unavailable_prefix` 只表示本次没有提供，不表示不存在中文译本或读者没有读过。

需要分开记录：文件可读、结构未发现异常、声明为完整卷、正文可能截断。EPUB 可解析、存在后记或与其他卷长度相近，都不构成内容完整的充分证明。

早期缺卷不自动阻断终点定位。若末端锚点清楚且 Web 后续状态兼容，可以提出建议；如果必须借助缺失卷才能区分两个起点，则报告缺少的证据并降低确定性。Web 原文可用于核验 Web 状态，不能据此填补缺失的中文剧情覆盖记录。

## 6. 终点选择

默认 `endpoint=latest_mainline`：在已提供且顺序已解决的主线逻辑单元中，选择最后可用正文范围。用户可显式指定卷或 chapter ID；指定终点之后的中文不得进入本次定位语义上下文。

`reference_endpoint` 表示中文侧目标，`recommended_start` 表示 Web 侧建议；两者必须分别存储。第 9 卷可能回述早期剧情，因此仍要结合已提供前卷识别各条线的覆盖，不能仅按该卷内部最晚发生的事件定位。

后记、广告和下一卷试读不自动推进目标。主线尾声、幕间及有正文价值的特别章需根据文本与结构判定，不能一律删除。Ex 或外传缺少可靠阅读位置时，默认不进入本次主线定位上下文；如需只用于译名，另建有范围和披露限制的参考用途。

目标卷疑似缺尾时，报告实际可用章/段范围。如果用户明确要求“完整第 9 卷之后”，证据不足；若允许“最后可用章节之后”，可以另给局部接续候选。MVP 仍以整章作为翻译起点。

## 7. 接入现有标准化模块

`ReferenceSetPlan.to_input_spec()` 生成现有 `SourceSpec` 的 `source_id/path/input_order/volume_hint`。规范卷标签例如“第7卷”，原始“第七卷”“07”等表记另存证据，避免同卷被不一致标签分成多个逻辑卷。

来源重排发生在提取之前，导入后保留每个文件的内部阅读顺序。已标准化的条目不通过绕过 `source_order_changed` 校验来重排。若单个文件内部确实乱序，MVP 报告准确范围，使用显式派生输入及来源映射重新导入；不扩大现有结构 patch 为任意正文编辑器。

在安装包中将新本地接口放入 `lightnovel_translation.ingestion`，接续规划与模型调用放入 `Index`。不改变现有 `import_book(paths)` 默认尊重调用者顺序的行为。调用者主动选择 `plan_reference_set(order="auto")` 后再导入。

结构/排序冲突先由可追溯的 overrides 或已有标准化 patch 解决；agent 可以读取局部卷首、目录和结尾来提出修正，但通用本地排序 API 不隐藏付费调用。排序完成不等于已完成语义续译定位。

## 8. MVP 验证与交付

本地测试覆盖乱序 3/1/2 与 9/7/8、1/10/2、全角/中文卷号、重复文件、同卷不同副本、Ex、上下册、独立章文件、元信息冲突、合本卷界、卷内交错 S/Y 章节、已标准化结果不可原地重排。

排列不变性是主要工程验收：同一批文件以不同列表顺序传入，在证据无冲突时产生相同的规范顺序、终点、源身份和模型请求身份。另一重要断言是仅有 7–9 卷时不能将其改标为 1–3 卷，不能自动加载 1–6 或 10–16 卷，也不能因缺前缀自动进入“从头补译”。

蜘蛛实测先通过两组参考集整理，再在各自上下文作用域内运行语义定位。逐条保存末端锚点的中日引用、Web 候选及排除原因，人工确定可接受区间，最后才创建一至两章试译任务检查实际接续。具体场景及本地已检查清单见续译设计第 8 节。
