# 缓存重建、数据复验与 P4a 试点

日期：2026-10-15。

先修复采集表示层，再重新导入语料和绑定结构证据；通过后只在冻结开发集启动小样本段落对齐。全量结构检查不等于全书双语语义金标准，P4b 知识库尚不自动从候选对应中抽取。

## 爬虫与清洗

- Linovelib 每个 HTTP 分页先按已验证的 `v1009c.8` 协议恢复阅读顺序，然后清除零宽控制字符，最后拼接分页。仅含隐形字符的段落在还原前仍参加置换，清洗后保留空段 DOM 槽位。
- 清洗实现位于 `translation/text.py`，爬虫通过 `epub/cleaning.py` 共用。清除 Unicode `Cf` 格式控制符及 U+034F；保留日文浊音等组合符、作者注音与异体字/表情选择符。正文、标题和正文属性中的控制字符均清理。原始 HTML 缓存不改写。
- Syosetu 保留前言、正文、后记各自的容器和段落 ID。导入日文原缓存时应用同一清洗视图，避免把已清掉的字符重新导入。
- 自动注音增加文字序列不变检查；若转换器不能精确重现原文，就保留原行。保留换行，避免再次处理作者已有 ruby 内部节点。重建版不重新生成机器注音，保留作者已有注音。
- Masiro 及 Wenku8 正文出口也接入相同清洗。
- 正文缓存加载器支持严格离线模式；缺页、截断缓存、跳页、分页循环或反向链接不一致均失败。不会仅为识别下一章而提前下载它。
- 修复无封面书籍的 `href="None"` 封面引用，以及章节目录标题中 `&` 等字符的 XML 转义。重建版将卷内目录链接指向 EPUB 内的章节；普通爬虫的卷页链接补全为网站绝对地址。

## 重建与版本保留

入口是 `py -3.11 -m epub.rebuild`。旧 EPUB 提供已有目录、元数据及资源命名，正文来自缓存；不重新请求目录或章节。

```powershell
py -3.11 -m epub.rebuild --output artifacts/crawler/rebuild-20261015 --resume --install
```

新运行请选择新的输出目录。`--resume` 仅用于恢复同一轮中断；完整 manifest 已存在时按哈希核验并复用结果。中断后复用日文暂存包前，会重新检查每段正文和作者 ruby 与原缓存完全相等。`--install` 在全部暂存包检查通过后替换输出目录中的 EPUB；重复执行不会再次对 EPUB 置换。

产物根目录为 `artifacts/crawler/rebuild-20261015/`：

- `originals/`：旧 EPUB 的精确副本。
- `rebuilt/`：经过核验的重建 EPUB。
- `manifest.json`：新旧 EPUB、缓存和图片哈希，以及校验结果。
- `pages.json`：逐页/章缓存定位、段落数量、清洗计数和顺序变化。
- `japanese_annotation_differences.json`：旧日文输出与原缓存的逐段差异。
- `installation.json`：实际安装后的输出哈希。

旧实验和旧语料未覆盖。历史 manifest 中旧 EPUB 的路径现在指向重建版本；复查旧输入时须按上述 manifest 的 `input_sha256 → backup` 定位到 `originals/`，不能用新文件冒充旧输入。

## 重新导入与结构证据

```powershell
py -3.11 -m translation --book tenken-cache-import ingest
py -3.11 -m translation --book tenken-cache-import verify-rebuild --previous-book tenken-order-repaired --rebuild-folder artifacts/crawler/rebuild-20261015 --section-patch artifacts/crawler/rebuild-20261015/reviewed_sections.json --repair-book tenken-cache-clean
```

`verify-rebuild` 要求新导入的每个段落按章节身份、顺序、正文、kind 和 ruby 精确等于旧阅读顺序审计结果的清洗视图，并验证旧 EPUB 备份、新输出和缓存哈希。原结构补丁不直接复用旧指纹；只有全量核验通过后，才按原段落位置和全文相等的证据重新绑定新版本，应用时再次验证标题锚点和整段重复序列。

后续开发使用 `--book tenken-cache-clean`。旧的 `tenken-reference-clean` 保留为历史分支。开发/验证/盲测的源章节划分保持原样，已确认审查和旧 few-shot 不自动继承。

已知上游内容仍须保留分区：第 61、226 章附录，第 697、720 章重复正文，以及第 1036 章中关联 1035/1036 的后记。第 1036 后记的 HP/MP 冲突继续标记为 `known_numeric_conflict`；不能因清洗成功就将译文数值当作事实。

本轮额外发现第 821 章尾部混入“收藏”按钮。缓存 DOM 为只包含收藏图标和文字的独立段落，图标 URL 为 Masiro 的 `fav.gif`，不是小说插图。以缓存哈希、原分页段号及精确 DOM 证据分为 `source_site_control`，保留记录并排除平行正文。`reviewed_sections.json` 在旧五章补丁之上增加此项，再通过全量内容核对重新绑定新版本；不会修改旧补丁。该图标是旧 EPUB 中唯一未内嵌的外链图片，重建仍保留外链，离线不显示图标；小说文字和已有内嵌资源均不依赖它。

确定性扫描 `scan-quality` 识别长段逐段精确重复、显式附录标题和零宽字符，报告尚待复核的结构候选，不自动删改正文。无法识别所有漏译、增译和版本差异。

清洗后另显露第 128 章的一条相邻长段重复告警。该章在冻结保留集内，本轮不查看其双语正文作开发调参，也不自动删段。语料为该章登记 `parallel_body_eligible=false` / `evaluation_eligible=false` 和质量阻断原因；章节配对保持待定。示例、评测参考、段落候选入口均拒绝它，后续需独立复核再解除。没有把“没有长块重复候选”写成“所有数据问题已消失”。当前 P4a 只在不受此项影响的三个开发章节运行。

## P4a 初版

`paragraph-candidates` 仅接受重新审查过的整章身份配对，当前试点限制在冻结开发集的 1–3 章内；验证/盲测章节在 embedding 请求前即被拒绝。

```powershell
py -3.11 -m translation --book tenken-cache-clean paragraph-candidates --keys main:3 main:775 main:1233 --max-requests 40
```

算法对非空正文采用单调动态规划，支持 1:1、1:2、2:1、2:2，以及两侧空对齐。综合双语语义向量、章节内长度比例、数字和引号形态；多段向量为按字数加权的聚合，不是 LLM 对该区间的语义判断。长段切块求向量，避免静默截断。非正文区间和空段另存排除清单，原段落 ID 完整保留。

每批最多 16 条、每条最多 600 字符。请求数有上限，模型与端点通过现有 provider 配置传入，缓存按文本和配置绑定；重跑复用缓存。输出位于 `alignment/paragraphs/`，包括 `candidates.json`、`review.html`、`pilot.json` 和独立向量缓存。

所有范围仍为 `candidate`；分数未校准。缺口、数字差异和引号差异仅表示待复核信号。候选结果不自动成为 few-shot、术语证据或冻结知识条目。下一步是针对候选对应检查局部版本/翻译差异，再完成 P4b 的候选术语、冲突管理、证据可见性和 K0 编译。
