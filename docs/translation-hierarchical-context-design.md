## 1. 本轮决定

采用确定性的三层上下文，先建立叙事索引，再逐步接入实体和时序知识。上下文编译器按位置自动选择内容，不要求翻译模型先发现缺口并请求工具。

| 层级 | 注入内容 | 用途 |
| --- | --- | --- |
| 近章 | 最近 `N_chapter` 章完整原文及允许使用的完整译文 | 保留对话、语气、指代及当前情境 |
| 近块 | 最近 `N_block` 个可见块的整体摘要及块内区间详细摘要 | 保留近期事件发展、角色关系变化和回忆线索 |
| 远块 | 其余所有可见块的整体摘要 | 保持远程剧情覆盖，支持识别早期线索 |

当前目标章完整原文独立放置，不占 `N_chapter`。P4.1 v1 的全局重点实体卡保留独立插槽，完整版本用于主角姓名、角色描述等信息；v1 不新增全书实体抽取、人物图或自动角色描述。已有、获准使用的译名约定可保留，插槽允许为空。v2 首版将基础描述及译法随块构建，按独立元信息工作集注入，实施范围和剩余缺陷见补充设计 B0–B4 及 v2 结果。

本方案确保指定层级的信息实际进入 prompt，但不保证摘要没有遗漏，也不保证模型充分利用输入。对局部注意力窗口和人类阅读习惯的适配是设计动机，质量及缓存收益需要测量。

## 2. 计数、窗口与可见范围

### 2.1 默认续译模式

- `N_chapter` 表示目标之前最近的原文章节数，不是左右各 N 章。初始试验值为 `3`。
- `N_block` 表示距离目标最近的可见块数，不是目标前后各 N 块。初始试验值为 `2`。
- 当前块已有可见前缀时，它占一个近块名额；目标恰好位于新块首章时，当前块没有前情，不占名额。
- 章节距离按规范化阅读顺序计算，不能直接对数字章号相减；番外遵循显式阅读顺序，非叙事附录不自动计入。
- 先选最近的 N 个章节，再检查其译文资格；缺译不会自动改选更远的 N 个双语章。记录实际双语覆盖数。
- 文本起始位置不足 N 时使用实际可用范围并记录原因。允许 `N_chapter=0` 或 `N_block=0`，便于消融。

例如块 A 为 1–20 章、B 为 21–40 章、C 为 41–60 章，目标为第 48 章，取 `N_chapter=3, N_block=2`：近章为 45–47；近块为 B 与 C 的 41–47 可见前缀；远块 A 注入整体摘要。不能用 C 的 41–60 摘要代替 41–47 摘要。

### 2.2 补缺与实验模式

P4.1 首版实现前向续译和严格前文遮蔽配置。补缺场景将来可显式增加 `after_chapters`、`after_blocks`，默认均为 0；与前文计数分开，注入时标注“后文参考”，不能伪装成前情。当前代码不支持的未来来源策略须返回未支持，不能通过此设计文档视为已放开。

政策分别定义：可访问日文、可访问中文、可用于摘要的前情、可用于表达约定的证据、评测保留资料。目标日文允许作为任务输入，但目标译文、中文标题、译注及其派生摘要始终按折隐藏。目标日文默认也不参与前情摘要；未来若实验允许目标原文预分析，单设产物和标记。

当前块摘要按精确可见前缀构建并缓存。完整块摘要包含未来信息时，不得截取其中几句冒充前缀摘要；缺少匹配产物就报告待构建。内容、标题、边界标签、实体别名和排序统计均接受依赖检查。

为避免标题泄漏，严格实验的分块只读取允许的标题和正文；不能直接复用由未来章节决定的语义边界或剧透性块名。全书生产目录与折内目录隔离。只读查询不临时生成摘要。

## 3. 分块及摘要结构

### 3.1 标题驱动，正文校核

现有 EPUB 目录是平面逐话列表，不能直接当作篇章树。先为全部授权章节建立无模型目录，再依据标题序列提出连续区块候选，支持人工边界覆盖。标题中的地点、事件和视角变化仅是候选信号；`Side` 不必另起一块。

首轮候选大小沿用约 20–50 话、40K–150K 日文 tokens 的容量参考；按实际正文计数约束，不能以话数保证容量。长自然篇章拆为有共同父篇章 ID 的连续子块，并记录容量拆分原因。边界校核读取邻近正文，记录证据与是否使用模型。

最小索引为“书籍 → 有序块 → 有序章节区间 → 原文章节/段落”。每个章节在同一分块修订中恰好有一个所属块；区间无重叠、无空洞。跨块回忆通过原文引用或线索链接连接，不复制章节归属，也不推导确定因果。

### 3.2 每块内容

保留用户提出的 `(全段总结, {章节区间: 摘要})`，区间在持久化时用有序列表表示，另附精确章节 ID，避免仅凭数字端点误包含番外。

```text
BlockSummary
  block_id / block_revision / summary_revision
  visible_chapter_ids / source_revisions / policy_fingerprint
  overview: text + evidence_refs
  details: [range_id, chapter_ids, text, evidence_refs, lookup_hints]
  unresolved: 未知、相互冲突的描述、待确认的指代
  generation: model / tokenizer / prompt / schema / usage
  dependencies / coverage / review_status
```

整体摘要保留人物、目标、冲突、主要转折和可见范围末端的状态。详细摘要补充称谓、关系变化、能力或物品的作用、回忆与当下的区别、人物声称与叙述事实的区别。保留日文原名；只有通过审查的中文译名可作为约定并列。不得推测缺失动机、性别或说话人。

首次构建将该块允许的完整日文正文交给模型，一次产生整体及详细摘要；详细区间初始以 3–5 话为候选，可按场景调整。重要陈述附来源章节/段落，引用位置有效不等于语义已经审查。摘要是有出处的导航信息，不自动转成已确认事实或实体约定。

先按计划中固定的区间生成，输出缺段、重复、越界引用或截断均不得标为完成。遇到超长块按预算拆分，记录父子关系；不静默截断输入。

### 3.3 质量与更新

完整译文进入近章层需要针对完整范围的使用资格。P4 只审查过两三段的 donor 不能据此升级为整章可信双语样本。拆并章配对要列出实际中文范围；漏译、增译、错主体等保留质量标记。

日文可用而中文缺失或被阻断时，保留完整日文并标明中文不可用；不补造译文，不以其他章节译文替代。摘要事实以日文为依据，已有译文仅在获准范围内提供表达约定。

原文、分块、审查或政策变化使依赖摘要失效；重建产生新修订，旧快照不覆盖。分别记录目录覆盖、摘要生成覆盖、语义审查覆盖、双语可用覆盖，不能用一个 `complete` 声称所有知识已完整提取。

初版前缀摘要由可见正文重新构建，缓存键含精确范围。连续运行可能导致反复读取增长的前缀，需单列成本；P7 再实现增量前缀/检查点策略，不能现在承诺单遍构建即可覆盖所有时点。

## 4. 确定性上下文编译

### 4.1 注入次序

```text
固定翻译规则与任务政策
全局重点实体卡插槽 / 已审查译名约定
远块整体摘要，按阅读顺序
近块整体摘要 + 区间详细摘要，按阅读顺序
近章完整日文 + 允许的完整中文，逐章配对
当前目标完整日文与输出要求
```

各层显示来源范围、可见截止位置和质量状态。块整体摘要在块由远变近时只保留一份。某详细区间完全被近章完整原文覆盖时可省略详细摘要，并登记“由完整正文替代”；部分重叠的区间保留完整摘要，不切除没有独立证据边界的句子。整体摘要保留以维持块内连贯性。

初版按上述次序重建确定性 prompt，不依赖有状态聊天。P7 再处理连续译文提交与压缩。在局部注意力模型中，远块总览未必能被生成位置直接利用，不能仅凭这个顺序宣布解决长程依赖；需在评测中安排远程事实与位置对照。

稳定块内容和确定性序列化便于复现。窗口滑动、近块提升、摘要修订和实体卡变化都可能改变共享前缀。记录供应商缓存指标和实际共享前缀长度；前缀稳定性不能代替 KV 命中证据。

### 4.2 预算规则

`输入可用预算 = 模型上下文上限 − 输出/推理预留 − 聊天模板与安全余量`，具体计入方式遵循提供方接口。生成摘要与编译翻译上下文分别设预算，不因为模型标称 1M 就默认使用 1M。

逐层记录 token，公开 tokenizer 缺失时报告保守估计与方法；不能把现有 UTF-8 字节预算标为精确 token。配置初始建议为 3 个近章、2 个近块，但必须由测量决定是否可用。

目标原文、请求的完整近章、近块摘要及所有远块整体摘要属于配置要求。装不下时返回 `budget_exceeded`，附每层占用和可执行的重新规划建议；不能静默截断正文、减少 N 或只选 top-k 个远块。显式修改配置后重新编译，保存 requested/effective 值与原因。

更长作品可后续增加“远块之上的篇章总览”或重写更短块摘要，但这是新增压缩策略，需保留全部范围覆盖和验证，不是首版自动降级。选定试验范围缺少必需摘要时返回 `coverage_gap`；允许不完整上下文仅能作为单独的消融配置，不能标成完整三层方案。

## 5. 存储与 API

沿用不可变语料与 SQLite 修订基础，新增独立叙事索引对象；不把摘要塞入 `Convention`。JSON/JSONL 用于冻结导出及审查。以下能力已在 P4.1 实现，Python 首版签名见表；本阶段不提供 HTTP 服务。

| 对象 | 必需内容 |
| --- | --- |
| `BlockIndex` | 书籍、阅读顺序、块/区间成员、边界依据、版本、可见性 |
| `SummaryArtifact` | 整体及详细摘要、精确来源、生成与审查身份、传递依赖 |
| `SummaryBuildPlan` | 范围、所需前缀、输入估算、输出/请求上限、缓存命中和失败策略 |
| `HierarchicalContextSpec` | N 值、目标、可见政策、源/译质量门禁、各项预算 |
| `ContextManifest` | 实际注入 ID/文本哈希、覆盖/重叠/缺失、分层计数、依赖、配置与指纹 |

| API | 行为及副作用 |
| --- | --- |
| `build_block_index(view, config, overrides)` | 本地构建标题驱动候选；不调用模型 |
| `review_block_boundaries(view, index_id, decisions)` | 显式保存边界修订和依据 |
| `plan_summaries(view, index_id, provider_identity=..., reuse_summaries=..., ...)` | 对全部可见块/精确前缀列出任务及预算；跨配置复用须显式固定旧摘要 ID；首版不另接受 targets 子集 |
| `run_summary_plan(view, plan, provider, provider_identity=..., retry_failed=False)` | 显式生成入口；执行有界请求、校验、缓存和用量登记 |
| `review_summaries(view, decisions)` | 保存审查，不覆盖原生成记录 |
| `view.list_blocks(index_id)` / `view.read_summary(summary_id, chapter_ids)` | 只读；要求精确 ID/章节范围，返回匹配版本或明确错误 |
| `view.read_chapters(ids)` | 按语言权限和完整中文范围审查返回完整正文与实际对应范围 |
| `compile_hierarchical_context(view, index_id, summaries, spec=..., knowledge=..., examples=...)` | 确定性编译，不隐含生成或补建 |
| `explain_context(bundle)` | 解释每层选择、替代、缺失、预算及来源依赖 |

错误区分 `coverage_gap`、`visibility_denied`、`quality_hold`、`stale_summary`、`unsupported_policy`、`budget_exceeded`、`invalid_summary`。读取摘要不能按最新版本悄悄替代冻结引用。

来源依赖按语言、用途和范围传递。兼容现有 `QueryPolicy` 时，应把“目标中文隐藏”与“目标日文可输入”拆开，禁止直接删除原有来源过滤。实体插槽同样受可见政策控制，不能注入全书身份揭晓后的角色描述。

生成模型支持可选 `reasoning_effort` 配置；未配置时保持历史 public 身份兼容。摘要和翻译的输出预留均包含计费思考输出，截断错误保留实际 usage。CLI 翻译恢复 bundle 固定的完整范围审查 ID，也可显式传入 `--chapter-reviews`；不得以恢复为由跳过重新编译校验。

## 6. P4.1 分步开发与交付

P4.1 是原 P4 之后、P5 之前新增的阶段。已完成的 P4 T0–T7 不重新编号，P6 的 D 对照名称保持不变。

| 任务 | 前置 | 交付与完成标准 |
| --- | --- | --- |
| H0：契约与政策 | 已有语料、P4 | 固定 N 语义、语言权限、范围/版本、schema、预算及错误；冻结合成夹具 |
| H1：本地分层目录 | H0 | 标题候选、边界覆盖配置、token 清单、章节/区间索引、检查报告；无模型可运行 |
| H2：摘要构建闭环 | H1 | plan/run/review、完整块与精确前缀缓存、结构及证据校验、用量账本；先用 mock |
| H3：三层编译器 | H0–H2 | 完整近章、近块详情、全部远块总览、重叠处理、预算失败、实际 prompt 与 manifest |
| H4：CLI 与离线验收 | H1–H3 | 从目录到计划、mock 摘要、编译和解释的可复现命令；依赖失效与恢复验证 |
| H5：小规模真实试验 | H4 | 明确 allowlist 和预算的真实摘要/翻译、质量报告、错误归因；不默认扩成全书 |

建议实现目录为 `translation/narrative/`，容纳 schema、分块、摘要计划/运行与读取服务；上下文接入现有 `translation/context/`，复用 provider 与知识修订设施。实现时再确定物理文件，不预建空模块。

H5 运行计划必须列出每个目标需要的全部远块、近块和前缀产物。先选前部 3–4 个连续块，才能在可控构建范围内同时验证三层；回忆/称谓难例可追加专项样本。晚章若缺少更早块总览，只能标为局部试验，不能宣称全前情覆盖。

首轮硬上限：摘要生成请求 12 次、翻译请求 12 次、全部 24 次、累计输入 2M tokens、累计输出预留 150K tokens，纠错和重试也计入。任一上限先到即停止并保存待办，不自动回收实际少用的预留。真实单请求及用量另计；计划不满足上限时缩小范围。本次累计 13 次请求、149800 输出预留，包含旧探索失败；详见结果报告。

## 7. 验证与效果判定

### 7.1 离线必测

| 场景 | 预期 |
| --- | --- |
| 开头、不足 N、块首、块中、块尾、番外 | 选择顺序正确；当前块前缀计数一致 |
| 近章缺译、中文质量阻断、拆并章 | 完整日文不丢；中文状态和真实范围可解释 |
| 只有段落审查却请求完整中文 | 不扩大资格，不冒充完整双语 |
| 目标中文/未来资料经摘要、标题或边界泄漏 | 构建或编译拒绝；依赖可回查 |
| 完整块摘要用于早期前缀 | 拒绝复用，不做文字切片 |
| 近章与详细摘要全覆盖/部分交叠 | 正确替代或保留，不生成摘要空洞 |
| 远块多于预算、必需摘要缺失 | 明确失败；无静默 top-k、裁剪或隐式调用 |
| 原文/边界/审查变更，旧快照读取 | 新视图标失效；旧产物仍可复现且保留原依赖 |
| mock 输出缺区间、越界证据、截断 | 不标成功，可恢复且重试有上限 |
| 同输入重复编译 | prompt、manifest、指纹一致；实际注入匹配审计清单 |

### 7.2 真实对照

使用独立名称，避免与既有 A–F 混淆：

| 配置 | 内容 | 核心比较 |
| --- | --- | --- |
| `C` | 现有短 few-shot + 折内冻结约定 | 重跑或身份完全相同的 P4 基线 |
| `H-near` | 同约定 + 完整近章 | 相对 C 分离完整近章的作用 |
| `H-tiered` | H-near + 近块整体/详情 + 全部远块整体 | 相对 H-near 分离分层摘要的作用 |

首轮最多 4 个目标 × 3 配置，保持模型、目标原文、资料权限、约定和输出要求一致；候选包含跨块、回忆及说话人含糊场景。同一折所有配置均不得从隐藏译文构建摘要。先检查长请求和输出完整性，样本不足则报告不足，不把请求成功视作质量改善。

分别检查摘要可追溯性、关键事实保留、近/远信息定位，以及译名、关系、时序、指代、对白增义和漏译。参考译文需按原文复核，不作为无误金标准。为失败记录“原文有线索 → 摘要保留 → 实际注入 → 模型采用 → 译文正确”，不能把摘要遗漏与模型忽略混为一谈。

记录首次构建、前缀重建、单次翻译和缓存复用成本，分开输入、输出/推理、重试与时延。后续扩大试验时再比较 N 值及同预算完整前文对照；小样本不能证明稳定收益。H-tiered 只有通过工程门禁才算实现完成，是否默认启用由质量证据另行决定。
