# 蜘蛛跨版本连续翻译：问题归因与修复计划

日期：2026-10-18。状态：核心工程修复已实施；真实复验与语义边界见[修复结果](translation-cross-edition-repair-results.md)。下文保留原始问题归因与计划，具体实现差异以结果文档为准。

基线为 [continuous-v1 首轮结果](translation-cross-edition-sequence-results.md)。制定本计划时只核对保存的请求、原始响应、索引、候选和代码，没有新增模型调用。后续修复在新分支进行了真实调用，未覆盖旧实验结果。可复核的诊断数据见 [continuous-v1-diagnosis.json](../artifacts/translation/spider-independent-index/continuous-v1-diagnosis.json)；离线生成脚本为 [diagnose_continuous.py](../artifacts/translation/spider-independent-index/diagnose_continuous.py)。

## 1. 先区分四个问题层次

| 层次 | 本次实际问题 | 当前判断 |
| --- | --- | --- |
| 译文生成与绑定 | 69 段生成 68 段；输出正文后再推断源段归属 | 模型重组跨段句子，违反布局要求；工程没有自动恢复 |

## 2. 69 段为什么变成了 68 段

### 2.1 原始响应就发生了重新分段

原文尾部如下，编号为本次规范引用：

```text
J065 そもそもそんなスキルがないときは天の声（仮）は反応すらしてくれないし、スキルが存在してたとしても、
J066 《スキルポイントが不足しています》
J067 という答えが返ってくるだけだった。
J068 スキルを取りまくって無双！とかできない仕様らしい。
J069 私が思っている以上に、スキル関連の制約は厳しいようだった。
```

模型实际返回：

```text
Z065 说到底，没有那种技能的时候天之声（暂定）连反应都不给，就算技能存在，也只会回一句：
Z066 《技能点不足》
Z067 看来这设定是不允许我狂拿技能开无双的。
Z068 技能相关的限制似乎比我想的还要严格。
```

`J065–J067` 在日语中构成一个跨三段的句子。模型把 `J067` 的“只会得到这样的回答”提前译为 `Z065` 的“也只会回一句”，因此三段变成两段，后面两段编号整体提前。

从这五段看，主要是跨段重组，不能据段数直接认定丢失了一整段含义。这里也没有发生存储换行丢失：原始模型响应有 68 个非空行，保存稿与只做换行规范化的原始响应完全相同。该请求 `finish_reason=stop`，输出 1,167 tokens，低于请求的 8,192 tokens；没有输出预算截断的迹象。

实际翻译输入包含完整的 `J001–J069`，system 也明确要求每个非空源段对应一个中文非空行。直接原因是生成未遵守布局约束；更具体的行为是按中文句法重组了引语前后的叙述。日志不能证明模型内部为什么优先这样处理，也不能证明长上下文是必要原因。长上下文和重复材料只能作为待对照的影响因素。

### 2.2 为什么后续映射没能处理

三次映射的原始输出文本 SHA-256 完全相同。它们均把 `J065,J066` 对应到 `Z065,Z066`，随后继续按同号配对，最终输出不存在的 `C0014.Z069`。这既是非法引用，也是尾部语义错位：实际 `J068` 的主要含义在 `Z067`，`J069` 在 `Z068`。

仅为解释内容，合理的粗粒度对应是 `J065–J067 ↔ Z065–Z066`，然后 `J068 ↔ Z067`、`J069 ↔ Z068`。这不是已经采纳的机器映射，也不满足当前 `preserve_paragraphs` 要求，不能直接写回数据库宣称完成。

相关工程机制：

- [coverage.py](../translation/review/coverage.py) 的校验检查标签存在、顺序、重复和覆盖，不能检查每组的实际含义。错误的同号配对在引用合法时可能通过结构校验。
- 重试反馈只报告 `invalid_mapping:m68`、未对应 `J069` 等，没有明确列出非法目标 `Z069`、合法目标止于 `Z068`，也没有指出更早的语义偏移。再次要求完整映射，并附上之前整份错误响应，未能改变本次结果。
- 两次诊断重试仍使用 temperature=0；相同文本是实际观测，不能仅凭此断言具体模型机制或网关行为。三次输入估算分别为 4,335、6,186、8,037 tokens，远短于翻译上下文，不能把这组失败全部归于长上下文。
- [service.py](../translation/sequence/service.py) 已把段数检查提前到映射之前，所以当前恢复不会继续支付映射费用。但是它只检测和阻断，没有生成新布局版本的恢复分支。普通修订又依赖先完成审校、裁决，布局错误无法进入这条修订路径。

### 2.3 应修复的设计缺口

当前流程要求输入带源段 ID、输出不带 ID，再给纯正文按行产生新的 Z 编号，最后让另一个 LLM 猜归属。布局约束只有自然语言要求，没有直接传递到输出数据结构。

保留原文段落是当前输出配置的选择，不是所有合格译文必然满足的语言规律。自然重分段可以另设多对多输出配置，但本轮先保持既有实验要求，补齐明确绑定和有界恢复，避免用放宽门槛掩盖失败。

## 3. 称谓到底在哪一步丢失

### 3.1 `岡ちゃん`：抽取和召回都成功，实体名称与称呼形式混用

完整证据链如下：

1. 日文索引 `Bb07f77a60b0c6dbf17da.n6` 抽到 `岡ちゃん`，描述明确写“古文教师的爱称”，引文位于当前目标章。
2. 中文开篇索引 `Ba8cc474d7ab3d46951ba.n25` 抽到“冈崎香奈美”，描述写“外号冈姊的古文老师”，用例本身是“……被外号冈姊的冈崎香奈美老师直接抓包……”。但没有独立、可匹配的“冈姊”名称形式。
3. 匹配模型基于同为古文教师、爱称和课堂用例建立了对象关联，有依据；它没有把二者误认成完全无关的角色。
4. [parse_entity_matches](../translation/editions/protocol.py) 直接以 `target_form = reference_entity['form']` 组装映射。匹配 prompt 及 schema 没有提供独立的“此处该用哪种称呼”字段，因此自动得到 `岡ちゃん → 冈崎香奈美`。
5. 当前章的参考包保留了这条候选及中文用例；真实翻译 prompt 中“冈姊”出现 1 次、“冈崎香奈美”出现 2 次。不是预算把称谓证据全部删掉了。
6. 首稿仍使用“冈酱”，审校未指出。说明已有用例也不保证模型采用；候选主值与用例中爱称不一致，进一步增加了判断负担。

所以应归因于“名称形式表示不足 + 候选生成不准确 + 生成/审校未采纳已有用例”，不能归为纯抽取失败或纯召回失败。翻译成“冈酱”主要是与既有中文称谓不一致；不能仅因没有沿用文库就认定发生了剧情语义错误。将其强制替换为全名，同样不合适。

### 3.2 `リホ子`：日文抽到，中文开篇漏抽，后续没有原文回查

1. 日文索引 `Bb07f77a60b0c6dbf17da.n5` 已抽到 `リホ子`，描述为同班女生绰号，本名未知。因此不是日文侧抽取失败。
2. 中文第 1 卷 S1 原始正文 `print-zh-v01:OPS/page4.html` 明确包含：

   ```text
   P0063 ……坐在左前方座位上的女学生。她叫作真贞子。那不是她的本名。
   P0064 真人版贞子──简称真贞子。
   ```

3. 该正文确实属于开篇中文索引输入范围，但模型原始摘要/抽取输出里没有“真贞子”，解析后的实体目录也没有。是摘要联合抽取时的内容遗漏，不是解析器删除了一条已经输出的实体。
4. 该次抽取正常 stop，共返回 35 个实体，未达到 prompt 的最多 64 个；没有证据表明是硬数量上限或输出截断导致。COVERAGE 声称 `processed_all=yes`、`entities_exhaustive=no`，自然语言 omissions 也没具体指出这个名字，说明自报覆盖不能证明名称穷尽。
5. 实体匹配的候选中文目录因此缺少“真贞子”，返回 `reference_entity: 未匹配`、`status: rejected`，理由是“参考侧无明确对应实体；不得凭推测合并”。这个拒绝就给定目录而言是谨慎行为；其范围只能解释为“本次目录中未找到”。
6. 另一个较后的中文 L2 `B7a21e7c37cf078ce14b0` 的确抽到“真贞子”，但不属于这次开篇匹配使用的参考 L1 范围。不能因为全库某处存在记录，就认为本次匹配模型已经收到它；也不应为补一个名字引入较后整块描述中的额外剧情。
7. [local_rows](../translation/editions/context.py) 有事件锚点时只取事件窗口，不再同时取术语命中窗口。本次选入的是 S1 裂缝结尾的 `P0072–P0075` 四段，不含前面 `P0063–P0064`。整个真实翻译 prompt 中“真贞子”出现 0 次。

因此链路为：**中文开篇漏抽 → 受限候选目录未匹配 → 局部材料选择未补救 → 翻译、审校没有目标中文称谓证据。** 只提高 embedding 相似度或把同一候选再注入一次，不能补出缺失记录。

另有版本差异：Web 的解释是 `リアルホラー子`，文库写“真人版贞子”。后续可以参考“真贞子”这个昵称，但如何保留 Web 的命名解释需要单独核对；不能直接把文库解释覆盖 Web，或仅以是否含“真贞子”判断整句语义正确。

### 3.3 当前定向检索为什么没有自动补上

[sequence/targeted.py](../translation/sequence/targeted.py) 的检索主要面向可见 Web 历史及其绑定译文、已有候选知识。它不会自动在独立文库正文中为一个未匹配名字重新提取中文名称。其片假名规则也不能单独完整表示 `リホ子` 这类混合表记。

目前独立版本 `lookup_reference` 主要读取已建索引，不等于已实现独立版本原始正文的名称补查。P6 的 Web 历史工具、跨版本参考包和独立版本查证不能混为已经连通的同一个检索入口。

## 4. 最小修复设计

### R1：输出带源段 ID，并在审校前有界恢复

新 run 使用独立版本化的生成协议。整章仍一次翻译，保留现有完整上下文，不拆成逐段独立调用。内部输出采用简单平面记录，例如：

```text
@@TRANSLATION C0014.J065
text: 说到底，没有那种技能的时候，天之声（暂定）连反应都不会有；就算技能确实存在，
@@TRANSLATION C0014.J066
text: 《技能点不足》
@@TRANSLATION C0014.J067
text: 也只会得到这样的回答。
@@END
```

以上只演示本次布局恢复的可能形态，不是已经生成或验收的修复稿。正式 prompt 的 few-shot 使用与作品无关的合成句子，覆盖“叙述—独立引语—后置叙述”的跨段句式，不把本样本答案写入生产规则。

解析器检查本次合法源 ID 清单、恰好出现一次、顺序、非空正文、结束标记。宽容处理已明确支持的标题全角变体、空白和包装，不修改正文含义，不补缺失文本、不猜非法 ID。程序组装干净正文和稳定引用；ID 不进入最终 EPUB。

绑定标为 `declared_by_translation_output`，表示模型声明的结构归属，不能标成“语义已验证”。通过后照常进行原文忠实度审校，特别检查相邻段之间搬移内容、重复和遗漏。新路径不必再让独立映射模型重建同一份结构；旧纯正文输入仍保留既有映射路径。

失败恢复规则：

- 首次生成后立即验证；不向映射/审校继续传递非法布局。
- 同一章的生成/布局恢复最多 3 次物理请求，包含首次；传输失败也占用已分配尝试与总预算。反馈、变换消息、重启不能重置该计数。工具调用若启用也受明确的共享物理请求上限约束。
- 可定位缺口时只返回该小窗口的完整 ID 记录，源文及前后上下文同时提供；只替换明确范围，范围外文本 hash 不变。无法可靠定位时允许一次整章按 ID 重新输出，不能靠段数猜位置。
- 原草稿、恢复请求和响应保持不可变，成功输出建立显式父版本/恢复来源。为布局恢复单列原因与计数，不能因结构重试消耗或绕过现有最多两轮语义修订限制；`create_version` 的父链、round 语义和版本读取需同时调整并做兼容测试。
- 结构修订成功后重新检查并审校整个当前版本；失败到上限才阻断，不补空行或按序强配。

旧失败稿的验证分支单独处理：保留原 `continuous-v1`。优先使用现有 `fork_from_commit` 继承四章完整、可验证前缀，再将第五章失败稿作为显式外部恢复输入，记录原 run/version/hash；不能把它变成新分支的已提交历史。新分支冻结新协议和恢复预算；比较报告必须区分“继承草稿后恢复”与“新协议从头生成”。

涉及 [sequence/service.py](../translation/sequence/service.py)、[sequence/requests.py](../translation/sequence/requests.py)、[sequence/schemas.py](../translation/sequence/schemas.py)、[review/versions.py](../translation/review/versions.py) 及新增输出协议模块。旧 run 的 prompt、缓存键和版本读取规则保持兼容。旧映射诊断同步补充非法标签原值、合法范围、相邻原译文窗口；不再只反馈记录序号，但不为旧映射增加无上限重试。

### R2：把“同一实体”与“此处称呼”分开

不建设完整别名图。保留当前实体目录和匹配结果，给实体匹配增加最小的出现形式字段，例如 `reference_rendering`、`rendering_kind`、`rendering_evidence_ref`。

实体关联仍可为“`岡ちゃん` 对应古文教师实体”；当前出现形式候选应为“冈姊”，类型为 nickname，用例必须确实出现这个字符串。解析器不能继续无条件将中文实体 `form` 当作最终 `target_form`。模型没有提供具体形式时兼容旧记录，但标明它只是实体主名候选，不保证适用于当前称呼。

prompt 明示区分爱称、实名、称号、泛称和等级，不把 Web 当前只写爱称的地方扩写成文库全名。送入的说明来自当前/可见源文局部语境，继续隐藏整块可能含后续剧情的描述。所有译法仍为候选，冲突保留，不能自动建立隐秘身份等价。

涉及 [editions/prompts.py](../translation/editions/prompts.py)、[editions/protocol.py](../translation/editions/protocol.py)、[editions/service.py](../translation/editions/service.py)、[editions/context.py](../translation/editions/context.py) 和连续桥接投影。新匹配输出字段需版本化并进入缓存身份。

### R3：对缺失的当前章名称做小范围补查

无需重建全书所有实体。利用已有源侧实体及当前章出现位置，为没有可用中文形式、存在形式冲突或证据不足的重要名字发起有上限的定向补查：

1. 收集当前章实际出现的源侧实体表记、源文局部定义及已有匹配状态。优先用完整实体表记，不仅依赖片假名正则。未覆盖的源侧范围明确标记，不能宣称全章实体穷尽。
2. 先读当前已关联的文库章节/局部 L2 原始正文，不要求目标名字先存在于实体目录。对于本次 S1，可直接查看已有同场景章节的完整正文或足够覆盖的窗口。
3. 将多个待查名字合并成一次有预算的模型请求，要求返回实际中文出现形式、证据标签和对象关联依据；没有证据就保持缺失/歧义。沿用结构化调用的有界重试；默认一个限定候选范围，不为每个名字遍历全书。
4. 必须校验中文表记逐字存在于实际引文、源名确实在当前/此前可见 Web 中、引文来自声明的版本和范围。匹配理由由模型判断，机械绑定成功仍不等于对象语义已确认。
5. 结果作为补充候选 sidecar 缓存，绑定原始 revision、检索范围、prompt/模型/解析版本和可见性。更新只影响后续新快照，不修改已冻结 run。

局部正文选择改为“事件窗口 ∪ 已知称谓/术语用例窗口”，去重并共享最终预算；事件锚点不再排斥术语锚点。未匹配名不能靠中文精确词形检索解决，因此第 2–3 步的原始正文补查仍有必要。预算不足时记录具体未注入项，不把省略解释为不存在。

增设每个待查名字的简短链路记录：源侧是否抽取、参考候选范围、中文形式是否存在于目录、匹配/补查结果、可见性过滤、预算省略、最终是否进入 prompt。`catalog_missing` 与 `evidence_incompatible` 要分开，前者不能持久化为全书否定结论。

MVP 先完成离线预编译参考包；不把所有角色的交互工具扩展同时纳入必做项。后续可让翻译/审校/裁决共用同一只读独立版本 lookup，但本轮关键名字应主动召回，不依赖模型先意识到自己缺证据。

### R4：审校消费相同的名称证据，并做受控对照

翻译、审校和裁决必须看到同一版本的称呼候选、原始用例和用途约束。增加简短检查要求：当前称呼形式是否适用、是否把爱称改为实名、是否损失 Web 的命名解释、是否把外版改写当作错误修正。偏离候选只产生待核对信号，不能做无条件字符串替换。

把现有首稿固定，分别用旧材料与新材料审校，测量“补足证据后是否能定位、引用和修正”。再另测新材料是否改善从头生成。不要同时换模型和草稿后把差异全部归因于召回。模型仍漏检时报告明确失败样本；不能通过强制输出 findings 或把标准答案写入 prompt 宣称能力提升。

“冈姊”看具体出现用法；“真贞子”同时核对跨版命名解释。生硬行文单独抽查，不用术语一致性得分替代自然度或原文忠实度。

### R5：失败收尾和增量知识保持可追溯

- runner 的阻断、异常、预算耗尽及正常结束统一关闭仓库并导出状态、已保存草稿和请求。报告导出不调用模型，导出失败不得覆盖首个运行错误。
- 已提交前缀的尾部索引作为显式、可恢复的付费步骤。若退出时还有构建预算，可按配置物化；预算耗尽时保留 pending 与可读快照，不能为了报告隐式发额外请求。翻译完成与索引待完成分别呈现。
- 摘要声称“三章”却覆盖四章、COVERAGE 与实体清单矛盾，暂不增加独立模型审查层。来源成员数、范围和抽取计数以程序字段为准，模型自然语言视为未审说明。
- 已生成的“冈酱/理保子”只记录 `provisional_rendering`。修复后生成新候选修订，标记被替代用法，不能因重复出现或压缩汇总升级成规范译名。

涉及 [run_cross_edition_sequence.py](../scripts/run_cross_edition_sequence.py)、[report_cross_edition_sequence.py](../scripts/report_cross_edition_sequence.py)、[sequence/knowledge.py](../translation/sequence/knowledge.py) 与现有 outbox/recovery。

## 5. 实施顺序与验收

| 顺序 | 交付 | 必须验证的具体场景 |
| --- | --- | --- |
| 1 | R1 输出协议、恢复账和旧映射诊断；R5 本地收尾 | 69→68 原始失败稿产生新恢复版本；每个源 ID 唯一；内容不靠补空段凑数；异常也能导出原稿；到上限后恢复不继续付费 |
| 2 | R2 出现形式候选 | 教师实体可关联，但 `岡ちゃん` 的当前形式为有证据的爱称；实名/同名异人/未知身份负例不被自动合并；旧记录可读 |
| 3 | R3 定向补查和窗口并集 | 不重建全库也能从开篇实际正文找到“真贞子”；不存在的测试名字保持未匹配；事件和称谓证据同时进入预算；完整记录未注入原因 |
| 4 | R4 固定草稿审校对照 | 分别报告证据是否注入、问题是否检出、引用是否正确、裁决是否合理、修订是否忠实；不要求凭空认定所有文库用法都是标准答案 |
| 5 | 五条目窗口闭环 | 保留旧分支，新分支完成最后一章及其审校/裁决/提交；再单独完成新协议五章生成，确认没有通过继承历史掩盖新流程问题 |
| 6 | 10–20 条目连续实验 | 实际跨至少两个新 L2、一次压缩、一次中断恢复；尾部索引、前缀和引用完整；先测成本，再决定是否做 L1 边界测试 |

回归优先扩充 [test_cross_edition_sequence.py](../tests/translation/test_cross_edition_sequence.py)、[test_independent_editions.py](../tests/translation/test_independent_editions.py)、[test_p7_sequence.py](../tests/translation/test_p7_sequence.py) 以及新增协议测试。关键失败注入包括：重复/遗漏/未知 ID、跨段含义搬移、恢复后仍无变化、保存响应后崩溃、重启时不重复调用、付费尾部索引失败、旧冻结上下文恢复不改字节。最后运行现有完整测试，不把 mock 通过当成真实模型验收。

其中跨段含义搬移不能靠 ID 校验自动识别；mock 只验证该情况仍进入语义审校且不被结构通过自动升级为已确认，实际检出能力必须由固定模型实验和人工核对评估。

实验分三步控制变量：先固定 68 段草稿验证布局恢复；再固定 S1 首稿只改变称谓证据验证审校；最后在新分支运行完整新方案。每一步保存完整输入输出、尝试数、实际 tokens、采用证据和剩余缺陷。

验收分两类：工程验收要求整个窗口走完且可恢复、引用有效、没有静默缺口；质量评价要求单列原文事实、名称形式、版本污染、叙事揭示和行文抽查。一个窗口完成仍不代表全书已可用，零 findings 也不作为质量真值。

## 6. 当前不优先做的事

不先重抽全书、不构建全局别名/身份图、不新增全量抽取审核模型，也不为每次失败无限追加 few-shot。首先消除已证实的结构绑定和材料缺口，再用固定草稿实验判断剩余问题是否属于当前模型在证据充分时仍无法可靠处理。
