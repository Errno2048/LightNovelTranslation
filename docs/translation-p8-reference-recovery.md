## 1. 协议与兼容性

新建 `SequenceSpec` 默认采用 `reference_profile=stable-v1`、`mapping_profile=coarse-v1`。读取缺少这两个字段的旧 manifest 时，分别恢复 `legacy`、`audit-v2`；旧 manifest 的哈希和请求身份不变化。

模型看到的章节 ID 由规范 `match_key` 确定。例如 `main:400 → C0400`，日文、中文段落分别为 `C0400.J001`、`C0400.Z001`。番外等其他目录命名空间使用带 X 的稳定摘要 ID，避免与正文冲突。段落按非空正文排序，多份中文文档在同章累计编号。注册表绑定真实文档、文本版本和段落，不从模型输出的数字推导另一个引用。

后台仍保留物理 chapter ID、目录 order、原始段落 ID 和 revision。索引抽取、翻译、近章证据、审校、裁决及查证工具使用同一套模型引用；审校报告仍绑定真实段落 ID。引用 ID 仅在绑定的文本版本中解释，翻译修订后必须重新映射。

事件、状态、知情字段改为 `disclosed_in: C0400`，跨章列出实际章节 ID。解析器根据当前注册表派生披露位置，不能把书面章号、目录序号混用。故事内部时间仍独立记录。新协议不接受数字偏移别名；旧协议保持独立读取。

进入 prompt 的历史导航删除旧引文注册表和数字披露字段，保留摘要、实体描述、实际译法和质量标记。已存 provenance 不删除，工具仍能读取底层正文。旧引文不能通过改名就晋升为新证据。

## 2. 小范围映射恢复

`coarse-v1` 先执行原有标签存在、顺序、重复和全覆盖检查，只有错误完全来自未映射段落时才尝试并组。

| 限制 | 初始值 |
| --- | ---: |
| 单个连续缺口 | 最多 2 段 |
| 每侧全章未映射总量 | 最多 4 段 |
| 恢复后单组每侧段落 | 最多 8 段 |
| 恢复后单组双语字符 | 最多 6000 |

程序合并缺口两侧相邻锚点；章首、章尾使用唯一相邻锚点；同组内部缺口只扩充该组。不跨章，不猜语义归属，不处理重复、逆序、未知标签或不完整协议。多处合并后仍须严格形成两个有序分区。

保留 `original_groups`、`original_unmapped_source/target`、`original_errors`、规则版本及 `recoveries`；恢复组状态为 `coarse`。`mapping_complete` 仅表示结构覆盖恢复，`semantic_coverage_reviewed` 仍为 false。读取 coverage 时，从 immutable raw 重新解析并执行同一确定性恢复，再核对全部派生字段。

每个恢复组产生 `mapping_gap` 信号，列出原未映射段落、完整局部双语及恢复方法。日文缺口标为 `possible_omission`，译文缺口标为可能增译或映射漏列。审校与裁决必须分别作出带段落定位的处置；确认错译必须关联 FINDING，证据不足保留未决。不能因结构并组自动驳回漏译警报。数字规则继续针对局部分组运行，其计数一致不能证明对象对应正确。

对于不能局部恢复的结果，最多三次映射尝试；后续 prompt 提供缺失/重复/顺序诊断，要求完整重建映射，允许真实未对应。反馈请求、传输重试共享同一逻辑任务的物理上限；重启复用已存 raw，不重置次数。映射尝试谱系单独记录。

### 无变化修订的有限复核

续测在 428 章暴露另一类阻断：审校声称“乌鲁穆特”与“乌鲁穆特”译名不一致，裁决确认，两份补丁均与当前正文逐字相同。该问题与编号、映射和 JSON 格式无关。

仅当补丁的定位、hash、范围、覆盖及段落数均通过正常校验，且完整修订文本完全未变时，允许一次裁决复核。输入提供原日文、当前中文、原意见、原裁决和实际补丁，要求重新判断实际差异。程序不把无变化自动视作误报，也不强迫模型制造修改。

原来确认的意见须全部被模型明确驳回，且不能新增确认项，才可继续；仍确认或未决时保持阻断。原裁决、补丁、新裁决和恢复对象全部保留。审校阶段在修订前持久化，重启使用同一份资料展示版本；复核请求缓存与物理调用上限不会因重启重置。历史 legacy 分支保留原行为。

真实 428 章复核已将两条意见改判为 dismissed，正文不变，之后继续运行。失败时的状态、封存和旧补丁另存于 `interruptions/`，不是覆盖历史失败后声称从未发生。

随后 431／432／433 章翻译的实际输入为 130200／134510／138555 tokens，缓存命中为 124928／132224／135552，约 96.0%／98.3%／97.8%。这说明检查点重建后仍能恢复前缀复用；首次换前缀与后续连续请求需要分开观察。

知识体积也值得继续优化：H 的候选／约定块本地计数 78625 tokens，导航块 27232 tokens，两者约占消息正文 tokens 的 84.8%。因此，本轮已验证按层重组可以缩短会话，但“全候选全部入 prompt”的工作集还不精简；当前大窗口足够容纳，并不等于在 128k 模型下也能直接运行同样配置。后续应优先做通用的候选去重与展示压缩，并保留需要时获取底层详情的入口。

两份草稿都保留了救援、绑架、追踪等待、魔药与魔剑的主要叙事，25 名袭击者、40 人以上损失、约 15 名伤者等数字也保留。H 对两把插入剑的指代更明确，但有“还没有完全死亡”“为了一女儿”等不佳表达；U 的“这里就忍忍吧”弱化了叙述者请求原谅的语气。一个开发章不足以证明压缩提高或降低总体质量。

### 原文复核与剩余问题

- **410 章使役关系漏检**：`大量の料理を出すのは控えさせたよ？` 仍译为“我还是克制住了……”。结合后文应为师傅让芙兰克制，而不是师傅自己克制。常规审校与 clean-v2 展示复测均无 FINDING。
- **410 章地点漏检**：`屋根裏に1人。隣の部屋に1人` 译为“屋顶上一个人。隔壁房间一个人”，前者应为阁楼／屋顶内侧空间。审校和裁决还声称人数与位置均一致，说明规则命中后的模型解释并不可靠。
- **423 章有真实补丁但收益未证实**：模型将 `ディメンジョン・シフト` 的“次元转移”改为“次元位移”，规范段落 ID 与 hash 正常定位；是否必须改名尚缺充分依据，不能计为已证实的正确修复。
- **428 章无效修订**：两条相同译名误报被裁决确认，补丁完全不变。一次反馈复核后两条均被驳回，正文未改；这是真实的恢复案例，不是原始裁决本就正确。
- **430 章审校误修风险**：原文明确腹、背各插一把剑，H 草稿写“那两把剑”。审校／裁决把后句 `その剣` 强行解释为单数，改成“那把剑”；原文没有为这种数量收窄提供充分依据，原“两把”有前句直接支持。这次修订及零发现回归不能算质量成功。
- **429 章局部正例**：五名敌人先减为四名、四次挥剑、每次消耗耐久等数量和因果链保留。这是逐原文抽查结果，不代表全章或全窗口已获语义认证。
- **439 章局部正例**：药品触发抵消、耗尽对方魔力后施术，以及师傅模仿该办法的因果链保留；四名敌人逐步减少的叙述也保留。
- **441 章待查专名**：`フレッシュ・グレーター・ゴーレム` 被译作“新鲜大石像鬼”，同句原文明确它是用尸体制作的 golem。审校按 Fresh 理解，仅建议加英文或改变名称形式；裁决把相关意见作为措辞偏好驳回，没有查证 Fresh／Flesh 的音译歧义及 golem 的概念对应。该例至少暴露了应结合当前段落重新查证的疑点，不能把提出过术语意见视为已经正确检出并修复。

封存后，441 章参考对照将该名称译作“肉身大魔像”，与同句“尸体制作”的解释相符。这里的判断依据仍是日文正文，参考只提供另一种译法，不据此规定唯一译名。

411／423／424 三个新工作提交还保留未决，包括历史译名证据不可定位、技能译法缺依据和主体省略的歧义。423 章修订为“次元位移”后，回归审校又建议改回“次元转移”，裁决以历史依据不足保留未决；没有把这种反复当作稳定修复。部分 UNRESOLVED 带有 `needs_lookup`，但没有发出实际 QUERY，本轮查证工具调用为 0；记录疑点不能等同于已获取额外证据。

另确认一项仍待修的上下文传播问题：审校得到的是检查点工作集与“当前章新增 delta”，没有持续汇总此前各章已经注入的 delta。420 章译者新增 197 条候选，审校也能看到；421／422 章新增 delta 为零，审校又只剩检查点的 75 条候选，而译者仍在会话前缀保有那 197 条。430 的新检查点暂时把累积知识重新带回审校，但后续新增知识仍会遇到同类问题。本轮聚焦引用和映射恢复，未在运行中改变该策略；后续应优先修复，不能将质量不足全部归因于模型。

### 展示版本与证据边界

最初长进程采用 initial-v1 展示，历史摘要自由文本仍带少量旧定位字符串；它们不会被 stable-v1 解析器猜成另一个新引用。随后 clean-v2 清理自由文本旧定位及规则信号中的物理段落 ID，同时保留实际原文／译文正文。旧请求不回写，旧审校资料按保存的展示版本复编译。

`clean-context-http/` 对相同 410 工作稿额外真实调用审校、裁决各一次，两个完整 payload 均无旧章节定位残留，仍漏检上述语义问题。它是展示协议探测，不修改主分支稿件，不构成独立质量评测。428 之后重启的新进程使用清理后的代码；428 的已有审校资料仍明确绑定原展示版本。

逐章审计在 410–429 的翻译 prompt 中各计得 5 处 `ja/zh:main:` 旧定位残留，来自历史摘要自由文本；430–445 的对应计数为 0。该计数只针对这类字符串，不是引用语义正确率。旧原始请求仍保留，未声称整轮从一开始就使用 clean-v2。

### 446 章阻断的具体原因

1. 原稿在 `C0446.Z007` 将 `ホーリー・オーダーの野郎` 写成“圣灵骑士团那帮家伙”，下一段又说它是神剑。
2. 首审只把同名在 `C0446.Z008` 的用法定位为 major，另一个相同音译的误报和招式措辞意见被裁决驳回。
3. 绑定 Z008 的补丁将该段改为“圣灵剑霍利·奥德”，正确遵守了单段 hash 与范围限制，但没有改动未被确认的 Z007。
4. 回归审校这才定位 Z007 的旧表述，裁决确认前后不一致。冻结 `max_revisions=1` 已用尽，流程阻断，未提交 446。

这是审校未一次枚举同名出现位置、局部补丁与一轮上限共同暴露的问题，不是 JSON 解析失败、映射不全、token 越界或费用预算耗尽。补丁没有权限静默改写另一个未确认段，程序也没有为完成窗口而提高修订上限。

“圣灵骑士团”作为一个剑名是否必然错误，不能仅由其字面像组织名决定；原稿“那帮家伙”以及修订后两处不同名称则需要核对。封存后参考写作“神圣秩序（Holy Order）”，支持按神剑理解，但不证明必须采用模型建议的音译。后续宜让审校定位同一术语的全部受影响位置，再做受限补丁；不能直接以无条件全文替换代替审查。

446 章也显示参考不是金标准：原文 `アース・シューター` 配合巨岩、后续 `大地の壁`，本轮“大地射击／大地墙”与日文相符；参考出现“寒冰射击／冰墙”，不能反过来据参考判本轮错误。
