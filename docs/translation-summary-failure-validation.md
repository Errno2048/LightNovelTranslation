# 摘要失败诊断：格式、证据和语义分开验证

日期：2026-10-16。范围为 P4.2 的失败诊断与实验验证，所有生成物仍是候选，没有晋升为生产知识，也没有调用目标章节翻译。

## 1. 需要区分的四种结果

1. **输出表示**：是否按要求输出 JSON／平面记录，是否闭合、是否夹带围栏。
2. **内容契约**：字段类型、枚举、实体数、字数和必填证据是否满足要求。
3. **证据定位**：引文是否逐字出现在指定位置，译名是否真的出现在其双语证据中。
4. **语义正确性**：引文是否支持描述，人物／组织是否混并，时序方向、因果与叙述层次是否保真。

前一层通过，不代表后一层通过。“整条管线 0/4 通过”不能解释为四份摘要内容全部错误，也不能将成功解析解释为知识可信。

## 3. 平面记录与新实验

实验模块 `translation/narrative/flat_summary.py` 使用 `@@OVERVIEW`、`@@ENTITY e1`、`@@RENDERING e1` 等开始标记和独立字段，不要求对象／数组闭合，不需要转义自然语言中的引号、括号。多行值缩进，重复字段承载多个形式和引文。主机重建原有的 canonical schema，继续执行原来的内容校验。

单条记录损坏不会让已读取的概括消失，但错误会显式保留；未知字段、孤儿用法、重复 ID、缺字段均不能静默忽略后宣称成功。解析成功与 schema／证据成功分别报告。该格式目前没有替换生产编译器。

独立实验目录：`artifacts/translation/tenken-cache-clean/verification/p4.2-format-consistency-601-700/`。最多 14 次模型调用，预留输入最多 1,800,000 tokens、输出最多 116,000 tokens，HTTP 自动重试关闭，失败也占预算。沿用当前配置模型，无 embedding 调用。

实验输入只取此前已审查覆盖范围内的 601–700 章；这 100 章没有全局保留集缺口。所有实验共享相同截止位置，不引入目标 1200 章译文、未来正文或全文知识。章级配对仍不是逐段语义金标准。

执行内容：

- 601–610：JSON 和平面格式各一次，完整双语正文、摘要上限 2500 字、实体上限 20、固定表达上限 5、证据规则、温度、8K 输出预算一致。
- 601–700：完整 100 章直接生成一次平面摘要；10 个连续十章块分别生成平面摘要，完整覆盖同一范围。
- 将全部十个子摘要再次汇总为最多 2500 字整体概括；不让汇总请求看到直接一级摘要。
- 比较两条路线，附 610、698 章完整双语作为针对旧错误的原文锚点，并放入刻意错误的控制陈述，要求区分真实矛盾、遗漏、状态变化和待回查事项。

共同语义指令还同时加强了人物／组织分离与穿越年龄、时间方向的要求。因此旧 100 章与新 100 章不是纯格式对照；只有同轮十章配对能提供较接近的格式对照。一个配对没有统计显著性，不能外推格式成功率。

## 4. 当前配对结果

601–610 的 JSON 输出正常结束，6,424 输出 tokens，缺少关闭元信息的一个 `}`。诊断补字符后，82 处引文均命中原定位，但仍有“输出译名未出现在所引证据”的校验错误；实体记录还把不同技能、药品与原料等混为同一对象。因此它是非常具体的格式失败，并不表示整份内容不可读；引文正确也没有证明实体身份正确。

同范围平面输出正常结束，5,608 输出 tokens，完整解析成功；整体概括 730 字，22 个实体超过 20 个上限，73 处引文中 72 处命中，1 处同章无逐字匹配。还输出了非允许枚举 `creature_species`。

原型平面格式的说明漏列了完整 `kind` 枚举，而 JSON schema 列明了该枚举。这是本轮发现的提示契约不对称，可能解释非标准类型，不能拿类型错误直接证明平面格式更差。后续应把枚举放入两种表示共用的指令；实体数量上限则两边配置已经相同。

初步结论是：平面表示在这个样本中消除了括号匹配失败，未消除其它约束及语义问题。JSON 与平面格式都没有原样通过全部校验。

十个二级块全部返回正常结束的可读结果；其中 8/10 完整遵循平面格式，另外两份分别缺少 `@@END`、增加未知字段 `source_form_alt`。两份的整体摘要仍可独立读出，但解析错误未被忽略为成功。schema 通过 2/10，现有全部内容校验通过 1/10；未进行全块人工语义标注，不能换算成内容准确率。

十个二级块共 595 处引文：580 处原定位正确、2 处同章唯一匹配、13 处同章无逐字匹配。类型枚举缺项是已知提示缺陷，但无法解释全部失败；其余还包括未声明的 source_form、源形式不在日文中、输出译法不在所引中文中等。第 691–700 块的概括能正确写出佣兵团及其团长，元信息却将佣兵团标为 person，进一步说明正文概括与实体抽取需要分开验收。

## 5. 100 章直接摘要与二级汇总比较

全部 14 次调用已完成，均为 HTTP 200、`finish_reason=stop`，没有输出截断或自动重试。不是只做了首个十章样本再推断全块效果。

| 项目 | 直接一级 | 十个二级再次汇总 |
| --- | ---: | ---: |
| 原始覆盖范围 | 601–700，全 100 章完整双语 | 同范围，全十个子块候选 |
| 整体概括长度 | 1271 字 | 2385 字 |
| API 输入 | 547383 tokens | 56569 tokens，不含先生成十子块的开销 |
| API 输出 | 11706 tokens，含 6590 思考 tokens | 2777 tokens |
| 输出结构 | 平面记录完整解析，19 实体 | 自由分段文字；整体概括另带时间线和不确定性 |
| 全内容门禁 | 未通过，含非允许类型与错引文 | 未作为 canonical 知识校验或接纳 |

直接一级的 58 处引文中，56 处原定位正确，1 处同章可唯一重定位，1 处同章无逐字匹配。`creature` 不在允许枚举内，仍与平面 prompt 漏列类型列表有关。整体摘要中还出现了未解释的英文 `exists`。

这里的 2500 字只约束整体概括。二次汇总的全部输出含时间线及不确定性共 3669 字，整体概括本身为 2385 字，没有超过该上限；不能拿全部输出长度误判摘要超长。

可据原文核查的比较结果：

- **时序表达可能在再压缩中退化。** 新直接摘要及其席拉实体描述明确写出幼年罗密欧回到八年前，再长大。601–610 子摘要中也有这个过程，但二次汇总压成“穿越八年前的成年罗密欧”，再次让穿越发生时的年龄含混。610@64、610@66 可以裁定，不能只看两份概括是否使用相同姓名。
- **分层保留了更多分段过程，也会继承候选错误。** 二次汇总保留每十章的事件、另一时间轴 Side 篇、关键招式和中间结果，对杰莱瑟的多次疑似死亡／再出现主动列了不确定性。不能将“直接摘要省略中间过程”直接判为矛盾；死亡的时点、确定性以及人类／魔剑主体需逐段回查。649@102 仍说未死透，649@110 以疑问表达是否已死。
- **新结果的团长和组织描述改善，但不构成纯格式因果证据。** 直接一级和二次汇总均写成“佣兵团……团长耐托哈特”，610、698 章两个刻意错误的控制陈述也被比较器否定。新 prompt 同时强化了实体分离与时序要求，不能把改善全部归因于平面格式。
- **逐字引文不保证描述受到支持。** 新直接 `e1` 写“封有黑猫族少年灵魂”，引用却只有655@89“这把剑叫师匠”；相邻655@91说明智能武器，但这个引文不能认证灵魂来源。另一个可核查的小错误是把649@98的“捏碎颈部”概括成“捏碎头颅”。这些属于内容／支持关系问题，格式改变不能直接解决。

### 比较器自身也必须审核

自动比较输出的 12 条 finding 只是疑点清单，不能当作 12 个已证实错误。`comparison-audit.json` 逐项回查：20 次引用定位中，6 次来自提供的完整原文锚点，其余14次来自输入候选内的引文；17次带短引文的引用均能在原始定位逐字找到。这说明出处可以回查，但不能据此认证判断正确。

例如 finding 6 声称二次汇总写了“收欧雷鲁之孙女凯特琳为见习弟子”，实际汇总连“见习弟子”都没有。该条是比较器对待比较文本的错误归属，已剔除出可采信发现；它引用的683@33只确认姓名，也不能支持“收徒”。比较器还在 finding 4 笼统称两版都按幼年穿越表述，与它自己 finding 2 指出的汇总措辞含混不一致。不能原样采用它的结论或排名。

因此，用户提出的交叉摘要比较适合**产生待回查的差异**：精确摘录先经主机确认确实出自相应版本，再回查涉及事实的原文区间。它不适合自动给出正确率，也不能用同模型两次摘要的一致来认证事实。

## 6. 对失败原因和后续实现的判断

**不是内容与 JSON 二选一。嵌套 JSON 是明确的入口障碍，突破它以后，证据支持和语义仍是独立问题。** 本轮 11 个平面结果中 9 个完整遵循格式，全部11份的整体概括可以独立读出；只有1份通过现有全部内容校验。后一个数字受到已知类型提示缺项影响，不能当作“其余内容全错”。同轮 JSON 的括号失败也不能当作“其内容全错”。

当前证据不足以将错误归因于长上下文注意力衰减：短输入重复了同样的闭合错误；新100章平面输入可正常概括；又只有一个十章格式配对，且新旧提示有语义强化差异。若要识别长度／位置的因果影响，还需固定事实问题和格式，只改变干扰正文长度及事实位置。

后续宜按以下顺序推进：

1. **继续采用可独立解析的记录，补齐提示契约。** 两种表示共用明确类型枚举，末尾重申实际数量上限和配置；源形式重复使用相同字段，不允许自行发明别名字段。保留原始输出、原始类型和错误，不悄悄映射为合法类型以冒充通过。
2. **拆开验收整体概括与实体元信息。** 整体概括、单实体、单用法分别报告结构／证据／语义状态；坏实体不应使已读取概括在诊断中完全不可见，仍不能把可读概括自动晋升为已审核知识。
3. **让主机负责可机械处理的定位。** 章号、语言和逐字引文唯一匹配时，可另建可审计的重定位建议；歧义或无匹配必须保留问题。不要跨章搜索后自动搬动证据，以免掩盖时间归属错误。
4. **用分层差异触发懒加载。** 先比较直接概括与二级汇总的事件／主体／时序；对不一致处读取原文窗口。未提及记为遗漏，不当作矛盾；状态不同先检查时间位置、世界线、人物声称与叙述事实。
5. **审核比较器的证据。** 要求每个 finding 附两侧逐字摘录、原文定位和短引文。先自动核实摘录确实存在，再人工或独立审核语义支持；本轮找到的虚构“收徒”差异应在这一步拒绝。

当前仍不建议把全部未通过候选并入翻译知识库。原型平面格式未替换生产格式，枚举列表等改进尚未进行新的真实 A/B 验证。

## 8. 实验文件和复现

- `p4_2_format_consistency.py --mock`：离线完整流程；真实调用需匹配当前实现的离线预检。
- `p4_2_format_consistency.py --phase all`：独立有界试验，恢复读取已有结果、不自动重试失败请求。
- `p4_2_consistency_audit.py`：只读复核输入输出，在新实验目录写 `audit.json`。
- `p4_2_comparison_audit.py`：回查比较器引用及其对摘要的错误归属，写 `comparison-audit.json`。
- `p4_2_tail_children.py`：与主流程并行生成三个独立尾部子块，使用同一预算账本和请求身份；主流程读取缓存，没有重复付费生成这些子块。
- `io/index.html`：每次完整 prompt、messages、原始可见输出；`http/` 保存实际 payload、响应可见内容、usage 和请求事件，不保存凭据或模型推理正文。
- `attempts.sqlite`：先预留后发送，失败与未知完成状态保留预留；结果未写入生产摘要对象。

回归测试：`py -3.11 -m pytest tests/translation -q`，129 passed；包含平面格式等价、多行文本、多证据、损坏隔离、未知字段、缺结束标记、错误引文仍被拒绝的测试。现有依赖的弃用警告仍在。
