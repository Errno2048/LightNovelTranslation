# 连续翻译历史索引修复规划

本文记录续译定位完成后，历史索引、上下文压缩和增量索引应如何衔接。它依据 2026-10-20 对“植物怪物娘日记”实际运行的诊断结果，既是设计约束也是实现验收依据。当前版本已实现历史层次初始化、增量节点接入和非重叠覆盖；文末仍列出尚未纳入本轮的长期增强项。

## 1. 问题与目标

当前连续翻译存在两套没有完全接通的机制：

1. 独立版本索引可以规划日文/中文的 L1、L2，但连续任务只读取已存在的部分 L2，没有将真实 L1 父摘要接入历史上下文。
2. 任务内增量索引只处理本分支已经提交的译文，不处理任务创建时通过 parallel_pairs 传入的历史双语章节。
3. 未被索引覆盖的历史必须保留为全文，这是正确的安全回退；但当前没有初始化步骤为这些历史建立覆盖，所以它们持续以全文进入上下文。
4. 当前父索引入口主要执行“已有 L2 摘要的汇总”，把 L2 当作构建 L1 的必要前提，无法表达“先直接构建 L1，只有上下文放不下时才回退到 L2 汇总”。
5. 连续上下文把 history_nodes 统一标记为 L1，即使来源实际是 L2，造成表示层级与实际证据不一致。

因此，历史双语没有摘要时会一直被要求保留全文；缩短 parallel_pairs 只能造成显式缺口，不能生成远距摘要。切换到 cross_edition 也不会自动完成历史索引初始化。

目标是在翻译第一章之前完成所有历史的层级覆盖，之后持续推进索引窗口：

    远处历史：L1 整体导航
    较近历史：L2 详细摘要和抽取信息
    最近 N_chapter 章：完整原文 + 已有译文
    当前目标：完整原文

## 2. 核心不变量

- 每个历史源章节都能追溯到 full_pair、L2、L1，或调用方明确接受的 explicit_gap。
- explicit_gap 只表示已确认的输入缺失，不能掩盖“索引尚未构建”。
- 未被摘要覆盖的历史仍保留全文；不能为了通过预算检查而静默删掉。
- L1/L2 节点记录精确的源/译文文档、版本指纹、引用和构建方法。
- 摘要是未审查的导航候选，不自动升级为事实；引用缺失要明确标注。
- 上下文中的 kind、level、representation 必须符合真实节点层级。
- 索引扩展产生不可变的新版本；已保存的 prompt、响应和检查点不得原地改写。
- 远距 L2 默认懒创建。只有翻译、审校或显式查证请求需要细节时才构建。
- 例外是直接 L1 因容量不足而触发回退：为完整汇总该 L1，可以构建其全部必要 L2；这必须标记为容量回退成本，不能描述为普通远距懒加载。
- parallel 与 cross_edition 可以共享覆盖机制，但不能混淆证据权限：确认的一一对应双语可作为历史对照；跨版本中文只能提供有界的风格、术语或候选关联参考。

## 3. L1 构建：直接优先，容量不足才回退

“先建 L2，再利用 L2 构建 L1”是容量不足时的回退路径，不是 L1 的前置条件。

### 3.1 规划一级块

根据章节顺序、标题/卷边界、配置的一级最大范围和模型容量，先生成稳定的一级候选范围。规划只做本地 token 估算并记录源章节、可用中文对照、预计输入/输出、安全余量、token 膨胀系数和回退参数。每个新一级块的首选方法是 direct。

L2 尚未构建不能使直接 L1 进入 blocked。它只表示：如果直接路径因容量不适用，届时需要物化回退所需的二级节点。

### 3.2 直接构建 L1

直接请求将一级范围内完整原文及可用的历史译文对照交给索引模型，要求生成整体摘要、事件、人物/专名、时间关系和知情状态候选。调用前执行保守预算检查：

    估算输入 + 请求输出 + 安全余量 <= 模型输入上限

成功后记录 level=1、build_method=direct、完整 source_ids、请求/响应、输入依赖和结果指纹。无需同时建立该一级块的所有 L2。摘要中的每项知识仍须有来源引用；缺失引用不能伪装成已核实。

### 3.3 容量不足时才执行 L2 回退

仅当本地预算预检确定直接 L1 放不下，或服务端明确报告上下文长度超限时，才触发：

1. 按最小内容量、最大章数和正文边界规划所需 L2。
2. 同一 L1 下按阅读顺序串行抽取 L2，使后续节点可参考前驱摘要；不同 L1 可并发。
3. 校验 L2 覆盖、状态和可用性。
4. 用已完成的 L2 摘要构建 L1 概括。
5. 将 build_method 记录为 child_summary_rollup，并保存精确子节点依赖。

格式错误、引用缺失、语义质量低或网络故障不能伪装成容量超限。它们进入有界重试、格式修复或显式 partial/blocked 状态，不应自动触发昂贵的 L2 全量抽取。单章本身超过输入上限时返回带章节 ID 和预算明细的 oversized_chapter。

建议区分 planned、direct_pending、fallback_required、partial、built、stale、blocked 等状态。allow_partial 不能把未覆盖的章节宣称为已覆盖。

## 4. 历史双语初始化与任务边界

### parallel 模式

调用方确认的 parallel_pairs 应在任务创建前进入历史索引准备阶段：

    parallel_pairs
      → 历史双语归档和依赖校验
      → 直接构建 L1
      → 只有容量不足时构建 L2 并 rollup L1
      → 保存历史索引版本和覆盖表
      → 创建翻译任务

不得混入目标章节或未来参考译文。摘要可以利用真实对照获取译名和文风线索，但保留译文质量及未决问题标签。

### cross_edition 模式

日文 Web 版与中文文库版分别建立索引。日文侧 L1/L2 用于 Web 剧情导航；中文侧摘要、实体和区块关联仅作为独立版本候选。匹配失败不得阻止日文 L1 建立，文库剧情也不得升级为 Web 事实。

### 冻结任务与索引修订

任务冻结创建时采用的索引版本和输入身份，不冻结未来索引的产生。后来懒建 L2 或新译文增量物化时，生成新的 index_revision。下一章的规划或显式工具调用可以选择新版本并生成新上下文指纹；旧请求与旧检查点仍引用其原版本。

## 5. 远距 L2 按需构建

翻译、审校或裁决模型发出局部查证请求后：

1. 校验请求范围位于当前任务允许的历史范围。
2. 查询指定 L2 是否已有可复用版本。
3. 若没有，只构建请求涉及的 L2，不自动抽取整个一级块。
4. 保存不可变节点，并生成新的父级元信息/索引版本。
5. 返回摘要、来源引用、质量状态和覆盖缺口；不自动将全部远距正文塞回主上下文。
6. 只有模型进一步请求原文时，才在独立预算下返回有限章节或段落。

未构建的 L2 表示“细节尚未物化”，不表示“没有事件”。失败时返回原因、已覆盖范围和证据入口，不得静默丢弃相应 L1。

## 6. 连续翻译中的滑动更新

每次提交译文都会产生增量索引待办。检查点或显式 materialize 执行时：

1. 开放尾部保留全文。
2. L2 块封口后，构建其 L2，并可向后续同父节点提供前驱导航。
3. 需要更新父级范围时，优先尝试直接 L1；容量不足才从已封口 L2 rollup。
4. 保留旧 L1/L2 版本，任何变化都产生新的索引修订。
5. 上下文选择器按最近全文、邻近 L2、远距 L1 重建覆盖。
6. 抽取不完整或失败的范围仍保留全文或显式缺口。

不要求每章重摘要全书。仅在 L2 封口、跨父块、容量阈值或显式查证时触发相应构建。

## 7. 建议的公共职责

接口名称可在实现时调整，职责应明确分离：

- 历史规划/准备：接收源版本、可选双语映射、近章窗口和索引参数；先返回本地计划，再由显式构建操作执行模型调用。
- 父级构建：默认 direct_then_rollup；结果区分 direct、child_summary_rollup、partial、blocked_context 和其他失败。
- 细节检索：指定 parent/child 和请求原因，只确保请求范围内的 L2 存在。
- 任务规划报告：展示索引修订、最近完整双语、邻近 L2、远距 L1、未覆盖范围和预算。
- 翻译后的物化：更新提交章节的增量节点，并供下一检查点选择新索引修订。

覆盖项至少包含 source_ids、representation、真实 level、node_id、index_revision、build_method 和 quality。history_nodes 不得统一写死成 L1。

## 8. 实施阶段

### 阶段 A：数据契约和文档

定义统一覆盖、节点层级、索引修订及 direct/fallback 状态；修正“current_index 会处理历史原译”的错误描述。

验收：离线历史 pair 缺少 L2 时表现为待构建的历史范围，不被误报为 explicit_gap。

### 阶段 B：直接 L1 与容量回退

为父级构建增加直接阅读一级范围正文的路径；仅预算/明确上下文超限才构建 L2 并 rollup；保存模型调用与来源依赖。

验收：小范围走 direct；人为降低容量后才走 rollup；未建 L2 不阻塞 direct。

### 阶段 C：parallel 历史初始化

任务前置流程索引全部已确认的历史双语，并将节点与覆盖绑定到任务。plan_next/reference_report 可检查近章全文、邻近 L2、远距 L1 和未覆盖项。

验收：185 章历史不会全部作为全文；远距有 L1 覆盖、近距仍有完整双语，且没有通过伪造缺口绕过预算。

### 阶段 D：cross_edition 与懒 L2

源版 L1 不依赖译本关联；按需请求只建立目标子块 L2；索引修订能进入后续上下文而不改写旧请求。

验收：关联为空仍有日文历史导航；请求指定远距细节时只构建对应 L2。

### 阶段 E：增量窗口

把新提交、历史参考和检查点接到统一覆盖选择器；验证封口、rollup、预算触发和抽取失败回退。

验收：跨越至少一个 L2 和一个 L1 边界，覆盖无重复、无遗漏，旧版本仍可追溯。

### 阶段 F：真实样本

1. 植物怪物娘日记：185 章已对齐历史与 257 章续译窗口。
2. 転生したら剣でした：检查现有连续翻译不回归。
3. 蜘蛛ですが、なにか？：检查版本重排、改写、双线叙事和大量技能实体的 cross_edition 路径。

记录模型请求数、输入/输出 token、构建方式、覆盖表、懒 L2 数、索引修订、实际 prompt、阻断原因和已提交章节数。

## 9. 测试与验收

离线回归至少覆盖：

- direct L1 成功；预算超限后触发 L2 rollup。
- L2 未建时 direct L1 不被 missing_child 阻塞。
- 格式、引用、网络错误不会误触发容量回退。
- parallel_pairs 能参与历史索引，未来参考和目标译文不会泄漏。
- 节点层级与上下文 representation 一致。
- 未索引历史不能被伪装为 explicit_gap。
- 懒构建只物化所请求的 L2。
- 新索引版本不修改旧 prompt。
- 跨层级窗口没有重复/遗漏覆盖；恢复不重复已成功请求。

真实翻译首章之前，plan_next 必须展示索引修订、完整双语近章、邻近 L2、远距 L1、待建/未覆盖范围和预算。翻译后通过 export(include_io=True) 能追溯实际上下文、索引版本、依赖和懒 L2 请求。

本规划不包括自动构建权威知识图谱、自动解决叙事诡计、将模型摘要确认为事实、无限重试、删除历史绕过预算，或不校验身份地跨任务复用索引。

## 11. 本轮实现与验证

本轮已完成：

- 历史 hierarchy 先直接尝试 L1；只有 `context_limit` 类本地/远端错误才进入 L2 rollup。
- `SequenceEngine` 在历史准备、检查点和连续运行中同时维护冻结 hierarchy 与提交后的 `sequence-node` 增量索引。
- 上下文选择器合并两类节点，最近完整双语、邻近 L2、远距 L1 采用非重叠 coverage；未物化节点回退为完整正文。
- 历史近距 L2 随当前目标移动；增量父范围优先以完整双语直接抽取 L1，只有明确容量超限才 rollup 已覆盖的 L2。
- 旧提交退出完整对话回放后，其增量 L2 和临时父级 L1 仍进入导航与 workset；节点版本、依赖和 `index_revision` 保留。
- `plan_next`、`prepare_history`、`ensure_details` 和操作手册说明了待物化状态与显式费用边界。

离线验证：`tests/translation/test_sequence_hierarchy.py` 14 项通过；加上 `tests/translation/test_library_api.py` 与 `tests/translation/test_reference_workflows.py`，定向回归共 50 项通过。完整回归为 137 项通过、7 项失败（72 warnings）；失败集中于 `tests/translation/test_syosetu.py` 的下载、缓存、配置和并发预取用例，不涉及本轮层次索引路径，根因仍待单独定位。`python -m compileall -q src tests` 与 `git -c core.whitespace=cr-at-eol diff --check` 通过。
