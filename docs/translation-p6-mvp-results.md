# P6 最小实现与多窗口开发验证

日期：2026-10-17。

本轮交付有界抽取恢复、三个模型角色共用的只读查证工具、对齐组内的数字信号及其审校/裁决连接。工程路径可运行，不能据此宣布 P6 翻译质量验收通过。实验中已发现模型漏检、错误确认以及没有主动使用工具的情况。

## 实现范围

- `translation/mvp/recovery.py`：每节点初次加两次重试，格式转录、重抽、传输失败共享上限；原响应先持久化，未知远端结果保留预算。格式转录须与已有记录 ID、字段、值严格相等；`length` 才提高输出预留。完整响应中的坏记录隔离为 `partial`，耗尽后 `summary_only` 或 `missing`。显式 `reparse()` 只迁移已有原响应，不重置次数、不调用模型。
- `scripts/p6_mvp_support.py`、`run_p6_mvp_extraction.py`：接回已有平面抽取协议，复用方括号引文、引用列表、末尾粘连等本地恢复。同父子节点串行，摘要或明确缺口传给后继；父节点可并发。整合只命名空间化选用版本的事件 ID，不合并不同生成尝试。
- `translation/mvp/evidence.py`：`search_evidence`、`read_evidence`、`read_index`、`lookup_dictionary`。只查允许的历史来源，不暴露目标参考译文或未来正文；返回原段、稳定 E 标签、来源版本、覆盖缺口。中文配对明确标为章节级。读取索引仅限冻结上下文已登记的节点，不触发付费构建。
- `ReviewSession` 可注入同一 broker，使翻译、审校和裁决共用 6 个不同动作、约 32k 返回 token 的预算，每个角色最多两轮。相同读取跨角色缓存，修订继承证据依赖。可选的 `request_retries=2` 为传输错误提供可跨重启计数的显式重试，默认旧路径仍为 0；HTTP provider 的隐藏重试必须关闭。
- `translation/mvp/dictionary.py`：只读 SQLite / JSON / JSONL，保留数据版本与候选状态；词典不替作品判定实体、数量或固定译名。当前文件由先前词典可用性验证提供，运行时不联网下载。
- `run_checks(profile='p6-mvp')`：在 S/T 对齐组内提取数字位置、精确数值、单位、附近语境与歧义标记。`30歳/三十岁`、十进制数、常见汉字数词可归一；`精一杯`不拆数字；歧义的“一点/一个/十分”保留诊断；多数量同组要求核对对象归属。没有构建通用数量语义解析器。
- `review_translation(checks_id=...)` 与 `model_adjudicate()`：每个正式信号都需处置，引用须落在对应对齐组，确认错译须关联有效 finding。等价或误报可 dismissed，证据不足保持 unresolved。复用现有 acceptance 的 `signal_decisions`，不自动发布或提升知识权威。

## 验证方法与边界

选取 701、1200 回归窗口，以及 610、616、688 三个新增开发窗口，避开 P8 保留来源。首次生成前冻结原文 hash、前文资料、目标译文隐藏策略和基于原文的判定点。B/D 的共同基础是已有一级摘要、允许的二级摘要和邻近三章双语全文；D 额外携带相邻已完成子节点的候选记录、工具协议和数字闭环。1200 的 D 另抽取 1190—1199，绝不使用覆盖目标章的 1191—1200 双语节点。

本次是整个方案的比较，不能单独归因于知识、工具或数字规则。共同基础重新组织为当前实验格式，不是对旧 P5 请求的逐字重放。

运行中修复了适配器遗漏的引文规范化、传输恢复、缺失的纯计数字段及裁决 ID 协议。原始输出和失败尝试均保留，额外消耗计入成本；**这些窗口因此是开发与回归验证，不是未经调参的独立盲测**。目标中文参考只在模型流程结束后用于人工对照，不进入任何模型请求。不同模型、独立保留集及全书质量验收仍未开展。

## 已确认的问题

1. 初版适配器只用了较早的字段规范化，遗漏已实现的 `[J…]` 解包与引用列表恢复。571、631 的原响应因此被误判，花费了 4 次新重抽请求。补齐后对相同原响应离线重解析，两个节点均可得到 `partial`；原失败结果与重试计数没有删除。631 的原始响应本可直接在本地恢复；571 的原始输出仍确实缺 END，不能假称原协议完整。最终从已有后续完整响应选用，没有为离线迁移追加请求。
2. 审校有时在首个记录前输出解释文字，仍按协议不完整阻断；没有把其 SUMMARY 当作质量通过。MVP 仅能依据实际 FINDING 数量补 `zero_findings`，不推断 `reviewed_all` 或语义覆盖声明。
3. 裁决有时漏 `finding/signal` 关联字段。改为给出每条完整 ID 模板；只有记录头精确等于已给定 ID 才可本地回填，`d1` 不会凭顺序猜成 `f1`。中文封闭枚举可记录别名恢复；未知值仍阻断。
4. 模型在已有完整原文时仍会错判：701 将实际『だな』说成「だな」，审校和裁决共同确认错误说话人解释。补丁主要涉及引号，不能仅凭此认定最终中文产生严重角色误译，但这已经证明“引用能定位”不等于“裁决正确”。
5. 616 的 D 初稿新增了施受颠倒，修订正确恢复为“想必是你让之前的我吃过大苦头吧”；然而“通常……告诉之前的自己”这一新增时间指向仍漏检，且该版本能达到现有程序的 `eligible_for_acceptance`。本实验从未调用正式接受/发布接口。
6. 数字规则暴露大量等价计数方式：`匹/只`、`一人/一个`、`30分/半小时`等需要模型判定。它们是待核信号，不应计为真实错译，也不能把全部 dismissed 解释成规则高精度。
7. 未经额外要求的 B/D 运行中，模型没有主动查询工具。独立的强制查证探针验证了三个角色的工具调用，但不证明模型会自行发现查证需求。

## 工具探针

探针与 B/D 质量对照分开记账，共 9 次请求、4 个不同工具动作。翻译角色搜索 `ミゲール`，再读取该章双语正文，得到第 239 章历史译法“米格鲁”，并正确声明这是历史用法而非已审规范。此前较近历史存在其他译名，说明只取最早命中不足以决定当前译名；范围、时序和译法冲突仍需要使用者判断。

审校角色实际查询 `精一杯`，所配小词典没有命中；模型保留不确定，没有凭词典空结果认定数量。裁决角色查询 `十分`，发现“足够/充分”义项，指出不能脱离句子一律视为 10。词典覆盖有限，当前固定词保护与语义审校仍不可替代。

## 运行与查看

```powershell
python scripts/run_p6_mvp.py prepare
python scripts/run_p6_mvp.py run --parallel 3
python scripts/run_p6_mvp.py run --windows 610 1200 --arms D --parallel 2
python scripts/run_p6_mvp_extraction.py --starts 571 631 --replay-first
python scripts/run_p6_mvp_extraction.py --starts 571 631 --reparse
python scripts/run_p6_mvp.py probe
python scripts/run_p6_mvp.py evaluate
```

输出根目录：`artifacts/translation/tenken-cache-clean/verification/p6-mvp-20261017/`。

- `章号/frozen.json`：冻结原文、历史资料、标签和配置，不含目标中文正文。
- `章号/B或D/translation.prompt.md` 与 `translation.messages.json`：实际翻译的完整输入，包括发生工具续接时的完整会话。
- `draft.zh.txt`、`final.zh.txt`：初稿与流程完成时的最后译文，均不是自动接受的发布稿。
- `http/*.request.json`、`*.response.json`：每次物理请求和返回；不保存认证头。
- `io/*/prompt.md`、`output.txt`、`generation.json`：所有角色的完整消息、文本、模型与用量；`result.json`、SQLite ledger 记录阶段、阻断与预算。
- `extraction-recovery/`、`1200/D/extraction/`：抽取原响应、失败版本、离线迁移和选用版本。
- `tools-probe/`：额外要求查证的集成探针，不混入自主工具使用率。

## 多窗口最终结果

五个窗口的十份译文初稿均已生成；其中 5/10 个 B/D 流程完整走到末端，另外 5 个因审校或裁决协议不完整而停止。这里的“完成”只表示工作流结束，不代表译文被接受。所有版本均未调用正式接受或发布接口。

| 窗口 | B 流程 | D 流程 | 人工对照要点 |
| --- | --- | --- | --- |
| 610 | 阻断：审校记录前有额外文本 | 完成 | 两稿都保留幼年罗密欧回到八年前并成长为席拉的时间线区分。B 初稿添加了原文没有的标题；D 没有。D 审校对“投与/服用”的意见被裁决驳回，不能算确认修复。 |
| 616 | 阻断：裁决记录不完整 | 完成 | D 初稿把施受关系译反，审校发现，裁决和修订恢复为“想必是你让之前的我吃过大苦头吧”。但它仍在另一句新增“告诉之前的自己”的时间指向，未被发现；该版仍达到程序上的可接受状态。B/D 的六条数字信号均作为等价表达消解。 |
| 688 | 阻断：裁决记录不完整 | 完成 | D 把指向西比拉的“姐姐您”结合上下文处理为“芙兰姐姐”；仍漏掉“我指示芙兰让路”中的叙述者主语。B 审校/裁决把乌鲁希的“（オン！/オフ！）”误判为开关指令，协议阻断了错误修订。 |
| 701 | 完成 | 阻断：审校记录前有额外文本 | 两稿均通过修订纠正“打赢米格尔的对手”方向。D 审校错误声称原文为「だな」，实际是『だな』；后续据此改标点，理由不成立。仅此尚不足以断言最终发生了严重说话人误译。 |
| 1200 | 完成 | 阻断：审校结束标记、覆盖声明和数字信号处置不完整 | 两稿都保留旁白离开、芙兰睡着、村民尚不知道东征公部下身份，以及等级 20 与 RPG 经验值 99999 的区别。D 审校提出魔兽名称需要查证，但流程未完成，不能视为已修正。 |

本组结果没有显示 D 在所有窗口稳定优于 B。它在 616 发现并修复了明显施受颠倒，在 688 解决了一个对话对象歧义；同时漏掉时间关系增写和叙述者主语，且自身审校也出现了错误引文判断。数字检查在这些窗口主要提出等价数量写法，未发现可确认的数字错译。因此本轮证明的是工程闭环可运行、问题可定位，不是 P6 质量验收通过。

全量验证：`python -m pytest tests/translation -q`，**328 passed**。另有 10 条来自现有爬虫依赖的 `pkg_resources` 弃用警告。

限制：传输错误按显式上限重试，但目前没有解析或遵循服务端 `Retry-After` 提示；词典数据覆盖有限；数字规则仅是对齐组内候选信号，复杂量词、单位和语义仍需模型/人工判断。不能把流程完成、格式成功或程序可接受状态直接当成译文质量通过。
