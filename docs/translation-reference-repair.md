主要问题已经定位并修复：Linovelib 返回的 HTML 正文顺序与浏览器阅读顺序不同，原爬虫没有执行阅读脚本中的段落还原规则。另外发现了附加番外、重复正文、跨章收录后记三类结构差异。它们均已在独立分支中处理，未修改原始 EPUB、原始缓存或已有 P3 实验。

## 1. 根因不是译者随机调整叙事顺序

本地 1572 个正文分页都声明使用 `/scripts/chapterlog.js?v1009c.8`。取得该版站点脚本后，发现它按 `ReadParams.chapterid` 还原段落；后续还会注入由 CSS 隐藏的重复节点。这些隐藏节点不是服务端原始段落，离线解析器无需生成。

实际的顺序规则为：

1. 每一个 HTTP 分页独立处理，不是把整章拼接后统一重排。
2. 选择正文容器中 HTML 内容非空的直接子 `<p>`；其他 DOM 节点保留原来的槽位。
3. 固定前 20 个参与段落。
4. 以章节 ID 生成尾部位置置换，再按逆向分配关系还原阅读顺序。

```text
seed = chapter_id * 126 + 232
tail = [20, 21, ..., paragraph_count - 1]
for i from len(tail)-1 down to 1:
    seed = (seed * 9302 + 49397) % 233280
    j = floor(seed * (i+1) / 233280)
    swap(tail[i], tail[j])
permutation = fixed_prefix + tail
restored[permutation[original_index]] = html_order[original_index]
```

爬虫原来按 HTML 顺序提取 `<p>`，因此把服务器发送的置换顺序写入了 EPUB。前 20 段往往正常，后续才大幅错位，也解释了为什么早先检查的短前缀示例仍然可用。

零宽字符既不是本规则的种子，也不是可靠的乱序判据。本轮没有按零宽字符决定是否修复，也没有批量删掉它们。

代码：

- `translation/corpus/linovelib.py`：共享字符表、元数据校验、已知协议的确定性还原。
- `epub/engine/linovelib.py`：每个分页先还原，再与后续分页拼接。
- `translation/corpus/reference_audit.py`：检查原缓存、分页链及 EPUB，生成独立修复语料。

协议仅覆盖此次验证的 PC 模板。未知脚本版本、身份冲突或嵌套段落会报错，不会猜测排序。如果站点在相同版本标记下更换脚本，仍需重新取得并比对脚本内容；仅检查版本字符串无法保证未来规则永远不变。

## 3. 排序修复之外的结构差异

仅检查章号和长度仍不充分。排序还原后，全量扫描与定点检查发现以下问题：

| 章节 | 实际结构 | 处理 |
| --- | --- | --- |
| 61 | 正文后附“番外篇1 芙兰和松饼” | 78 段标为 `unpaired_appendix`，不归入当前正文对齐 |
| 226 | 正文后附“番外篇3 芙兰和大扫除” | 98 段标为 `unpaired_appendix` |
| 697 | 第二次出现本章标题，其后重复同一份正文 | 66 段标为 `duplicate_content`；核验 64 个有效正文段逐段一致 |
| 720 | 第二次出现本章标题，其后重复同一份正文 | 88 段标为 `duplicate_content`；核验 87 个有效正文段逐段一致 |
| 1036 | 正文后集中收录第 1035、1036 章后记 | 17 段关联第 1035 章，44 段关联第 1036 章，均标为 `afterword` |

重复核验仅忽略空白、零宽字符；没有用语义相似度删除“看起来差不多”的段落。被分区的 391 段没有删除，段落顺序和原文字均保留，只改变分类与正文视图。

上述补丁绑定排序修复后的语料指纹、章节版本、连续段落 ID、起始原文锚点及审查证据。重复区间还要验证保留段与重复段的规范化序列完全相同。结构审查由 Codex 完成，不是独立人工语义盲评。

这五章原来的中／日正文长度比分别为 1.554、1.659、1.581、1.436、1.570；分区后为 0.782、0.704、0.787、0.715、0.725。原先阈值 `[0.3, 1.5]` 下的四个异常已消失，但第 720 章说明：长度不异常仍可能存在整章重复，不能把长度比当成质量结论。

第 1036 章后记还有数值冲突：日文 `HP 1092→1238 / MP 1008→1166`，译文为 `1092→1138 / 1008→1066`。它被标记为 `known_numeric_conflict` 并原样保留。可能涉及译文问题或原文修订差异，需要来源核对；不能把这些数值直接冻结为知识库事实。

本轮重复扫描范围是至少 8 段、500 字的连续精确重复，以及显式番外标题。没有声称穷尽短重复、近义重复、所有译注或所有版本差异。

## 4. 章级对应与段落对应必须分开

原有 1320 组章序键候选仍然成立为候选；本轮没有发现整体章号平移导致的大范围错配。37 个仅原文条目均为后续闲章：第二组 15 篇、第三组 17 篇、第四组 5 篇，不能继续把它们当作中间随机丢章的证据。

但章级身份不等于整章每一段都能一对一对应：

- 第 3 章中，日文两个相邻自然段在译文中合成一段，属于正常多对一候选。
- 番外附录应登记为译文单侧区间，不能强行匹配到相邻正文。
- 后记应与后记对应；收录在第 1036 章的内容，来源可以属于第 1035 章。
- 现有日文语料中，524 个条目有非空后记、54 个有非空前言；不是只有发现的这一章需要区分正文与作者附记。

P2 的整章候选 span 表示章节身份范围，仍包括保留的其他段落类型，**不能作为已批准的正文段落映射**。P4 应先按 `kind` 和 section 证据选择区间，再建立局部单调、多对多映射。

## 6. P4 的进入条件与使用方式

当前可以基于修复语料开始小样本段落对齐；不能跳到全书知识抽取。建议依次完成：

1. **重新登记章级身份和可用示例。** 先复核已有开发样本的首／中／尾内容，审查记录绑定新版本；正文与作者附记分别处理。
2. **按区间建立段落映射。** 在正文内支持 1:1、1:n、n:1、局部缺失与弃权；附录、重复内容、后记不混入正文单调路径。不能以“最终都排完了”替代语义覆盖验证。
3. **先处理不一致再抽取。** 数字、否定、主客体、姓名／普通词混淆由日文原文与定位证据裁决；参考译文用于确定优先译名和风格，不能单独确立事实。保留“原文修订／译文错误／无法判断”的不同状态。
4. **为跨章区间登记真实依赖。** 第 1036 章中的第 1035 章后记不能只标成依赖 1036；隐藏 1035 时，相关后记、派生知识和摘要也必须一并隐藏或重算。未解决附录先不进入平行知识抽取。
5. **重新准备实验，保持旧结果可追溯。** 新语料、新审查、新示例产生新实验身份；不用修复后的参考覆盖旧 sealed 文件。正文知识库与可选作者附记知识应记录不同证据角色。

本轮人工性质的语义检查覆盖 3、61、226、697、720、775、1035、1036、1233 章，其中只有 3、775、1233 属于既定开发集，其余均不在既定验证／盲测保留集。全量文本完整性验证和规则扫描不是对保留集逐章人工语义审查。

无需让 LLM 重新“猜”现有译文的阅读顺序。可靠流程应当是：**先还原网站可验证的表示层，再分离文本区间，最后让语义对齐与知识抽取处理真正的翻译差异。**
