# P4.2：两级懒加载叙事索引

日期：2026-10-16。承接 [双语摘要与翻译元信息](translation-bilingual-block-metadata-design.md)。本轮先试验固定 100／10 章结构，使用用户指定的 1,048,576 tokens 上下文预算；实际 API 容量与摘要质量分别验证。模型标称容量不是本地实测结果。

最新状态：平面协议与范围审查已完成 [第1200章最低工程验收](translation-p4.2-1200-acceptance.md)，12个一级、2个近二级及近3章双语产生真实草稿。原文审阅仍有局部语义问题，候选摘要未获语义确认；后续进入 [P5审校与接受设计](translation-p5-design.md)。本文首轮失败记录保留其历史范围。

## 1. 本轮范围

一级节点按阅读顺序每 100 个叙事条目分组，二级每 10 个分组。番外计入实际阅读位置，章号不作为位置。先固定位置再过滤实验保留章，避免隐藏一章导致全部边界漂移。标题目录构建不调用模型，也不把标题候选视为已读剧情。

翻译时需要全部可见一级总览，邻近 `N_child=2` 个二级节点的概括，以及最近 `N_chapter=3` 章完整双语。可显式请求其他二级节点。只有被选择的二级节点才生成语义摘要；廉价子目录可以预先列出。当前一级块只读取目标之前的精确可见前缀。

一级和二级均读取各自完整、获准使用的日中正文，独立生成本节点 `overview` 和翻译元信息；`details=[]`，不在一级请求中预付十个子摘要。二级概括在上下文中承担详细信息层。近章完全覆盖某二级节点时可省略其概括，并登记替代理由。

首次获得全部一级概括仍需读完整前文。两级懒加载主要节省细摘要生成、细粒度证据抽取及后续翻译上下文；不会把第一次全历史阅读变成常数输入成本。

## 2. 预算与摘要约束

| 项目 | 新多级模块默认值 |
| --- | ---: |
| 模型上下文规划值 | 1,048,576 tokens |
| 每次摘要输出预留 | 16,000 tokens，包含提供方计入的思考输出 |
| 摘要安全余量 | 8,192 tokens |
| 每次摘要输入上限 | 1,024,384 tokens |
| 一级／二级概括上限 | 各 2500 字，不设下限 |
| 每节点重要实体上限 | 20 |
| 每节点固定表达上限 | 5 |
| 单条引文上限 | 160 字符 |
| 翻译上下文输出／安全预留 | 8192／2048 tokens，可显式调整 |

字数按 `len(text.strip())` 计算，含标点与内部空白。元信息和引文另计输出预算。20 个实体是本轮抑制复杂 JSON 和噪声的工程上限，不代表能覆盖 100 章全部人物、专名；缺失与覆盖问题需要另行评估。

新多级模块显式设置 2500 字，旧 P4.1 配置及历史请求保持 1000 字，以保留原试验可复现性。没有修改过去的 prompt、结果和预算账本。

初次 100 章请求已被 API 接收，实测输入 547,068 tokens，但模型声称没有资料并返回无效 JSON。请求副本核实包含完整正文，不能把此失败归因为容量不足。当前 prompt 新版本在完整正文之后再次给出任务规则与 JSON 格式；这个修正用于验证长输入后的任务遵循，不代表已证明最初错误的具体原因。

完整请求计数包含日文、中文、逐段引用定位、标题、配对说明和系统消息。当前使用已有公开 tokenizer 加聊天模板余量估算，API `usage` 是另一组实测值，不能混用。先保持 100 章；仅在本地完整请求超限或 API 明确拒绝容量时再规划调整。不静默截断正文，不因沿用旧 128K 限制而自动缩块。

后续增加按上下文预算动态确定一级大小的规划器：以固定阅读位置和可复用边界为约束，读取完整双语实际计数，预留输出和安全空间，生成版本化分块方案。本轮尚不实现自动拆块、预算驱动合块或自动付费重试。

## 3. 元信息的懒更新

一级元信息快照汇集该一级概括及已经生成的子摘要记录，包含实体日文形式、作品相关描述、已有中文用法、双语逐字引文及来源层级。子节点增加时创建新的不可变父元信息快照；原一级 `overview` 不被改写。

父快照记录 `detailed_chapter_ids`、`unbuilt_child_ids`、精确输入摘要 ID、候选条目与冲突。全文快照只汇集实际已建节点，不把未建二级视为“没有事件”。当前合并是确定性的证据并集，不进行实体同名归一、身份推断、矛盾裁决或自动确认。候选状态为 observed、语义待审查；对象即便同名也保留独立证据。

元信息工作集按目标原文、完整近章与显式重点形式选择。人物描述随候选项注入。这个简单选择器仍可能漏掉异名、隐式回忆和未直呼姓名的角色；后续语义检索与人工审查不能被本轮词面匹配替代。

## 4. Python API 与边界

| API | 作用 |
| --- | --- |
| `build_multilevel_index(view, MultiLevelConfig(100, 10))` | 保存廉价一级目录，无模型调用 |
| `list_children(view, index_id, parent_id)` | 返回子目录，无生成副作用 |
| `select_nodes(..., n_child=2, requested_child_ids=...)` | 全部一级＋邻近及显式请求二级 |
| `plan_multilevel_summaries(..., target_node_ids=None, ...)` | 固定完整输入、可见性、身份、token 与请求预算 |
| `run_multilevel_summary_plan(...)` | 有界显式生成，严格校验，保存原始输出、失败和预留 |
| `read_node_summary(view, summary_id, node)` | 重新验证完整双语依赖和逐字证据 |
| `rollup_multilevel_metadata(..., persist=True)` | 生成不可变父／全文元信息快照，无模型调用 |
| `compile_multilevel_context(...)` | 检查覆盖，编译完整 prompt 和实际注入清单，无模型调用 |
| `run_translation(...)` | 重建验证多级 bundle，调用已有翻译 runner |

代码入口为 `translation/narrative/multilevel.py` 与 `translation/context/multilevel.py`。当前新增能力提供 Python API 和独立试验脚本，通用 `narrative-*` CLI 尚未增加两级索引参数。

计划标明 `pending/cached/blocked_context`。任何必需节点超预算时默认不执行局部；诊断必须显式选择节点或使用 `allow_partial`。`complete` 只表示本计划任务成功，局部试验不能由此推导全文覆盖；另列整个上下文要求节点数量。

缺任一必需一级或选定二级，编译返回 `coverage_gap`。任一摘要存在未解决的 `coverage_notes` 同样阻断。不会用检索命中几个块冒充全前情，也不会在编译过程中悄悄构建未付费的节点。

已闭合节点的缓存身份绑定真实双语内容、审查修订、模型、prompt、配置及 tokenizer，不绑定无关的目标截止位置。换目标时仍需在新视图中验证全部依赖；同一闭合范围可以复用，增长前缀必须重新构建。若重新创建了不同审查修订，也会影响缓存身份。

## 5. 开发及试验步骤

| 步骤 | 验收 |
| --- | --- |
| L0：目录与版本 | 100／10 分区、保留缺口不漂移、标题变更失效、查询不生成 |
| L1：生成闭环 | 全量双语、1M 预算、2500 字配置、持久账本、失败保留、恢复零调用 |
| L2：懒细化与元信息 | 仅新增被请求子节点；新父快照保留旧总览、来源和未建范围 |
| L3：上下文及翻译 | 全一级覆盖＋近二级＋完整近章；缺失／超预算阻断；既有 runner 可接收 |
| L4：真实容量试验 | 第 1200 章前文全目录容量规划，有限节点 API 实测及输入／输出导出 |
| 后续 | 动态一级分块、全历史翻译、实体消歧、摘要语义覆盖审查、按需检索与更大样本评测 |

首轮真实试验最初规划完整 100 章一级块、最近一级块及两个近邻二级块。首次 100 章请求失败后保留原始输入输出，新版本继承该次预算预留，只剩最多 3 次请求，因此改为完整 100 章一级块、最近一级块及一个近邻二级块。两版合计仍限 4 次摘要请求、累计输入预留 2M tokens、累计输出预留 64K tokens。最大本地请求所处的 100 章位置包含保留章，不能为凑足实测章数解除隐藏，因此另选无缺口的 100 章节点实测。不生成目标章译文，因为此范围缺少其他一级概括。全部前文一级规划用于容量检查，不等于全部调用授权或已构建。模型错误需先审查，不进行隐式付费修复。

初次产物：`artifacts/translation/tenken-cache-clean/verification/p4.2-multilevel-1200/`，保留初版源码副本。正文尾部重申任务的新版本独立存放在 `p4.2-multilevel-1200-tail-task/`，并在账本导入首次失败记录。运行脚本为同级 `p4_2_run.py`，先 `--mock`，再真实运行；`--prepare-only` 仅规划，`--phase coarse/refine` 可分步执行。账本全局覆盖两个阶段和首次失败；重复已成功请求直接读取缓存。`p4_2_audit.py` 用只读数据库恢复验证已成功阶段，不发送 HTTP。

真实结果与剩余缺陷见 [P4.2 实施记录](translation-p4.2-results.md)；本设计不把 JSON 结构有效、引用能定位或 API 接收长输入等同于剧情概括准确。

本轮 L0–L3 工程和 mock 通过，122 项回归通过；L4 完成真实容量与失败观察。四次真实请求直接通过全部校验为 0，尚未形成真实可用摘要、元信息上卷或第 1200 章全历史翻译。保持实验入口，先修正生成可靠性再扩量。

## 6. 2026-10-16 补充：宽容解析与一次格式修正

上述严格 JSON／证据准入是首轮历史行为。当前多级索引采用 [稳定输出协议与恢复设计](translation-resilient-summary-protocol.md)：先输出平面概括，再输出可选元信息；可读概括和缺失引用分开处理，损坏条目隔离。必要时使用受独立预算约束的一次 LLM 格式转录。真实覆盖缺口、可见性和总预算仍按原规则检查。旧摘要保留原版本读取，新计划使用 v3；完整工具检索仍留待后续实现。
