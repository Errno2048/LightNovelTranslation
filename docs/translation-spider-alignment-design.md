# 蜘蛛案例：web 日文与文库中文的跨版本对齐设计

日期：2026-10-18。

基线提交：`6884698`（P8 连续验证、定向词条与局部证据）。本文是提交后的新增设计，尚未实现跨版本对齐。已完成本地 EPUB 结构盘点和开篇抽样；没有调用模型做全书语义对齐，也没有确认全书具体分歧边界。

## 1. 目标与边界

默认目标仍是翻译 **web 版日文**。文库中文是另一个版本的参考材料，不是每个 web 段落的标准答案。目标是建立可追溯的部分对应，明确哪些片段可作为双语范例、哪些只能提供术语、哪些属于改写或无法判断。完整覆盖所有内容不等于让所有内容都获得对侧匹配。

用户已指出双线叙事、叙事诡计、版本改写和结局分歧。对齐器必须允许重排、拆并和长期无对应；不能把检索失败直接解释为缺译，也不能依据文库情节修正 web 原文。

## 2. 本地盘点结果

独立输出：`artifacts/translation/spider-alignment-preflight/`。`preflight_epubs.py` 是只读盘点脚本，`manifest.json` 保存文件 SHA256、目录和统计，`entries.jsonl` 保存条目定位、标题、字数及短摘录，`toc.txt` 便于检查阅读顺序。未修改输入 EPUB，未导入旧魔剑语料库。

| 输入 | spine 阅读条目 | 当前段落抽取的字符数 | 旧分类器结果 |
| --- | ---: | ---: | --- |
| 日文 web | 600 | 1,514,541 | narrative 331，unclassified 269 |
| 中文文库 1–16 卷 | 458 | 1,828,497 | narrative 115，unclassified 311，cover 16，volume_intro 16 |
| 中文 Ex | 20 | 61,760 | unclassified 18，cover 1，volume_intro 1 |

这里的条目不是统一意义上的“章节”；中文计数包含卷介绍、后记、特典等，字符数也不是纯正文净字数。图片内的文字不在统计中。目录 NCX 还有书名/作者等标签，不能直接把标签总数当章数。

实际发现：

- web 的 `S１ 日常が終わった日` 位于主线第 10 话之后（spine ordinal=10）；中文第 1 卷的 `S1 日常生活终结的一刻` 位于第 1 章之后（ordinal=4）。抽样可见共同的日常上学、网游和教室灾变内容，但叙述有调整；这里只认定为待精查的场景候选。
- web 第 1 话包含世界背景和主人公醒来、确认身体的过程；中文第 1 卷有独立短篇“序”（4 段、101 字），随后是第 1 章。整章边界不能直接一一对应。
- web 标题不仅有数字主线，还出现 S、血、鬼、過去編、最終決戦等系列；中文也有 S/Y/R、血/鬼、幕间、角色姓名等多种标题。旧分类器会漏掉重要叙事。
- 中文 `main:1` 到 `main:5` 各在 13 卷出现，`main:1` 不是全书唯一标识。第 11、12、16 卷在旧规则下没有 narrative 条目，不代表这些卷没有正文。
- 第 3 卷 `8 下层的地龙` 中，粗略规则命中了 57 段列表/升级消息；web `１６６ 母食い` 也有大段此类文本。这是结构诊断，不是最终技能识别结果。
- Ex 的目录包含设定、访谈、插画集、投票、短篇发表时间表。应单独归类，不能顺接第 16 卷形成默认叙事历史。
- 第 15/16 卷人物档案、Ex 部分设定条目没有被当前 p 段落抽取器提取到正文。应检查图片/布局类型，不能直接认定爬取缺页。
- 中文目录可见 `N神`、`不知Q` 等屏蔽文本。用户已说明这是站点自动屏蔽原标题部分字符导致的显示结果，不是版本改写。导入时保留原始字串并记录疑似屏蔽位置；不得全局替换 N/Q。只有日文标题或其他可信原始来源能逐项支持恢复时，才另存规范化候选及其证据，不能覆盖原始文本。

## 3. 当前实现不能直接复用的假设

- `translation/corpus/__init__.py` 的 `ingest()` 扫描两个 out 目录内的全部 EPUB，没有显式作品/版本清单；旧缓存选择还依赖标题。新案例必须显式选文件，并用作品和原生来源身份隔离缓存。
- `translation/alignment/__init__.py:rules()` 依唯一章号建立候选；正文尚未检查。语义窗口只取章首 650 字和章尾 350 字，窗口内采用单调动态规划，无法发现所有中段删改和跨线重排。
- `translation/alignment/paragraphs.py` 的段落匹配可作为局部工具，但当前入口仅面向少量已审核的整章一一对应；不能直接处理跨卷、跨章的场景对应。
- `translation/knowledge/evidence.py:CorpusArchive.canonical()` 仍按 `match_key` 把中文映射到单个日文章节；`translation/narrative/service.py:review_chapter_pair()` 和 `translation/sequence/view.py:FrozenArchive` 也依赖单一 canonical 绑定。
- 因而不能只增加底层 n:m 记录就宣称支持跨版本：上下文读取、知识证据、冻结历史和评估都需要消费范围映射。

## 4. 数据模型：内容身份、对应、用途分开

保留各版本自己的原始阅读顺序，不强行统一章号：

```text
work_id
  edition_id: web-ja / print-zh
    document_id: web-book / volume-01 ... volume-16 / extra-ex
      entry_id: native URL 或 EPUB href
        revision_id + paragraph_id [+ 必要时字符范围]
```

标题里的 `S1`、`血1`、阿拉伯数字只作为标签。段落跨 EPUB 更新时必须检查 revision，不能复用过期偏移。场景是段落范围的派生视图，不改变原文。

对应记录最少包含：

```text
alignment_id
source_spans[] / reference_spans[]
content_relation: equivalent | partial | rewritten | unresolved
order_relation: monotonic | reordered | unknown
coverage: 两侧已核验范围、未覆盖范围
differences[]: 有来源范围支持的增删、事实变化或无法判断
status: candidate | reviewed | rejected
evidence[] / method / model_config / input_hash
allowed_uses[]: parallel_example | terminology | style_reference | evaluation
```

结构上的 1:n/n:m 可以由 spans 推导，不能与语义等价混为一谈。`no_candidate`、`reference_integrity_suspect`、`suspected_edition_only` 等缺口原因另行记录；只有核验后才能确认版本独有。候选分数不是校准后的置信概率。

最小版不需要知识图谱或完整世界时间线。主对应在同一版本内应避免覆盖冲突；另设可重复关联的 `same_event`/`retelling_candidate` 辅助链接，允许同一事件被回忆、重述，不能把这些链接视作可直接互换的双语段落，也不能通过关系传递推定等价。

## 5. 对齐流程

### 5.1 先做输入完整性与结构分类

显式 manifest 导入这 18 个文件，按卷号数值排序。保留未知分类；序章、幕间可能是正文，不能因标题特殊而丢弃。区分正文、系统/状态文本、插图、人物资料、后记、访谈和特典。核查可疑字符、重复段、空条目、缺页提示、续页拼接。可疑区域暂缓准入，但不必阻塞其他合格区域。

### 5.2 使用小范围正文召回，而非整卷摘要决定对应

以段落窗口为基础，优先沿空行、分隔符和明显视角切换分段；起始可试约 800–2,000 个本地估算 tokens，保留一小段重叠并记录归属。长章节切成多个单元，短章可整章保留。尺寸是待校准参数，不是语义边界的保证。

对两侧正文构建跨语言语义向量；在全体候选中召回 top-k（起始如 8），结合目录标签、稀有名词、事件动作、地点等补充召回。日中标题只提供弱线索；叙事线标签未知时不设硬过滤。先验证所配置 embedding 模型的日中召回能力，再决定替换或增加摘要召回，不预设现有端点必然适用。

可先建立全库轻量候选索引，再只对实验窗口作 LLM 核验；无需先花费全书 LLM 摘要/图谱抽取的成本。语义摘要是补充特征，原始证据始终保留。

### 5.3 叙事正文和技能清单分轨

正文相似度与清单相似度分别计算。高频 HP/MP/SP、系统提示、常见技能名不能主导匹配；清单比较以稀有组合、主体、等级变化和附近动作作为辅助。不能仅凭相同技能列表接受一组对应，也不能把真实的跨版本等级变化作为格式错误“修正”。

纯状态页可单独匹配，但保持独立类型。技能定义、译名用法与某次状态快照分别保存；重复列出同一技能不会创建新实体。数字/等级和技能名词面分开解析，保留完整原始串。

### 5.4 全局找候选锚点，局部才用顺序约束

双向检索互相命中、候选间隔较明显、且内容检查支持时，形成高可信锚点。全局允许交叉边；沿连续锚点划分可局部单调的片段，再复用/扩展现有段落 DP 处理拆并和缺口。

当锚点交叉或相似度持续不足时，暂停该局部顺序假设，重新搜索其他场景或标 unresolved。首版不构建复杂全书图优化器，也不通过硬指定卷号/时间线强制匹配。全局跨线重排不能靠放宽 gap penalty 解决。

长缺口应允许持续保留；可以在局部 DP 中采用缺口开启/延续的不同代价，但这只能改善路径，不能证明内容被删改。特别是末卷，宁可保留无对应，也不能因为双方都有“最终战”便接受匹配。

### 5.5 LLM 只核验候选及其原始邻文

给定一组日文范围、若干中文候选和必要邻文，要求列出：同一事件的证据、两侧实际覆盖范围、主体/动作/结果差异，以及无法判断的部分。不能用模型对作品的记忆补证据；引用必须落到输入段落并经程序校验。

同一场景不代表同一事实。对 partial/rewritten，不允许把整章中文当 parallel few-shot；仅有再次核验的等价子范围可以准入。中段缺页要检查双向覆盖，不能只检查中文段落是否全部被映射。

## 6. 双线叙事与揭示顺序的隔离

保存三个独立概念：版本内的阅读位置、故事时间（可未知）、当时文本明确使用的视角/称呼。标题标签是可见线索，不自动等于最终角色身份；时间推测不参与硬排序。最小版无需提前解开叙事诡计。

离线对齐器可以检索整本书来定位，但生成侧只能读取经过可见性裁剪的证据投影：

- 用 web 的目标阅读进度控制可见性，不能用文库卷号或中文 ordinal 推算已知事实。
- 一个中文片段即使含有与当前 web 场景对应的部分，也可能夹入更晚披露；必须裁到合格范围。不能只看该中文片段的最早对应点。
- 剧情、身份、关系、时间等事实要求有当前允许的 web 范围支持；中文提前揭露且无法安全剥离时，不注入正文，也不借摘要、检索标签、理由字段泄露。
- 术语译名和隐藏身份别名不同。翻译偏好必须有明确用法证据；身份合并需要单独的披露条件，未知时保守不合并。
- web 的回忆文本可以描写更早事件，但知识何时公开仍取决于阅读位置，不取决于事件发生时间。

全库检索与生成输入在存储和接口上隔离；“禁止剧透”的 prompt 提醒不能替代范围过滤。文库事实不并入 web 事实库。当前章节的参考中文在翻译验证时同样必须封存，避免把检索到的答案塞回输入。

## 7. 对外接口与主线接入

建议最小接口：

```python
retrieve_alignment_candidates(source_span, edition_id, top_k)
verify_alignment(source_spans, reference_spans, context_spans)
record_alignment_review(alignment_id, decision, evidence)
get_reference_spans(source_span, purpose, cutoff, reserved_spans)
get_alignment_coverage(edition_id, source_range)
```

`get_reference_spans` 返回中文范围、来源版本、核验状态、差异和用途，不再返回一个貌似完整对应的中文章。可见性和质量门槛由服务端强制实施；找不到合格内容时返回明确的空结果及原因。

翻译、审校、裁决、定向词条和增量摘要统一消费这份受控证据。现有一一对应作品可通过适配器继续使用；跨版本模式不能回退到旧的 match_key canonical。冻结时保存范围映射的版本和所有证据依赖，避免后续修订悄悄改变先前实验输入。

## 8. 小规模验证与推进顺序

1. **数据准入**：显式选作品/版本，保留全部阅读条目和原生定位，分类非正文，核查屏蔽标记与图片页。输出问题清单，不用自动猜字修补。
2. **开篇锚点实验**：web 前 30 个阅读条目对中文第 1 卷正文；手动建立少量场景范围标签，验证主线拆并与 S1 重排。不是把两个范围宣告完全对应。
3. **困难窗口**：加入技能密集窗口、一个中段跨线/回忆窗口、web 末 30 条目对文库第 15–16 卷候选。范围仅用于采样，召回仍可跨卷；最终对应范围由证据决定。
4. **受控故障**：在派生副本中删中间若干段、拆并章节、交换场景、替换等级，确认系统不会把缺页/重排/事实变化误收为等价。原始 EPUB 不改。
5. **接入翻译实验**：小窗口比较无中文参考、仅受控术语、核验段落＋术语三种输入；其他配置和预算尽量相同。盲测保留独立源文忠实度检查，禁止当前参考泄漏。

先标注约 30–50 组候选/困难负例作为开发集，另留独立检查样本。需有人核对双语原文；模型自审仅是辅助，不等于真值。

度量：候选 Recall@k、接受对应的 precision、两侧范围覆盖率、错误强配率、缺口原因判定、各类样本分别表现、未来信息泄漏、请求数与 tokens。特别记录因保守弃权损失的有效参考，防止用全部拒绝换取漂亮 precision。

首轮验收优先级：不强配改写/冲突，不泄露未来信息，随后提高可用覆盖。可以要求小型人工确认的冲突/负例集合中零误接受，但必须同时报告样本量，这不是全书误配率为零的证明。文库中文不能直接作为 web 全书 BLEU/chrF 或事实质量真值，只有核验等价范围才适合参考式评估。

## 9. 本次结论

本案例应采用“版本隔离的场景/段落部分对齐”，并把可用于翻译的双语证据与仅相似的剧情材料区分开。最先要做的是输入准入、范围身份、全局候选召回和用途过滤；不应先把整本文库知识抽入 web 的层级索引，再设法补救错位和提前揭示。

目前已提交 P8 基线；后续已完成全库窗口向量候选召回和 25 对候选的模型复核试点，详见 [试点结果](translation-spider-alignment-pilot-results.md)。当前仍是待人工核验的局部对应线索，没有完成全书语义对齐或蜘蛛翻译验证；文库参考尚未准入翻译上下文。
