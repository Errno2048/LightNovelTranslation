# 独立版本索引与翻译管线接入设计

日期：2026-10-18。状态：D1–D5 已有独立试点实现；蜘蛛样本窄候选池实验已运行，结论见 [试点结果](translation-independent-edition-index-results.md)。D6 已接入原有连续引擎并完成首轮五章窗口实测：四章提交，一章因段落合并与无效映射阻断；增量索引、压缩和恢复已验证，尚未达到窗口全章通过。详见 [连续试点结果](translation-cross-edition-sequence-results.md)。

本设计补充并调整蜘蛛案例的跨版对齐方案：保留已有配对语料路径；跨版本采用双方独立索引、L2 剧情区块关联和 L1 范围实体匹配。精确正文对齐退为需要复用译文或进行参考式评测时的按需能力，不再是开始翻译的前置条件。

如何从已提供的中文文库定位 Web 续译起点，另见[续译起点定位设计](translation-continuation-design.md)。该能力尚未实现；共同事件关联不能直接当作整块覆盖或续译边界。

## 1. 核心决策与边界

三种关系必须独立记录：

| 关系 | 回答的问题 | 可以支持的用途 |
| --- | --- | --- |
| 区块关联 | 两个区块是否描述相关事件或故事阶段？ | 查找参考、定位正文、提示版本差异 |
| 实体对应 | 两侧表记是否指向对应的人物、地点、技能等？ | 有证据的译名选择及用例检索 |
| 精确平行范围 | 这些具体原文和译文是否语义对应？ | 双语示例、复用译文、参考式评测 |

相关区块不自动生成实体对应；实体对应不证明区块等价；区块对应不能使正文直接成为译文。这三类结果都允许无对应、不确定和多候选。

Web 日文及其可见历史是翻译的剧情依据。文库中文提供语言用法和查证线索；文库的新增事件、技能效果、等级、人物关系和知情状态不因名称匹配而成为 Web 事实。新生成的中文绑定其实际 Web 原文，仍可进入已有连续翻译、提交和增量索引流程。

当前窗口向量试点可保留为候选检索工具，但没有建立全书语义对应。现有章级配对审查中的 `accepted` 也只代表规定范围的覆盖检查；代码仍记录 `semantic_status=unreviewed`、`whole_chapter_few_shot=False`，不能将其解释为逐段语义金标准。

## 2. 任务识别：独立于现有策略和质量模式

新增 `reference_mode=parallel|cross_edition|source_only|auto`。不复用 `SequenceSpec.strategy` 的 R/U/H，不复用 `mode` 的 working/accepted_only，也不改变旧 `mapping_profile` 的含义。

- `parallel`：确认是同一底本的译文，已有章级映射继续使用；保留缺章、拆章、合章状态。局部缺失不会把全书变成跨版本任务。
- `cross_edition`：明确不同底本，或存在显著重排、改写；双方独立建索引，不要求章节一一对应。
- `source_only`：没有可用译文；依然可以建立源文索引和连续翻译。
- `auto`：输出可解释的模式建议和范围清单，然后冻结实际模式；不允许运行中凭某次相似度静默切换。

识别顺序为：用户/manifest 的版本声明 → 已有映射的出处与覆盖 → 开篇、中段、末段及异常处的正文抽样。标题编号、长度比例、顺序一致性只作诊断信号，不构成确认依据。明确为 Web 对文库的蜘蛛样本直接采用 cross_edition。

未确定时用 source_only 或 cross_edition 的保守参考能力，不假定 parallel。全书默认模式与局部能力分开：cross_edition 内经核验的局部平行范围可以单独启用双语示例；parallel 内发现改写的范围暂停该项能力。MVP 用范围覆盖表表达，不引入自动全书分段分类器。

## 3. 独立建树与懒构建

```text
Web 原文 ─→ Web L2 摘要/事件/实体 ─→ Web L1 导航/实体目录
                     │                         │
                  L2 多对多关联             实体对应表
                     │                         │
文库中文 ─→ 文库 L2 摘要/事件/实体 ─→ 文库 L1 导航/实体目录

Web 正文/历史 + 可用译名 + 用途明确的参考材料
                     ↓
             翻译 → 审校 → 裁决 → 提交
                     ↓
          Web 原文绑定的新译文及增量索引
```

双方节点边界各自规划，不要求块数相同或 L1 一一对应。文库已有卷结构时将卷设为分组边界；大卷可以包含多个预算节点，不强行将一卷正文装进一次调用。Web 使用标题段落和内容预算分块，保留原始阅读顺序；叙事线作为标签，不按最终人物身份重新排列正文。

复用现有容量规划思想：预估 tokens 乘可配置膨胀系数（初值 1.05），另预留 system、历史上下文和输出预算；L2 保留最小内容量，L1 放不下时由 L2 汇总。1.05 只是先验余量，服务端仍报超限时缩小实际请求并记录校准信息。不能为了让 L1 放得下而持续将 L2 缩到失去概括意义。

构建顺序：

1. 全部文档先生成无需 LLM 的目录骨架，标注卷、标题、顺序、正文范围、预算及 `not_built`。
2. 优先复用已有的、具有明确版本来源的 L1 概括。需要全局导航时可直接从单版本 L1 正文生成概括；超预算则使用 L2 汇总。标题目录不能伪装成正文摘要。
3. 为当前 Web 位置及候选文库范围构建 L2。若已有覆盖全书的 L1 概括，可用其筛候选；尚未覆盖时结合目录和现有正文检索定位，并明确搜索范围不完整。
4. 同一 L1 下按阅读顺序提取 L2，携带本版本前驱摘要；不同 L1 可以并发。后者依赖冻结的历史导航，不读取并发任务尚未稳定的结果。
5. L2 完成后更新父节点目录、概要和覆盖清单。父摘要由正文直接生成还是由子摘要汇总，分别记录；后续汇总不能覆盖丢失的原始证据。

单侧提取不注入另一版本正文或实体解释，避免两侧摘要提前被“校正”为一致。源文摘要可以用中文表达，但名称保留原始日文表记和版本内实体 ID，不自行创造既有中文译名。

## 4. L2 输出：既供导航，也保留匹配所需差异

每个 L2 输出以下内容，采用现有可容错记录协议，保存原始响应、解析结果、重试及完整性状态：

| 字段 | 内容 |
| --- | --- |
| `overview` | 连贯剧情概括；2500 字作为软目标，超长可存储，注入时另裁预算 |
| `events[]` | 主体、行动、对象、起因、结果及原文依据；缺失项显式未知 |
| `threads[]` | 文本明确的视角/线索标签，不能擅自解开匿名叙述者身份 |
| `temporal_claims[]` | 回忆、先后、同时、时间跨度；分别记录叙述位置与故事时间声明 |
| `knowledge_claims[]` | 谁得知什么、谁误以为什么，何处披露；没有依据不补全 |
| `entities[]` | 原始表记、类型、局部角色描述、出现位置、代表用例、局部 ID |
| `coverage` | 输入范围、已处理范围、缺失引用/截断/待补提取状态 |

事件要点用于区分“同一地点中的不同事件”，不能只有主题词列表。回忆和重述保留为不同叙述记录，不强行合成一个时间点。

技能密集段保留原始列表位置；技能名称与某人物在该时刻持有的等级分开。重复名称合并用例，不把每次列表视为新实体；名称相近不证明不同技能属于同一技能族。若单次输出不足，保存已完成记录并按缺失范围补提取，而不是声称已穷尽所有实体。MVP 不另建完整技能本体或复杂关系图。

摘要和结构记录均可缺少精确引文，但必须标记证据状态。这类摘要仍可用于导航；无有效引用的实体映射候选不能直接升级为固定译名。

## 5. L2 匹配：摘要判断，多对多，正文按需核对

先用 L1 概括寻找若干候选父范围，再对其中 L2 摘要做联合匹配。父关联是搜索提示，不能成为硬过滤：无可靠匹配或有冲突时允许扩展到其他卷/父节点。现有窗口 embedding 可以补充召回，后续也可索引摘要，但不作为关联是否成立的最终判据。

匹配 prompt 包含：双方版本说明、L2 摘要及事件要点、标题序列、各自前后相邻 L2 的简短概括、已有锚点及待核对差异。可选实体对应只作为已有候选证据；不能用刚由此匹配推导的实体关系反向证明自身正确。

要求输出：

```text
association_id
source_node_ids[] / reference_node_ids[]
relation: event_overlap | related_context | unrelated | uncertain
matched_event_refs[]
differences[] / unresolved_questions[]
evidence_refs[] / evidence_status
search_scope / candidate_recall_methods / review_status
```

`event_overlap` 表示包含共同事件，不表示整块等价；`related_context` 可能只有背景、人物或同一故事阶段，可用于寻找语言样本，不能解释为同一事件。`no_candidate`、`not_built`、`search_incomplete` 属于检索状态，不等于小说没有对应内容。

章节名序列用于提供局部阶段线索。例如 Web 的 S24/S25/S26 与文库卷内 S1–S5 可共同描述一段迷宫行程，但不能按数字相等匹配；主线穿插和跨卷编号重置使全书单调约束不成立。正文行动、参与者和结果发生冲突时，标题相似不能推翻冲突。

对关键或不确定的事件，回读双方原文局部及邻段。MVP 不逐章配对、不运行全局硬一对一指派。匹配记录仅记录使用过的摘要/正文证据；不把模型解释当成新事实。

## 6. L1 范围实体匹配

用户提出的扩大匹配范围有必要：同一对象可能在不同 L2 被介绍，局部块误配不应把译名永久绑错。但“全局”指选定候选父范围内、实际已抽取的实体，不意味着全书完整实体集。

步骤如下：

1. L2 抽实体时保留描述和用例。各版本在 L1 下汇总，精确重复表记可以聚合出现索引；同名不同对象保留独立候选，别名合并要求证据。
2. 对 Web 某 L1 和若干候选文库 L1 的实体目录联合匹配，纳入这些父范围下未配对 L2 的实体。父范围不足时允许跨父检索，不要求共享 L2 关联。
3. 类型、原始表记、定义性描述、出现的事件及用法用于提出候选；描述要保留版本属性，不能将文库特有职业或关系当成 Web 属性。
4. 输出表记对应、双方实体 ID、双方实际用例、适用范围、差异、歧义和状态。一个日文名称可对应多个中文用法；同一中文名称也可能指多个不同对象。
5. 大目录分批处理，每批携带紧凑目录及已确认对应，最后检查同一实体被冲突指派、别名误合并等情况。无须一次把所有 L1 实体及全部用例塞入 prompt。

实体对应表核心字段：

```text
mapping_id / source_entity_id / reference_entity_ids[]
source_forms[] / target_forms[] / entity_type
source_description / reference_description
source_usage_refs[] / reference_usage_refs[]
status: candidate | supported | ambiguous | rejected
scope / disclosure_dependencies / conflicts[] / revision
```

`supported` 仅表示已有可检查的两侧用例支持，不是人工真值。翻译注入时保留简短 Web 描述、中文实际译法和可回查引用；文库描述只在消歧查证时按策略提供。译名对应与“匿名角色就是某实名角色”的身份揭示单独处理，不能通过全局实体合并提前暴露。

懒构建的父目录标注已覆盖/未覆盖 L2。新提取出现后产生新版本，重新处理相关歧义；不能用未覆盖区间的空结果证明不存在该译名。暂缺译名时允许暂定译法并登记待查，不阻断全部翻译。

## 7. 正文参考和翻译输入

保持原有层次上下文的组织方式，但明确各部分角色：

1. 任务规则、目标版本和引用协议。
2. 当前需要的实体译名、Web 描述和实际用例。
3. Web 历史：远 L1 概括、近 L2 概括及详情。
4. 邻近完整 Web 原文；存在可靠配对或已提交生成译文时，附其绑定的中文。
5. 独立的跨版本语言参考区：相关 L2 的全文/摘录、版本标记、关联理由及已知差异。
6. 当前待译 Web 正文及输出要求。

正文参考区不使用旧 `pair_rows` 把文库挂在某个 Web 章的译文槽位。两侧各有 ID，明确“这两个区块相关，但不是逐章或逐句译文”。Web 历史正文已在第 4 项出现的部分不重复注入。跨版中文可以帮助语气和措辞，角色对白的具体指代和语义仍依照目标日文及 Web 历史。

整块参考是一种支持的选择，不是无条件注入：

- 预算充足且符合可见性策略时，附完整相关 L2，减少截取丢失语境的问题。
- 同一中文块关联多个源块时按范围去重；不能每翻一章重复附整块。
- 不足时依次降为命中实体/事件的前后 n 段、概括加用例、仅译名，并记录省略清单；目标正文和必要 Web 历史优先。
- 没有文库关联仍正常翻译；缺少可选参考不应触发旧的近邻双语 `coverage_gap`。
- 新译文提交后，逐步用真正绑定 Web 原文的邻章双语替代外版全文，外版主要保留译名与定向查证用途。

建议 prompt 核心约束：

> 目标是翻译 Web 原文。以下参考分为 Web 事实、绑定原文的既有译文、跨版本语言参考和实体译名用例。跨版本区块之间没有逐句对应保证。可以参考中文措辞和有用例支持的译名；不要据此添加、删除或更改 Web 中的行动、因果、时间、数量、技能属性与人物知情状态。存在冲突时保留 Web 含义，并引用对应证据提出疑问。

这段指令用于明确任务，不能保证模型不会受到相邻文库剧情影响；需要通过源文忠实度审校及对照实验测量实际污染。

## 8. 可见性、叙述顺序和实验模式

阅读顺序、事件发生时间、事实披露位置分别保存。回忆的事件时间较早，不代表它在 Web 当前阅读位置已经可知。中文卷号和中文顺序不能转换成 Web 可见性门槛。

离线索引/匹配可查看全书；生成阶段读取按策略投影的结果。全书生成的父摘要也可能含未来知识，不能只裁正文而把父摘要、实体描述、别名、匹配理由全部送入。无法证明可见的整块摘要应改用允许的子块/前缀生成概括，或不注入。

保留两种明确实验策略：

- `history_only`：沿用既有历史约束。当前 Web 块中尚未到达的章节不作为历史；文库块没有可靠的可见范围说明时，不注入其整块正文。可以使用已准入的译名用例、语言风格记录或另一个已核验历史块。严格保留目标中文及其派生摘要/实体输出的隔离。
- `reference_assisted`：为了测试用户提出的整块参考，允许注入选定的跨版本块，包括可能覆盖当前事件的内容；记录暴露范围与风险。仍禁止把文库事实当作 Web 事实，但不将该实验报告成留一盲测或严格无未来信息实验。

生产任务是否允许全书参考与内容忠实性是两个配置维度：即使允许更多参考，仍须忠于目标 Web，保留当前叙述的含混和揭示方式。MVP 默认继承旧历史策略，整块开放参考作为显式实验配置；不要求先完成所有精确对齐才能运行无外版正文的翻译。

已经注入过未来材料的持续会话不能通过下一个 prompt 删掉字段恢复盲测；必须使用新会话/检查点。压缩同样保留事实来源和用途，不能将文库参考压缩成 Web 前情。

## 9. 最小数据对象与 API

在现有文件式产物存储上增加对象，无需图数据库：

- `EditionDocument`：版本、文档/段落 ID、revision、标题及阅读顺序，保留 EPUB locator。
- `EditionIndexNode`：版本、层级、父节点、正文范围、摘要/实体/事件产物引用、构建方式、覆盖与版本。
- `BlockAssociation`：L2 多对多关联和证据。
- `EntityMapping`：独立实体对应与用例。
- `ReferencePacket`：为特定目标、用途、策略和预算冻结的上下文材料。

建议接口：

```python
classify_reference_mode(manifest, existing_mapping, probes) -> ModeReport
plan_edition_index(edition_id, document_ids, capacity, index_spec) -> IndexPlan
ensure_index_nodes(node_ids, build_budget) -> BuildReport
match_blocks(source_node_ids, reference_scope, matching_budget) -> AssociationReport
match_entities(source_parent_id, reference_parent_ids, entity_budget) -> EntityMappingReport
compile_reference_packet(target_id, purpose, visibility, token_budget, snapshot) -> ReferencePacket
lookup_reference(query, purpose, visibility, token_budget, snapshot) -> LookupResult
```

构建与读取分开：`lookup_reference` 不隐式发起付费摘要调用，返回 `not_built` 及建议节点；编排器在运行配置的调用/重试预算内调用 `ensure_index_nodes`。沿用有上限重试与失败回退，不把解析成功等同于语义正确或完整抽取。

`ReferencePacket` 至少包含：`source_history`、`parallel_examples`、`terminology`、`style_documents`、`navigation`、`omissions`、`dependencies`、`visibility_policy`、`snapshot_id`、`fingerprint`。每个材料带版本、用途、引用和证据状态。实体对应批准不意味着其整份文库上下文也获得批准。

离线对象使用版本命名空间和稳定 ID；prompt 可用冻结注册表里的短 ID。标题、章号和卷号用于显示，不能作为跨版本主键。旧 stable-v1 别名协议通过旧 adapter 保持原义，新协议另行版本化。

缓存键包含源/参考 revision、分块计划、摘要版本、实体映射版本、prompt/解析器/模型配置和可见性策略；API key 不进入日志或缓存内容。索引更新只影响相关下游对象，已开始的翻译 run 使用冻结快照；查证新结果以显式附加快照登记，不悄悄改动原始输入。

## 10. 接入现有模块

| 现有位置 | 已有假设 | 接入方式 |
| --- | --- | --- |
| `knowledge/evidence.py`、`narrative/service.py` | 中文通过 match_key/canonical 归于日文章节 | 保留 parallel adapter；增设按版本读文档和检查权限的 reader |
| `sequence/view.py` 的 FrozenArchive | 每份中文都需要唯一 canonical source | 外版文档存独立 archive；生成的 Web 中文保留真实 source/commit 绑定 |
| `references.py` | 中文段落归入源章的 Z 引用 | 新版本引用注册表；禁止为跨版块伪造 canonical 归属 |
| `narrative/partition.py` | 基于 pairs 测量双语长度 | 抽出文档载荷计量和分块核心，旧 pair adapter 继续提供旧输入 |
| `narrative/bilingual.py`、`sequence/knowledge.py` | 同一调用包含已配对原译文 | 保留 joint profile；新增单版本提取及实体匹配 profile，复用预算、解析、重试、存储 |
| `sequence/context.py` | 近邻必须有完整双语 pair，历史覆盖按源 ID | cross_edition 允许 full_source；必需源历史覆盖与可选译文覆盖分开检查 |
| `sequence/targeted.py` | 通过历史 pair 找中文用例 | 日文命中 → EntityMapping → 独立中文用例；无匹配时只给源文证据 |
| `review/context.py`、`review/lookup.py` | 审校、查证沿用 pair、canonical 与旧节点 | 共同消费 ReferencePacket 和用途过滤后的 lookup；裁决不得将文库差异判作 Web 错译 |

连续翻译提交和恢复主流程保留。Web 新译文的实体增量标记为生成用法，不能反过来当成文库既有译名的独立证据，避免自我强化。人工确认或修复后生成新版本并使相关缓存失效。

旧 run 不静默迁移，旧默认值与旧 prompt/cache 不改变。跨版本开关在新 run 中生效；旧配对路径的回归用例必须继续通过。

## 11. 分阶段实现和验收

以下为 P9.3–P9.6 的细化替代路径，P9.0/1 的语料身份和 P9.2 的基准保留。各步都可单独验收，不先建设复杂知识图谱。

| 步骤 | 交付 | 最低验证 |
| --- | --- | --- |
| D1 模式与读取接口 | 显式模式、独立版本 reader、引用注册、旧适配器 | 旧样本原行为不变；中文无 canonical 仍能合法读取；卷内同名不碰撞 |
| D2 单侧索引 | 独立分块、L2 摘要/实体/事件、L1 汇总、覆盖状态 | 无中文也能建 Web 索引；无日文也能建中文索引；大列表截断可见且可续建 |
| D3 块关联 | L1 候选范围、L2 联合匹配、差异和回查 | 开篇拆并、S 线重排、迷宫同背景负例及结局无匹配；不强迫一一对应 |
| D4 实体匹配 | L1 范围实体目录及独立对应表 | 未配对 L2 中仍能找译名；同名异人、技能等级变化、隐藏别名不误合并 |
| D5 上下文与审校 | ReferencePacket、定向查证、正文降级、策略过滤 | 无关联可翻译；外版事实不进入 Web 历史；源文覆盖不依赖中文存在 |
| D6 连续试点 | 小窗口翻译、审校、生成索引、压缩、恢复 | 新译文绑定正确；压缩保留用途；恢复不重复构建；新增知识可追溯 |

首批选择开篇、S 线迷宫片段、技能密集段、结局分歧范围；相似背景而不同事件必须纳入负例。先对同一批源文固定模型和预算比较：

1. Web 独立索引，不加文库信息。
2. Web 索引 + L1 实体译名匹配。
3. 上述内容 + L2 定向正文片段。
4. 上述内容 + 完整相关 L2 参考（符合策略，单独标明 reference_assisted）。

分别报告实际 tokens、构建成本、参考覆盖、译名正确率、源文事实错误、版本事实混入、叙事揭示改变、查证次数和弃权。固定总预算的比较用于判断信息组织是否更好；额外放宽预算的比较另列，不把多读文本的增益归因于匹配架构。

块关联评价看共同事件和误关联，实体评价看对象一致与实际译法，不以标题相似度替代。源文翻译质量由原文忠实度检查；文库整体不能作为 Web 的参考答案。小样本保留逐条结果与分母，不宣称全书质量。

MVP 完成标准是两条路径可共存、跨版关联可缺省、译名有用例、全文参考用途明确、连续翻译与恢复能运行，并且选定负例未产生已确认的错误等价/实体合并。是否提升翻译质量单独由实验回答，不以工程验收代替质量结论。

## 12. D6 连续接入的实现约定

连续流程复用 `SequenceEngine`、`SequenceRepository` 和原有提交／恢复机制，不新建第二套状态机。`translation/editions/sequence.py` 将独立 Web 历史摘要和各目标冻结的 `ReferencePacket` 接入上下文；新译文只绑定其实际 Web 原文，文库不进入 `history_pairs` 或 canonical 译文槽位。已有配对任务保持原行为。

参考包先按当前 Web 章的事件引文与源文出现位置筛选，隐藏整块关联解释及跨块实体描述。本轮显式采用 `reference_assisted`，仍可能读到文库的目标／未来内容，不计作严格无剧透或留一盲测。

首轮实测发现参考包元数据重复导致预算超限，因此新增冻结的 `edition-reference-selection-v1` 投影：模型读取段落引用和正文，revision、原生段落 ID 等留在原始包内；已由完整 Web 双语覆盖的日文历史去重。可选文库摘录、其次术语候选，按全部最终消息的校准预算逐项裁切并记入 omissions；目标正文和必需日文历史不在此处裁掉。审校、裁决只注册该投影实际选入的外版引用。

已冻结上下文恢复时验证包与投影，不重新挑选材料或改写 prompt。存储 JSON 会调整键顺序，投影复核比较结构值，同时保留已发请求的原始消息字节；旧版未精简的上下文仍可恢复。

本实验启用 `preserve_paragraphs`，要求每个非空日文段落对应一条非空中文行。翻译或修订一旦段数不符，在映射与语义审校前阻断，并在提交前复核。这是布局保护，不能证明逐段含义正确。真实试点第五章的 69→68 合并已作为失败样本保存；没有按序伪造映射，也没有把草稿升级为已提交译文。

新译文经既有双语联合提取生成 L2 节点与父目录元信息，术语用法保持 `provisional_rendering`。检查点保留最近三章完整双语，更早已提交正文可以由可追溯的节点摘要替代；不完整抽取、隔离记录和待查信息保留状态。本轮只验证了四章前缀的开放 L2 修订，没有验证跨多个新 L2／L1 的长跑。
