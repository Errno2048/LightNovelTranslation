# P4.2 两级懒加载索引：实现与容量试验

日期：2026-10-16。设计见 [两级懒加载索引](translation-multilevel-lazy-index-design.md)。本轮实现固定 100／10 章结构，按 1,048,576 tokens 规划上下文，新节点摘要上限 2500 字，不设下限。按上下文预算动态确定一级大小留待后续。

本文保留首轮严格JSON／引文准入的失败记录。后续平面协议已完成第1200章完整链路，见 [最新验收报告](translation-p4.2-1200-acceptance.md)：12个一级及2个近二级候选进入翻译，工程验收通过，译文仍待审；P5设计已另行完成。下文“未生成译文”等结论仅适用于首轮试验。

## 1. 工程交付

- `translation/narrative/multilevel.py`：无模型标题目录、子目录查询、节点选择、完整双语计划／运行、不可变摘要、跨截止位置复用、父／全文候选元信息快照。
- `translation/context/multilevel.py`：全部一级概括、近邻或请求的二级详情、近章完整双语、作品相关实体描述与译法工作集、完整 messages 和 token 清单；缺失或超限明确阻断。
- `translation/narrative/translation.py`：发送前重建验证多级 bundle，复用已有翻译执行器与账本。
- `tests/translation/test_multilevel_narrative.py`：目录与缓存、细化上卷、范围变化、保留缺口、超预算、失败保留、1M／2500 配置、局部任务不能冒充全文覆盖。
- 独立试验脚本 `artifacts/translation/tenken-cache-clean/verification/p4_2_run.py` 与只读审计 `p4_2_audit.py`。

回归命令 `py -3.11 -m pytest tests/translation -q`：**122 passed**。现有依赖仍有 `pkg_resources` 弃用警告，本轮未修改依赖。合成夹具验证了完整多级上下文能进入翻译 runner、重复翻译零新增调用；真实晚章范围没有满足全历史覆盖，因此未调用目标章翻译。

## 2. 第 1200 章容量规划

前文共有 1199 个日文叙事条目。全局验证／盲测保留集有 48 章，其中 45 章在目标之前；实际允许前文为 1154 章。目标中文及其派生信息隐藏，只使用目标之前、非保留章的完整日中正文。章级映射及中文范围完整性检查不代表语义金标准。

100 章一级节点先按固定阅读位置编号，再隐藏保留章。最末一级只有 1101–1199 的可见前缀；二级同理，不能用含未来第 1200 章的摘要代替前缀。

## 3. 首次真实请求与修正

首次选择第 601–700 章，是为了实测没有保留缺口的完整 100 章。请求两条消息，含 100 组完整日中正文；用户消息约 83 万字符。原始 HTTP payload 和可见响应已保留。

API 返回 HTTP 200、`finish_reason=stop`，实际输入 **547,068** tokens，本地估算为 547,151；完成输出 314 tokens，其中提供方报告思考输出 250 tokens。模型却声称“输入中未提供任何作品正文”，并给出不闭合、层级错误的 JSON。该结果被拒绝，没有转成可用摘要或元信息。

这说明该请求没有被接口以容量超限拒绝，但不能证明模型有效阅读了全部正文。已检查发送文件含真实正文与中文对照，未发现本地静默裁剪；目前不能确定模型为何声称无资料。

针对长输入中任务指令距离生成位置很远的问题，新 prompt 保持完整资料，在正文末尾再次重申本节点章节范围、摘要任务、原有规则与 JSON 格式。版本为 `lazy-two-level-bilingual-v2-tail-task`。这是有控制的诊断性修正，不能直接宣布最初错误已定位。

首次失败及初版源码存放 `verification/p4.2-multilevel-1200/`；修正版另存 `verification/p4.2-multilevel-1200-tail-task/`。新账本导入首次失败，两个版本合计仍最多 4 次请求、输入预留 2M、输出预留 64K。剩余 3 个任务改为完整 100 章一级、最近一级及最近一个二级节点，另一个邻近二级保持未建。

## 4. 修正版实测

完整 100 章的新请求同样返回 HTTP 200、正常结束。实测输入 548,054、输出 10,672 tokens（其中思考 4688）；提供方报告 547,008 个输入 tokens 命中缓存。正文前缀与首次请求一致，但一次命中不能外推连续翻译的长期缓存收益。

新输出确实给出了跨本块前、中、后部的事件和人物：597 字整体概括、19 个实体候选、5 个固定表达。它仍是无效 JSON：`translation_metadata` 未在根字段 `unresolved` 之前闭合。本地仅为诊断插入一个 `}` 后可解析，但进一步检查 85 处引文中有 **11 处**未通过逐字定位；候选仍未通过生产校验，未写入可用摘要对象。

诊断报告为 `full-100-diagnostic.json`，明确标为 `diagnostic_only_not_adopted`；没有修改原始输出或自动挪动引文。示例：它将「湖の大魔獣が不完全な復活を遂げる」标为 `ja:main:619@15`，该引文实际位于同章 `@8`。另外一些引文在所称位置或同章中找不到完全相同文字，需要区分错定位和改写引文。

人工抽查还发现：

- 时序表述失真。第 610 章原文及中文均明确是“年幼罗密欧回到八年前，随后长大”，输出却概括为“从八年前时间线穿越而来的成年罗密欧”，丢失关键方向与过程；这正是长期时序知识不能直接从粗摘要确认为事实的例子。
- 同一条目合并不同对象。`e19` 同时收录人物 `ナイトハルト` 和佣兵团 `触角と甲殻`，类型设为 organization，违反分开建实体的规则。
- 个体 `レーン` 被分为 species；概括中的“师匠”和元信息采用的中文“师傅”也未统一。元信息有双语对照仍不代表摘要必然遵循。
- `coverage_notes` 把“一级按设计没有 details”也当作缺口；若此产物被接纳，当前编译器仍会阻断。该字段需要进一步明确区分设计上的粗化与真实未处理内容。

最近一级块 1101–1199（过滤后 94 章）返回可解析 JSON，但在 `ja:main:1101@0` 处未通过逐字引文校验，被拒绝。最近二级块 1191–1199（9 章）也返回非合法 JSON。因此错误不局限于 100 章长输入。

| 请求 | 本地输入估算 | API 输入 | API 输出 | 结果 |
| --- | ---: | ---: | ---: | --- |
| 首次 601–700 | 547151 | 547068 | 314 | 声称没有正文、JSON 无效 |
| 尾部重申任务 601–700 | 548137 | 548054 | 10672 | JSON 未闭合；诊断后仍有错引文和语义问题 |
| 尾部重申任务 1101–1199 | 479868 | 479785 | 6053 | JSON 可解析，逐字引文校验失败 |
| 尾部重申任务 1191–1199 | 47126 | 47043 | 5168 | JSON 无效 |

4 次请求均 HTTP 200、`finish_reason=stop`，无自动 HTTP 重试、无输出截断；**直接通过全部校验 0/4，可用新摘要 0 份**。累计实际输入 **1,621,950**、输出 **22,207**、总计 **1,644,157** tokens；输出中提供方报告思考部分合计 5184。输入预留 1,622,282／2M、输出预留 64,000／64,000，请求上限已到，不再追加调用。

初版、修正版分别保留独立 payload、可见响应、请求事件、计划、失败账本和完整 I/O 页面。`p4_2_remaining.py` 只执行此前未尝试的最近一级与二级任务，仍使用同一账本；没有覆盖或修复前两份失败输出。原始输出均未转成可用摘要，完整前情编译保持 `coverage_gap`。

离线 mock 的三个选定节点通过，恢复新增调用为 0，懒建二级后对应父元信息细化覆盖由 0 增至 9 章、未建子节点由 10 降至 9，旧一级总览不变。**元信息上卷的成功证据本轮来自 mock 和合成测试；真实生成全部被拒绝，未得到有效实体上卷结果。**

最终只读审计记录在修正版 `audit.json`：重新核查历史保护文件，不发送 HTTP。新版本保护范围包含初次试验，合计 1147 个文件；未修改原语料、旧 P4/P4.1 产物和初次失败。完整原始 I/O 页面为 `verification/p4.2-multilevel-1200-tail-task/io/index.html`。

## 5. 目前已知的限制

1. 首次全部一级概括仍需阅读完整前文。本例仅输入就约 7M tokens，懒二级索引不会免除这部分成本。
2. 长上下文接收成功不保证任务遵循、内容覆盖或长程事实利用。首个真实失败已直接体现这一点。
3. 100 章概括最多 2500 字，实体最多 20 项，不能覆盖所有事件、人物、专名与时间关系。粗索引用于导航，细化与原文查询仍有必要。
4. 严格校验只证明结构、引文与范围一致；逐字引文能定位，不代表它支持全部描述或因果。
5. 元信息上卷是证据并集；同名实体尚不消歧，描述可能重复或冲突。候选均为 observed、语义待审查。
6. 工作集仍按目标／近章词面与重点形式匹配，异名、隐式回忆、对白说话人和人物知情状态未解决。
7. 完整双语请求的定位与配对包装占用可观。例如 601–700 章正文约 308,905 tokens，完整新请求约 548,137；后续可精简定位编码，但不能因此丢失可追溯性。
8. 本轮没有第 1200 章完整前情覆盖，也没有真实翻译质量比较。缺少必需一级／二级时编译器返回 `coverage_gap`；不能只给局部摘要再称全历史续译。

下一步根据本轮实际输出先处理摘要任务遵循、证据可靠性与覆盖审查，再决定是否增加付费一级节点。模型预算驱动分块、全文身份归一、连续翻译与上下文压缩仍分别规划，不由本次容量试验替代。
