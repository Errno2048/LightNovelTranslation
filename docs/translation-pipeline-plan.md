## 1. 目标与范围

从原文序列和不完整的译文序列建立可审查的对应关系，从可靠的双语配对提取翻译约定，在保留人物、术语、叙事信息与译风的前提下补译缺章和连续续译。

需要分别解决以下问题：

1. **内容对应**：章节、场景和段落范围的对应；支持漏章、拆章、合章、附加说明和版本差异。
2. **翻译约定**：人名、别名、称谓、专有名词、人物表达和局部译风。
3. **故事理解**：当时发生了什么、谁知道什么、谁在说话；不把猜测固化成事实。
4. **连续性**：前文译文和知识增量能影响后文，且可压缩、恢复、纠错。
5. **可验证性**：隐藏参考译文之后测量效果，能追溯错误来自对齐、知识、上下文还是模型。
6. **模型可替换**：生成模型和向量模型分别接入，替换配置不要求改写业务管线。

“完整对齐”指内容覆盖、语义、翻译约定和上下文的一致性，不以逐字复现参考译文为目标。现有译文是参考资料，也可能包含漏译、错译、译名变化和多种风格。

初期以本地 Python CLI、SQLite、JSONL 和 Markdown/HTML 审查报告为主。暂不开发网页管理系统、图数据库、模型微调、自动出版或多代理编排。后续是否增加这些能力，以实际瓶颈为依据。

## 3. 总体架构与开发原则

```mermaid
flowchart LR
    A[原始 HTML 与 EPUB] --> B[规范化语料及版本]
    B --> C[章节对齐]
    C --> D[段落范围对齐与质量标记]
    D --> E[证据档案与冻结知识库]
    E --> F[当前章节上下文编译]
    F --> G[翻译草稿]
    G --> H[检查与定向修订]
    H --> I[接受译文与知识增量]
    I --> F
    J[评测可见性策略] --> E
    J --> F
    H --> K[独立评测及运行报告]
```

执行原则：

- 先建立可运行的简单基线，再增加新模块；每次增加能力都保留关闭它的对照配置。
- 原始文件只读；清洗、对齐、知识和译文都是有版本的派生产物。
- 参考译文的隐藏边界先于知识抽取和检索建立，不能在最后拼 prompt 时才屏蔽。
- 独立章节的抽取可批量执行；同一连续翻译区间的状态提交按叙事顺序串行进行。
- 低可信映射、人物身份和台词归属允许保持未知，不能为了覆盖率强行确定。
- 缺少外部 API 时，P1、规则对齐、数据契约和离线验证仍能推进。
- 阶段完成以产物和验收证据为准；模块存在、接口返回成功和译文质量合格分别记录。

## 4. 模块边界与数据契约

```text

  knowledge/             # 抽取、实体合并、K0、增量和依赖关系
  context/               # 可见性过滤、few-shot、状态和预算编译
  workflow/              # 翻译、检查、修订、事务、恢复
  evaluation/            # 划分、基线、错误标注、盲评和统计

  cli.py
```

### 4.2 核心数据对象

| 对象 | 最小字段和约束 |
| --- | --- |
| `SourceDocument` | 来源、文件路径、书籍/版本、原始文件哈希、抓取时间（若可得） |
| `Chapter` | 稳定 `chapter_id`、语言、来源章节 ID、阅读顺序、标题、种类、`revision_id` |
| `Paragraph` | 所属章节版本、段落 ID、原始位置、清洗正文、作者注音、前后记或正文分类 |
| `AlignmentGroup` | 双侧一个或多个有序范围、对应类型、状态、方法、评分、证据和版本 |
| `Evidence` | 原文/译文范围、文本哈希、来源、可见性、抽取方法、派生依赖 |
| `KnowledgeEntry` | 类型、稳定实体 ID、内容、适用范围、证据、置信状态、冲突关系 |
| `KnowledgeSnapshot` | 基础版本、允许资料集合、构建配置、依赖摘要和稳定序列化哈希 |
| `KnowledgeDelta` | 父版本、新增/修改/撤销项、原文证据、生成章节、状态和影响范围 |
| `VisibilityPolicy` | 实验类型、可见原文/译文、隐藏目标、截止点、附录策略、角色权限 |
| `TranslationArtifact` | 原文版本、正文块、覆盖范围、草稿/接受状态、模型和 prompt 版本 |
| `Checkpoint` | 已接受章节、知识快照及增量链、压缩状态、未决问题、运行位置 |
| `RunManifest` | 数据、配置、模型、代码、prompt、可见性和运行分支的指纹 |

章节 ID 不直接等于内容哈希。来源章节身份保持稳定，内容修改产生新 `revision_id`；段落 ID 与章节版本绑定。EPUB 回退 ID 使用书籍、来源和文件内定位信息，不假定不同 EPUB 中同名 `page2` 是同一章。

文本范围优先使用段落 ID；确需段内定位时，记录清洗版本及字符偏移。清洗规则变化后不能沿用旧偏移和旧向量。所有范围指向的内容必须可回查。

对齐项允许 `1:1`、`1:n`、`n:1`、`n:m`、`source_only` 和 `target_only`。`uncertain`、`edition_mismatch` 是状态或原因，不等同于“待翻译”。只对已确认的缺失正文自动创建翻译任务。

### 4.3 模型适配层

业务模块仅依赖两类接口：

```text
TextGenerator.generate(request) -> GenerationResult
Embedder.embed(texts, options) -> EmbeddingResult
```

生成请求包含角色消息、任务类型、输出预算及通用采样配置；供应商特有参数只在适配器层出现。抽取、翻译、审校和压缩预留独立模型配置，初期可全部指向同一生成模型。

结果需区分正文、结构化结果、结束原因、请求 ID、模型回报标识、用量和错误。供应商不返回的字段记为 `unknown`，不能补成零。能力配置记录结构化输出、流式、token 计数、上下文限制和缓存统计的“已验证/未验证/不支持”状态。

结构化输出先做本地 schema 校验；若接口未验证原生 schema 支持，采用受约束 JSON 文本和有界纠错。截断、空正文、格式错误、拒答和业务错误均不能作为成功译文提交。

向量缓存键至少包含提供方、端点配置身份、模型、维度、预处理版本及文本哈希。更换向量模型或维度后重建索引；相同维度不代表向量空间兼容。

凭据不进入运行清单、请求日志、异常消息和报告。运行清单只保存凭据别名，不保存密钥或可还原的授权头。

| P2 | 规则优先的章节映射及人工审查入口 | P1 | 初版不需要；模糊区间按需使用 |
| P3 | 无泄漏评测框架、原文及 few-shot 基线 | P0 真实生成接入、P2 | 是 |
| P4 | 段落对齐、术语/风格知识库 K0 | P2、P3 可见性框架 | 向量与生成按需使用 |
| P4.1 | 标题驱动分块、块/区间摘要、三层上下文 | P4、容量评估 | 目录/mock 不需要；摘要和真实对照需要 |
| P5 | 校验、定向修订和接受事务 | P3、P4；按本轮顺序先完成 P4.1 | 语义检查需要 |
| P6 | 人物状态、信息边界和台词歧义处理 | P4、P5 | 是 |
| P7 | 连续翻译、增量、压缩、恢复和缓存观测 | P5；复杂状态依赖 P6 | 是 |
| P8 | 冻结评测、真实续译和完整导出 | 所选功能通过前序验收 | 是 |

最小可用里程碑 M1：P0–P3，能可靠导入、按章对齐、隐藏目标译文并完成少量基线翻译。  
约束翻译里程碑 M2：P4、P4.1、P5，加入可追溯约定、分层前情及检查修订。  
连续翻译里程碑 M3：P6–P7，处理状态演进、对话歧义和长程上下文。  
验证发布里程碑 M4：P8，得到固定测试报告、可读产物与下一轮问题清单。

## 6. P0：基础契约、配置和模型接入

目标：先让一次任务的输入、输出、模型身份和失败状态可记录、可替换、可恢复。

实施顺序：

1. 建立最小 Python 运行环境声明和测试入口，明确 Windows UTF-8 路径及文本处理。
2. 定义章节、范围、运行清单、可见性和生成结果的最小 schema，并带版本号。
3. 兼容读取现有 `config/apikey.py`；允许环境变量和显式实验配置覆盖对应配置，明确优先级。单个提供方的端点、凭据别名与模型作为配置组校验，避免只覆盖端点造成误配。
4. 实现模拟生成/向量适配器、请求记录、失败状态和 dry-run；先不接入复杂框架。
5. 实现智谱适配器，生成和向量使用各自端点与凭据配置。
6. 核对接入方式适用性后，用短合成文本做最小真实探测；不直接用整章测试未知参数。
7. 建立超时、有限重试、退避、请求数上限和 token 预算。鉴权/参数错误不无限重试。

真实探测分别验证：短文本生成、结束原因与用量字段、结构化输出策略、向量返回顺序和数量、1536 维配置支持情况、非空有限数值、单项失败行为。缓存能力、token 计数和模型别名行为分别记录；未确认不影响基本翻译功能。

产物：非敏感示例配置、`provider_capabilities.json`、最小 `RunManifest`、dry-run 报告和真实探测报告。

验收：

- 使用模拟提供方能够验证正常响应、超时、限流、畸形 JSON、空正文和输出截断的处理。
- 生成与向量端点不会串用；真实向量数量、顺序、维度均检查，不默默丢弃失败项。
- 更换模拟/真实提供方无需修改语料和翻译业务逻辑。
- 日志不含密钥；请求预算、错误分类和失败次数可见。
- 模型响应是否成功和当前用途是否具备适用接入方式均有明确记录；外部条件不足时记录未通过项，离线阶段继续。

## 7. P1：规范化语料和数据体检

目标：取得可靠正文、来源定位和稳定顺序，为后续所有实验提供同一输入版本。

实施功能：

1. 从 EPUB manifest/spine 读取实际阅读顺序；保留卷、标题和原始定位。
2. 日文优先读取可匹配的原始缓存，并与 EPUB 核对；缓存无法明确匹配时保留候选而不猜测。
3. 分离封面、目录、卷介绍、作品相关、正文、资料、前言、后记和译者注。
4. 移除程序生成注音对正文的污染，作者原生 ruby 保存为独立标注；保留正文标点、空行和场景分隔。
5. 中文识别版权说明、译者说明和站点残留；先分类保留，不用宽泛文本规则不可逆删除。
6. 对合并分页检查重复首尾、异常短章、正文缺失、乱码和相邻重复。
7. 导出章节和段落 JSONL、文件/文本哈希、分类清单、字符统计及问题报告。

产物：`corpus_manifest.json`、`chapters.jsonl`、`paragraphs.jsonl`、`ingest_report.md`、`corpus_issues.jsonl`。

验收：

- 三个 EPUB 的全部阅读条目都被登记并归类；分类和计数可与第 2 节核对。
- 不能解释的计数差异进入问题报告，不能为匹配预期数量而删除内容。
- 覆盖前言合并容器、原生注音、自动注音、分页拼接和番外的样例人工检查通过。
- 同输入和规则重复导入得到相同章节身份、版本和内容哈希。
- 原始文件哈希未变；清洗失败能回溯到具体文件与段落。
- 清洗不会把人物语言中的括号、拟声词或省略号误判为站点垃圾。

## 8. P2：章节映射，从规则扩展到语义

目标：先获得可审查的章级映射，不急于自动解决所有困难样本。

P2a 规则基线：

- 按书籍版本、正文/番外分组；将数字章号和规范化标题作为候选锚点。
- 识别终章和番外序列，显式列出源侧/译侧额外条目。
- 用长度、段落数量、开头结尾和少量正文样例做核验；章号相同不直接等于正文已确认。
- 建立 JSON 补丁或 CLI 审查入口，支持确认、拒绝、拆分、合并和记录理由。

P2b 模糊区间增强：

- 对锚点之间的候选计算日中跨语言语义分数；先用小型人工配对验证 `embedding-3` 的效果。
- 在局部序列上做允许跳过、拆章、合章的动态规划；候选分数及路径差值保留为证据。
- 对重排或不同版本先标注异常，不强制套用全局单调顺序。
- LLM 仅复核少量困难候选，并返回对应原文/译文范围及简短依据。
- 阈值在开发标注上校准；未经校准的分数不称为概率或“99% 可信”。

产物：章级候选表、已确认映射、未匹配原因、审查报告、人工修订记录及映射版本。

验收：

- 当前书的 1320 篇目录对应候选和 37 篇额外正文有明确登记；正文未核验项保留状态。
- 同一版本的源/译文本范围不能被冲突地分配给多个组；允许的多对多关联显式表示。
- 合成夹具覆盖中间缺章、额外说明、重复章号、拆合章和局部重排，结果符合预期。
- 用人工核验子集衡量自动接受项的准确率和覆盖率；所有异常项进入审查队列。
- 仅 `confirmed missing` 生成待翻译任务，`uncertain` 和 `edition_mismatch` 不自动补写。

## 9. P3：评测框架和最小翻译基线

目标：在构建全书知识库之前，先能进行可信、可重复的遮蔽实验。

实施功能：

1. 建立开发、验证、最终盲测划分，冻结清单与选择规则。
2. 实现单章补缺、连续区间补缺、顺序续译三类 `VisibilityPolicy`。
3. 将生成侧资料视图与评测侧参考答案分开；生成流程不能访问参考答案存储入口。
4. 实现 A 基线：仅当前原文与统一翻译指令，整章翻译。
5. 实现 B 基线：A 加少量已允许访问的邻近双语示例；先固定选择规则和数量，再测质量。
6. 保存 prompt、模型配置、结束原因、原文版本、输出正文和用量，初步检查空正文与截断。
7. 生成原文/候选译文/参考译文对照报告；盲评版本隐藏方法及模型名称，顺序固定随机化。

此阶段少量手工双语范围可用于示例，不要求先完成全书段落对齐。基线初始输出为整章正文；段落范围映射在 P4/P5 加强。

产物：`splits.json`、`visibility.json`、A/B 实验配置、基线译文、错误标注模板、运行与初步质量报告。

验收：

- 隐藏目标译文的正文、中文标题、译注、对应摘要、向量检索结果和示例均不能进入生成上下文。
- 用带唯一标记的合成参考内容检查检索和 prompt 泄漏，并检查依赖闭包；不能只靠字符串检测判断无泄漏。
- 顺序续译不使用截止点之后的译文或由其产生的知识；默认严格协议也不使用当前章之后的原文。
- 两侧补缺可访问后续已译资料，但明确标记时间和用途；不与顺序续译混合评分。
- 在 3 个开发章节完成 A/B 的 6 次基础翻译后，再扩展至开发集；错误或预算超限不会自动扩大任务。
- 模拟失败后能恢复，已完成的任务不被无理由重复调用。

## 10. P4：段落对应与第一版冻结知识库

目标：先解决最可控的术语和风格约束，再逐步引入复杂剧情状态。

补充设计见 [知识库设计](translation-knowledge-design.md)，具体实施见 [P4 执行计划](translation-p4-plan.md)，完成证据见 [P4 结果报告](translation-p4-results.md)。本轮已完成有限范围的版本化审查和折内 K0；其余候选仍不能直接交给抽取器冻结为知识，也没有认证全书语义完整性。

本阶段按 T0–T7 推进：输入/政策契约 → 局部对应审查 → 版本化知识存储 → 标题/正文索引 → 有界术语/风格抽取与审查 → 折内 K0/工作集 → CLI 集成 → 离线门禁与真实 B/C 对照。标题用于召回，正文检索独立；索引和只读查询默认不调用模型。

P4 保存故事时间、揭示位置与知识版本的独立契约，完成简单适用范围和可见性检查；完整事件时间线、人物知情推理与局部图查询在 P6 实现。基础知识提交、冻结与修订在 P4 实现；译文接受事务及连续运行恢复分别归 P5/P7。全书摘要、全书精细抽取和全书新向量索引均不是 P4 的默认工作。

P4a 段落范围对齐：

- 在高可信章节组内实现段落序列匹配，允许多段对应一段及少量空对齐。
- 用双语语义、数字、引号结构和长度作为辅助信号；语义向量不作为唯一依据。
- 发现局部漏译、增译、译者注和重复分页；保留疑似原译错误，避免当作训练示例。
- 对齐范围用于证据和示例，不强迫正式译文保持原文段落数量。

P4b `K0.v0`：

- 从允许的高可信配对抽取实体、源文形式、中文译法、别名、称谓与使用范围。
- 建立稳定实体 ID；相同表面名不自动合并，不同别名合并必须有依据。
- 提取全局和区间风格：标点、敬称、自称、拟声词、断句及人物表达的双语例句。
- 先保存候选项，再统一实体、检测冲突，冻结有效约定；矛盾项不自动多数表决。
- 每项附证据、状态和适用范围；故事事实来自原文，中文表达约定来自译文。
- 编译完整核心约定和本章相关术语；按当前原文匹配别名，并补齐必要关系和消歧信息。
- 形成 C 基线：B 加冻结术语/风格；此时只使用简单人物卡，不强制构建完整时间线。

产物：段落对齐、参考质量清单、术语表、人物表达卡、风格区间、冲突报告、证据档案和 `K0.v0`。

验收：

- 每个生效知识项都有可访问的原文或双语证据；推断与直接陈述分开。
- 知识构建遵守实验折的可见性。全书生产版 K0 不能直接用于隐藏部分译文的评测。
- 名字、称号和昵称的合法变体不会被单一全局替换破坏。
- 删除或修改一条证据后，可定位受影响的知识条目和后续派生物。
- 在相同开发/验证样本上比较 B/C，报告术语准确性、误用、译风与 token 增量。
- 核心知识和完整术语表实际测量 token；只有确实适配预算才整表放入，否则按明确规则编译工作集并报告遗漏候选。

真实试点在 `tenken-cache-clean` 使用第 3、775、1233 章，按目标建立独立遮蔽折；使用允许的 donor 范围构建知识，不能用目标自身译文抽取后再评测。B/C 同输入、同 few-shot、同模型配置；旧污染语料上的 B 不直接作为对照。费用上限、参考质量处理与完成清单见 P4 执行计划；未证明改善时如实报告，C 不自动默认启用。

### 10.1 P4.1：分层叙事索引与确定性上下文（工程与初步对照完成）

采用 [分层索引设计及任务计划](translation-hierarchical-context-design.md)，按 H0–H5 实施：政策/schema → 本地标题分块 → 完整块与可见前缀摘要 → 三层编译 → CLI/离线门禁 → 有界真实对照。历史 P4 完成范围不包含这些能力。

2026-10-16 已完成：全书 1357 个日文叙事条目的 35 个候选块；第 45 章独立遮蔽折为 41 个允许前文章节构建六份摘要，完成 C/H-near/H-tiered 三组真实翻译及无请求恢复。103 项回归通过；四份摘要依赖本地恢复，语义和译名仍有明确缺陷，未证明分层稳定改善。详见 [P4.1 结果报告](translation-p4.1-results.md)。

- 最近 `N_chapter` 章注入完整日文及允许的完整中文；最近 `N_block` 个可见块注入整体及区间详细摘要；更远可见块全部注入整体摘要。
- 初始试验取前 3 章、最近 2 块，当前块已读前缀占一个块名额；未来资料默认不可用。
- 译文缺失不补造，段落审查不升级为完整章节资格；缺必需摘要、过期依赖或超预算均明确报告，不静默丢弃远块。
- v1 全局重点实体卡仅保留插槽；后续 v2 随块生成基础人物描述和双语译法元信息，再汇总和独立注入，仍不扩建完整人物图或通用 Agent 工具循环。
- 对比 C、H-near、H-tiered，分别测量完整近章和分层摘要效果；零泄漏、确定性覆盖与来源有效为硬门禁，质量收益另行判断。

B0–B4 的首版流程已执行：双语准入/schema → 联合摘要和元信息 → 确定性候选汇总 → 独立工作集及完整 prompt 审计 → 单章有界消融。真实试验另立预算和产物，未使用旧账本。原始响应格式、章节区间错置、描述证据不足与注入体积仍有缺陷；后续先解决这些可靠性问题及 P5 审校。基础描述前移不代表完成 P6 的人物状态和知情推理。

## 11. P5：覆盖检查、语义审校与定向修订

目标：使接受译文成为有记录的状态转换，阻止已知错误进入后文。

具体架构、API、P5.0–P5.5任务、预算及第1200章真实缺陷夹具见 [P5设计](translation-p5-design.md)。权威接受记录与head在同一SQLite事务提交，独立知识库通过outbox投影；近章读取需使用接受感知适配器。P4.2阶段验收不改变草稿状态。

实施功能：

1. 输出正文与机器侧段落覆盖记录分离；验证原文范围无静默遗漏或重复，允许自然合并。
2. 确定性检查：空输出、截断、异常长度、数字/单位差异、术语变体、括号与格式异常。长度和数字差异是复核信号，不一律判错。
3. 语义检查：漏译、增译、否定、主客体、时态、人物关系和明显说话者错误。
4. 风格检查：称谓适用范围、人物表达与局部风格；不为追求参考措辞而惩罚等价自然表达。
5. 审校器返回定位、严重程度、原文依据和修订建议，不能只给总分。
6. 独立请求进行定向修订，保留前后版本；初始最多两轮，失败进入待复核，不无限重写。
7. 对修订涉及的范围和相关术语重新检查；记录修复成功及新引入错误。
8. 以原子事务提交接受译文及其关联状态，草稿和修订过程不进入连续翻译主上下文。

产物：检查报告、带定位的缺陷清单、修订记录、接受策略、接受/待复核译文。

验收：

- 注入漏段、重复段、否定反转、错误数字、错误名字和角色互换等合成缺陷，检查器能发现对应问题；同时测量正常文本的误报。
- 原文段落 ID 全覆盖不被表述为语义完整，语义检查保留独立结果。
- 未修复的确定性硬失败或经确认的严重语义问题不能自动标为接受。
- 每条审校意见可回查依据；同模型自评只作为辅助，不能替代人工样本检查。
- 修订后重新验证，比较开启/关闭审校的收益与成本；未改善的修订策略不默认启用。

## 12. P6：人物状态、信息边界和台词理解

目标：只对影响翻译的歧义增加结构化理解，避免过早实现完整世界模拟。

具体实施以 [P6局部状态与对白设计](translation-p6-design.md) 为准：P6.0–P6.6依次建设契约、时间／状态底座、正文取证、局部分析、上下文编译、P5接入和有界验证。使用B／D-reviewed／D-candidate对照区分知识抽取与模型利用能力；P5质量未通过不阻止离线底座开发，但真实译文继续处于待审状态。

实施顺序：

1. 从明确原文事实开始，记录人物在场、时间地点、关系变化、物品和能力状态。
2. 在 P4 的契约上实现故事发生时间与文本揭示位置两条轴，独立保留知识版本；回忆、资料页和后日谈单独处理，不把章节顺序当作故事时间。
3. 区分世界事实、人物声称、人物相信/怀疑，以及系统尚不知道的信息。
4. 按章节生成简短场景表：参与者、叙述视角、表达通道、关键指代和未决事项。
5. 对影响中文代词、敬称、语气的台词，给出说话者/受话者候选及证据，不要求全部唯一归属。
6. 将明确动作、称呼、自称、对话邻接作为主要线索，人物信息和语气作为辅助约束；保留撒谎、试探和引用的可能。
7. 中文可自然保留含混时不补写姓名、性别或“某某说道”；高影响歧义按需扩大上下文。
8. 形成 D 配置：C 加状态与场景信息；分别消融状态和台词分析，避免合并收益无法解释。

产物：状态账本、事件及关系记录、人物信息状态、场景表、台词候选和歧义报告。

验收：

- 样本覆盖回忆、关系变化、人物误解、隐瞒和无标注多人对话。
- “没有记录知道”不会推导成“确定不知道”；假说不会被下一次摘要升级为事实。
- 后续参考资料可以帮助译名校准，但不能让当前角色提前拥有未来知识或在译文中提前揭示身份。
- 对有可靠人工标签的台词统计归属准确率；对真实歧义记录弃权比例与不必要显式化错误。
- D 相对 C 的改进落在目标错误类型上，且没有明显增加增译和错误确定性。

## 13. P7：连续翻译、知识增量与上下文压缩

目标：让系统在连续缺口和真实续译中保持一致，并能中断、恢复和回滚。

实施状态：P7.0–P7.5 最小功能及回归已交付，P7.6 的真实多窗口／共同前缀试验已开展，完整长程和质量验收尚未通过。代码、完整输入输出与限制见 [实施报告](translation-p7-results.md)。

详细任务、数据契约、API、动态分块和验收场景见 [P7详细设计](translation-p7-design.md)。本阶段使用完整请求估计乘默认1.05的先验膨胀系数，再加本次输出预留和固定余量；不同角色共用预算入口。100/10章改为可配置上限，两层边界根据实际输入及输出预算缩短，不再要求整除。分卷边界预留后续实现。

P7开发不以P6语义质量已通过为前提。连续实验默认在独立 `working` 分支使用满足机械与流程条件的最终工作译文，未决事项保留；它不构成正式接受，也不提升全局知识权威。`accepted_only` 模式仍使用既有接受策略。以下总体原则按详细设计中的两种模式执行。

P7a 知识分支与增量：

- 每个实验折、策略和连续翻译分支从自己的允许资料构建 K0，禁止共享可变运行知识。
- 新事实以当前原文为依据；新中文译名先标记为分支暂定约定，正式接受与知识升权独立处理。
- 增量保存父版本、证据、适用时间、状态和影响范围；K0 本身保持不可变。
- 修正旧知识时创建新版本或撤销增量，并标记依赖它的译文为待重新检查；不静默改写过去。
- 首个新术语的命名决策保留来源和理由，便于后续统一或纠错。

P7b 连续上下文：

```text
固定翻译指令
冻结核心约定
本轮固定状态快照与双语示例
本轮三层前情（远块整体、近块整体/详情、完整近章）
本章新增约束与原文
本章最终已提交译文（working / accepted 标记明确）
下一章新增约束与原文
下一章最终已提交译文
……
```

- 初期每个连续缺口一个独立分支；状态按章节顺序提交，会话由检查点分段管理。
- 保持会话前缀稳定，在尾部追加新约束；不为追求缓存而忽视必须更新的错误知识。
- 三层前情在检查点重编译；会话内部新提交章节可暂以完整双语追加。二级块闭合或准备移出全文时联合抽取摘要与知识；跨块或超预算时显式刷新窗口与摘要，记录实际层级范围，不能声称窗口移动后前缀仍完全不变。
- 审校和知识抽取请求与翻译主会话分开，避免草稿和内部分析持续占据上下文。
- 核算输入、输出和余量预算；没有准确 tokenizer 时用保守估计并记录估算偏差。

P7c 压缩与恢复：

- 按 token 阈值或篇章边界生成检查点，保留当前状态、未决事项、译名变更和最近完整双语章节。
- 老历史优先复用 P4.1 中版本及可见范围匹配的块摘要；新增/修正部分从原文及证据重建，结构化账本仅提供辅助，避免反复“摘要的摘要”。
- 新会话载入检查点、核心约定与按 P4.1 规则编译的三层前情；明确本轮可见性。更高层压缩若替代远块摘要，必须作为显式策略另行验证完整范围覆盖。
- 对请求完成、译文接受、知识提交和检查点保存之间的中断位置分别测试。
- 记录提供方实际返回的缓存读写字段；缺失时报告不可观测，不将耗时下降等同于缓存命中。

产物：知识增量日志、状态快照、上下文清单、压缩检查点、恢复记录及缓存/成本报告。

验收：

- 同一窗口的完整运行与从已提交检查点恢复，在任务顺序、知识版本和已有译文上相同；不要求重新生成的文本逐字相同。
- 不重复接受章节、不丢失知识增量、不把半成品提交成成功；超时后远端是否计费不明时如实记录，不宣称请求严格只执行一次。
- 未压缩长上下文、压缩上下文和简单滚动窗口使用同一数据条件比较，测量质量与成本。
- 压缩后检查关键约定、未决问题和信息边界的保留，不能仅比较摘要长度。
- 更换生成模型创建新运行分支，沿用可解释的知识数据但不复用隐藏状态；重新校验能力、预算和模型相关 prompt。
- 修改或撤销早期增量能定位需要重审的后续章节，已有结果保留审计记录。

## 14. P8：固定评测、真实续译与导出

目标：证明选定配置在未调参样本和连续区间中有效，再投入真实缺失内容。

实施顺序：

1. 固定数据版本、配置、阈值、提示词及评价规则，运行最终盲测；不根据盲测结果继续调同一轮参数。
2. 在单章、连续缺口和顺序续译三种协议下分别报告结果；按早中晚期、对话密集、新术语等分组。
3. 对比最简单可用基线和最终候选，保留未改善和变差的案例。
4. 在人工可投入的范围内检查关键错误和连贯性；未复核部分明确标为自动检查。
5. 对 37 篇目录上无译文的闲章，先确认真实缺失范围，再从最早的少量章节开始续译，检查通过后逐步扩展。
6. 导出接受译文、对照审查页面和独立 EPUB；保留原有译文，明确已有译文与机器补译的来源。
7. 形成运行说明、模型替换步骤、数据更新/重建说明和下一轮缺陷清单。

产物：冻结评测报告、真实续译试运行报告、接受译文、独立导出文件、可重跑配置和操作文档。

验收：

- 最终报告含样本数、可见性策略、实际配置、错误分类、成本及失败/弃权项，不只给平均总分。
- 在已检查的发布范围内不存在未处理的已确认严重错误；未检查范围不能声称已证明无误。
- 导出能打开，章节顺序和文本覆盖与接受记录一致，生成失败或待复核章节没有被悄悄填成完整结果。
- 原始 EPUB 不被覆盖；机器补译和历史译文的来源可区分。
- 无参考的 37 篇不计算参考匹配分数，也不作为最终质量提升的唯一证据。

## 15. 统一验证协议

### 15.1 分层评测与样本规模

下列数量是启动建议，在 P3 根据预算确定并冻结；不是当前已经建立的样本集。

| 集合 | 建议规模 | 用途 |
| --- | ---: | --- |
| 最小冒烟 | 开发集中的 3 章 | 验证模型、格式、记录与 A/B 流程 |
| 开发集 | 12 章 | 调解析、提示词和错误分类；允许反复查看 |
| 验证集 | 24 章 | 比较新增模块和选择配置；不作为最终盲测 |
| 最终盲测 | 另选 24 章 | 配置冻结后的最终比较 |
| 连续区间补缺 | 2 个窗口，每个 8 章 | 两侧衔接、术语选择和累计误差 |
| 顺序续译 | 2 个截止点，各续译 8 章 | 禁用未来资料的状态演进与压缩 |
| 对齐/台词标注 | 先标注小型困难子集，再按错误补充 | 针对性衡量准确率与弃权 |

集合尽量跨早中晚期、不同译风、多人对话、首次命名、密集技能和回忆场景。不同用途的测试窗口不与开发目标重叠；若正文上下文必须重叠，记录关联并按窗口聚合统计。当前开发集训练资料中可能出现最终测试译文的问题，需要用统一全局保留集合阻断，不能只在最终运行时临时屏蔽。

不是每个阶段都运行全部配置和样本。先在小集排除明显无效的策略，最终盲测只运行保留的基线和候选；连续窗口的分析和成本按整个窗口计算。

### 15.2 可见性与防泄漏

- **单章补缺**：隐藏目标章译文及相关派生物，允许使用策略指定的其他双语资料。
- **连续区间补缺**：隐藏整个目标区间及派生物；区间内后续状态只能来自本次已接受的译文和对应原文。
- **顺序续译**：初始知识仅来自截止点前允许资料；逐章开放当前原文，不提前读取未来原文或译文。若测试允许未来原文，应作为单独的辅助协议标注。
- **对齐评测**：完整参考可用于独立人工金标准；翻译生成侧不能读取金标准中隐藏译文的标题、正文或实体答案。
- **资料页策略**：开篇人物/技能资料可能包含后期信息，默认不进入严格顺序实验，除非每条信息都完成适用时点筛选。
- **派生物策略**：知识合并、风格归纳、摘要、检索索引、示例选择和压缩检查点全部受同一策略控制。

每个派生物记录依赖。隐藏一个章节后，包含该章的抽取和跨章归纳需要重算；仅删除直接引用该章的条目不足以保证无泄漏。独立章节的允许资料抽取可以缓存，跨章结论必须以本折资料重新建立。

生成与评测使用不同数据入口；评测器可读参考答案但无权修改生产知识库。模型可能从预训练中记住公开小说这一点无法完全排除，报告中区分项目资料泄漏与无法控制的模型记忆，不把留一实验视为对陌生作品的普遍保证。

### 15.3 对照配置

| 配置 | 增加的能力 | 核心比较 |
| --- | --- | --- |
| A | 当前原文与基础指令 | 最低基线 |
| B | 邻近双语示例 | few-shot 的收益 |
| C | 冻结术语和风格约定 | 专名与译风改善 |
| D | 场景、人物状态和信息边界 | 对话及信息错误改善 |
| E | 连续历史、增量和压缩 | 跨章一致性与成本 |
| F | 独立审校和定向修订 | 最终错误减少及新增错误 |

开发顺序中审校在 P5 先实现，最终消融仍可按 A–F 组合。F 也应单独作用于 C，区分审校收益与复杂状态收益；E 同时比较不压缩、滚动窗口和检查点压缩。

P4.1 另设 `H-near`（C 的约定＋完整近章）与 `H-tiered`（H-near＋近块整体/详情＋全部远块整体摘要），不占用 D。使用相同模型/目标/权限，记录增加的输入成本；后续 D–F 若叠加分层上下文，必须显式记录基础配置。

同一对照使用相同资料可见性、目标章节、模型配置和输出预算。上下文引入 token 增加时如实记录，不宣称在相同成本下提升。不同模型的对比新建运行分支；抽取器、审校器和压缩器的模型身份也要记录。

### 15.4 指标与验收口径

| 维度 | 指标/检查 | 注意事项 |
| --- | --- | --- |
| 数据清洗 | 条目登记、正文保留、重复/缺失、注音处理 | 对原始位置可回查 |
| 对齐 | 自动接受准确率、覆盖率、错误类型、弃权率 | 高准确率不能靠隐藏未解决样本取得 |
| 内容忠实 | 漏译、增译、否定、主客体、数字、时间错误 | 以原文为依据，参考译文也可被判有误 |
| 术语 | 出现级正确率、实体误合并、称谓范围错误 | 区分合法别名，不仅做字符串完全匹配 |
| 对话 | 有标签的归属准确率、弃权、错误显式化 | 对真实歧义不强制唯一答案 |
| 信息状态 | 提前泄露、错误知情、关系与事件时点错误 | 单独列为严重错误候选 |
| 风格 | 人物表达、局部连贯性、自然度盲评 | 不把润色偏好自动当忠实度提升 |
| 运行 | 成功/失败/重试、恢复一致性、调用量和耗时 | API 成功不等于质量通过 |
| 成本 | 输入/输出 token、重试开销、缓存字段、每接受章成本 | 缺失用量记 unknown，价格不在此固定 |

严重程度建议使用 `critical / major / minor`，定义和示例在 P3 冻结。自动发现的问题是候选缺陷，抽样人工复核后统计准确率；歧义判断有争议时保留双方依据。

质量门槛在开发/验证集上确定，再用于最终盲测。最低结构门槛是登记覆盖完整、无静默截断、无已确认遗漏未处理；语言质量不预先承诺一个未经测量的百分比。模块若不能稳定改善目标错误或成本过高，保留为可选项。

对最终候选报告逐样本配对差异和原始计数；样本足够时给出按章节或窗口重采样的不确定区间。小样本不把细微平均分差写成确定结论。

## 16. 运行、预算与故障处理

### 16.1 运行状态

```text
pending -> running -> drafted -> checked -> accepted
                       |           |
                       +------> needs_review
running -> retryable_error / failed / unknown_remote_result
accepted -> stale（依赖失效，保留历史结果并触发重审）
```

知识更新仅在对应译文接受事务中提交。某章被撤销后，依赖它的状态和后续译文标记失效，不直接删除原记录。模型请求与本地提交分离，远端成功但本地超时的费用及重复调用风险如实记录。

### 16.2 预算和缓存

- 每个运行配置明确最大章节数、最大请求数、重试次数、输入/输出预算和并发数；dry-run 显示预期任务数及估算。
- 先以低并发探测实际限流；相互独立的向量/抽取任务可并发，同一翻译分支保持顺序。
- 全书知识抽取前用开发样本估算工作量；缓存键包含资料版本、模型配置、prompt、schema 和可见性身份。
- 不将输出长度当作计费 token；若供应商没有可靠计费信息，只报告实际可得用量。
- 提供方缓存、客户端响应缓存和压缩后减少 token 是三种不同机制，分别统计。
- 缓存命中不得跨越不兼容的数据版本、评测可见性或模型配置；缓存也属于需要审查的派生物。

### 16.3 模型替换流程

1. 新建提供方/模型配置，保留旧配置和结果。
2. 运行 P0 能力探测及最小生成/向量契约检查。
3. 生成模型替换时重新设置 token 预算、结构化输出与思考参数，重跑小型 A/B/C 回归。
4. 向量模型替换时重新嵌入并校准相似度阈值；不混用旧向量，即使维度相同。
5. 对知识抽取模型变化选择复用已审查的 K0 或重建 K0，并在比较中明确是哪种实验。
6. 连续会话在清晰的检查点处分支；不把供应商隐藏状态作为可迁移资产。

## 17. 关键风险与对应验证

| 风险 | 处理与验证所在阶段 |
| --- | --- |
| 正文被当作前言删除、注音污染 | P1 来源适配、原始定位和夹具 |
| 目录完整但存在漏段或分页重复 | P1/P4 正文检查与段落对应 |
| 同名不同人、别名过早合并 | P4 有证据的实体合并，P6 时点和信息边界 |
| 参考译文有错误或多译风 | P4 区间约定、冲突记录，P5 原文校验 |
| 留一实验经知识/摘要/标题泄漏 | P3 可见性隔离、P4/P7 依赖重算 |
| 说话者分析制造错误确定性 | P6 候选、弃权和错误显式化评测 |
| 自己生成的内容成为虚假事实 | P5/P7 以原文举证、接受事务和增量回滚 |
| 压缩丢失人物信息或未决事项 | P7 结构化重建和压缩消融 |
| 缓存优化导致旧约定长期残留 | P7 检查点更新和必要前缀失效 |
| 模型/端点/维度不兼容 | P0 独立能力探测，模型替换流程 |
| 大规模调用成本不可控 | P0/P3 小样本与任务预算，逐级扩展 |
| 指标偏好润色、忽略忠实度 | P3/P8 分项错误、原文依据和盲评 |
