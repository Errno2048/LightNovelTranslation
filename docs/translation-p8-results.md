## 3. 第一个阻断：映射模型遗漏，重启不会自动恢复

410 章第一组输出为：

```text
@@MAP m1
source: S001,S002
target: T001
status: mapped
```

实际正文包含：

| 标签 | 内容 |
| --- | --- |
| S001 | 决定接受库鲁贝鲁多去见雇主的提议及原因 |
| S002 | `道中コルベルトにその雇い主に関する質問をしてみる。` |
| T001 | 接受提议及原因的完整中文 |
| T002 | `路上我们试着向库鲁贝鲁多询问关于雇主的事。` |

S002 的中文已存在，映射模型却将它并入 T001，并跳过 T002。程序因此正确报告 `unmapped_target=T002`；这里的直接阻断原因是**映射结果不完整，不是格式解析失败，也不是该句实际漏译**。

当前 `map_coverage()` 只做一次语义映射。HTTP 返回成功、协议完整后，不会因 `mapping_complete=false` 再发起带诊断的映射请求。重启又复用同一份缓存，因此一直在相同位置阻断。既有三次上限没有为这种成功返回后的覆盖失败提供恢复路径。

证据：`http/043.request.json`、`http/043.response.json`、`failure-forensics.json`、`io/main-410/translation-draft.txt`。新 runner 会为阻断返回退出码 2，不把 shell 正常退出与实验完成混为一谈。

最低限度修复应是：按同一版本、同一逻辑映射任务计数，最多三次；向后续尝试提供缺失／重复／乱序诊断，要求完整重建映射。保留全部旧响应，不按段落编号自动补对应，不降低覆盖门槛，也不在恢复时重置尝试数或总预算。

## 4. 更重要的工程问题：引用编号命名空间混用

本书有三套编号：

```text
阅读章号 main:400
目录 order 401
物理 ID ja:syosetu:n6006cw:402
```

L2 输入使用 `J401.27` 这类 **order + 段落序号** 标签。历史摘要则含 `ja:main:400@27` 这类 **match_key + 段落序号** 引用。模型受混合上下文影响，抽取时大量输出了后一种形式。

当前生产解析器 `translation/narrative/extraction.py::normalize_output()` 从 `J401.27` 的数字自行构造 `ja:main:401@27` 别名，于是发生：

```text
模型输出 ja:main:401@27
解析器换算为 J401.27
实际绑定的是 main:400 的段落，而不是 main:401
```

这不是全角字符或分隔符的无损规范化。代码没有显式的 match_key 映射，不能证明这两个标签等价。模型有些位置也可能把 order 写进了 `main:`，更说明此处不能由解析器猜测其意图。

离线回放发现 205 次这类标签命名空间不一致，涉及 149 个不同别名；**这些是标签不一致计数，不是 205 处已证实的语义错译**。细节和具体绑定的 chapter ID 保存在 `failure-forensics.json`，可零调用重现。

首个生成 L2 的结果为：

| 项目 | 数量 |
| --- | ---: |
| 通过当前校验的记录 | 12 |
| 隔离记录 | 43 |
| 其中通过的实体／事件／状态／知情 | 3／1／1／2 |
| 其他通过记录 | SUMMARY 1、COVERAGE 1、NEED 3 |
| 注入 410 章的知识候选 | 10（不含 SUMMARY/COVERAGE） |

隔离包含无效日文／中文引用、空证据、译名未出现在证据中及事件端点缺失。大量隔离反映抽取损失；同时，**通过了校验的记录也不能因这一编号换算而被认为引用可靠**。

因此停止本轮后续传播，保留原始基线。最低限度修复应由 `render_pairs()` 显式生成并冻结 `chapter_id / match_key / order / paragraph_id / alias` 对照，仅接受能查表证明的别名；未知或冲突标签隔离。修复后对旧 raw 显式离线重解析并保存新版本，不能悄悄把旧节点改成“引用正确”。这部分确定性工程缺陷应先于新的长程试验解决。

## 5. 原文复核：审校漏检仍存在，参考译文也不是金标准

### 已提交的 409 章：两处明确的角色关系错误

| 原文 | 本轮译文 | 原文支持的修复方向 |
| --- | --- | --- |
| S053：`拘束するっていうから任せたんだが` | `说要拘束对方就交给我了` | 对方说要抓住跟踪者，所以**我交给他们处理**；不是别人交给“我” |
| S075：`アシュトナー侯爵に仕える密偵` | `让阿修德纳侯爵效力的密探` | **为阿修德纳侯爵效力的密探**，主从方向被颠倒 |

该章审校报告没有 FINDING，语义覆盖声明完整；裁决处理的是规则信号，没有定位这两处错误。这是实测漏检，不能因工作提交成功而宣布语义正确，也不能用知识引用解析问题替模型开脱。

### 未审校的 410 草稿：使役关系丢失

S034：`大量の料理を出すのは控えさせたよ？` 译作“**我确实克制了**从次元收纳里拿出大量料理”。根据后文芙兰想拿咖喱、师傅只让她吃炸串的上下文，应是“**我让她克制一下／没让她拿出大量料理**”。410 因映射阻断尚未进入语义审校，不能把这一例统计成审校漏检。

### 审校也有误报，但本轮裁决成功挡住了一例

404 章审校声称草稿用了“瓦尔基里”，实际绑定的草稿是“战乙女”；意见自己又说两种写法均可、无需修改。裁决正确指出草稿内容不符并 dismissed，没有产生无效修订。

十份审校报告共输出一条 FINDING，被驳回；37 条数字规则信号也全部被裁决 dismissed。37 是模型判定结果，不代表已逐条人工验证。数字提示带来了明显复核开销，而本轮发现的语义问题主要是参与者和修饰关系。

### 也有译得更准确的地方

409 章的 2／3／5 发施法能力及 7／10 条雷锁被保留。410 草稿对 `すぐに立場で抜かれてしまった` 译成“很快就被超越了地位”，与上下文中兽王后来地位高于伯爵相符；既有参考把它写成“马上就忘记了立场说笑起来”，反而偏离原文。400 章“就算四十岁左右也不奇怪”也保留了推测语气。

这些只是局部复核结果，不能外推总体准确率。新出现人物的中文音译与隐藏参考不同，也不能仅凭差异判错；应检查此前允许的译名证据及分支内一致性。

## 6. 恢复、验证和下一步

建议按以下顺序继续：

1. 修复编号命名空间，并用 `main != order != physical ID` 的样本补回归测试；先零调用回放当前 L2，检查恢复与隔离差异。

4. 再推进到 429／430，执行原定共同前缀压缩对照；语义错例另外用来评估审校角色或通用关系检查策略，不把本作品答案注入翻译 prompt。
