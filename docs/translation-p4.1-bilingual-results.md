## 2. 资料与对照范围

目标仍为 `main:45`，近章为 42–44，`N_chapter=3, N_block=2`。隐藏目标中文及派生物，沿用全局验证/盲测保留集合；前文实际排除 `main:5/23/28`。41 个允许前文章节组成六块：1–4、6–20、21–22、24–27、29–32、33–44。

与旧试验的重要区别是：本轮允许这 41 章的对应中文参与联合构建，而旧试验只有 2、4、42–44 章中文的 allowlist。每章登记完整中文正文范围准入，保留实际段落定位；这是范围覆盖检查，不是全章语义金标准，也没有把章级映射冒称逐段金标准。

生成模型沿用配置中的 `glm-5.3-flash`，思考模式 enabled、`reasoning_effort=low`、自动 HTTP 重试为 0。全部真实调用计入独立 SQLite 账本；旧轮 149800/150000 的预留不动。

两组新翻译共享同一批最终选用摘要、近章双语、短 donor、旧 K0、目标原文、模型与 10000 tokens 输出预留。`v2-summary` 不注入独立元信息，`v2-metadata` 额外注入元信息工作集。二者消息删除元信息消息后应完全相同；旧 H-tiered 只作诊断，不作同资料的因果基线。

## 3. 摘要模型现在收到什么

每次请求有两条消息：system 规定联合任务和 JSON 契约；user 包含 1000 字长度配置、固定区间计划、逐章配对状态及完整日文/对应中文。日文定位如 `ja:main:42@5`，中文定位如 `zh:main:42:0@1`；`pair:main:42` 说明章级对应，不承诺这两段恰好逐段互译。

整体摘要与每条区间详情各最多 1000 字、不设最低字数，元信息、引文、JSON 与思考输出另计 token。模型同时提取作品描述、实际译法、用法范围、双语引文和未决事项。描述依据日文，既有译法依据对应中文；无法支持的译法不作为有效观察项保存。

首轮六块完整双语输入估计中，6–20 块最大，约 114672 tokens；33–44 块约 103593。单块输入计划上限为 150000，输出预留每次 20000。不裁剪原文或中文来满足预算。上述是本地 tokenizer 加聊天开销估计，实际 API 用量另列，不能当作精确模板计数。

第一次 33–44 产物出现详情错置区间和近期主要事件未充分覆盖，未用于翻译。另发一份 `range-bounded` 请求，仅重建该块：在每章双语前重复显示所属详细区间，要求逐区间核对全部章节，并禁止把不同地点/技能因同类而合成一个实体。具体请求另存 `summary-refinement-plan.json`，其余五块沿用已保存修订。

**专项重建并未彻底解决区间错置。** 最终标为 41–44 的详情仍包含第 39–40 章的子爵技能掠夺与毒沼调查，随后才写料理、调查方针和袭击收尾。过滤越界引文只能校验剩余引文，不会自动迁移错误位置的叙事。此次保留模型原摘要进行诊断性试译，没有把它当作语义验收通过的生产知识；完整 42–44 章双语仍在近章层。后续必须将正文覆盖审查与字符串/引用校验分开。

## 4. 可靠性问题与本地处理

七个摘要请求均正常返回可见内容，`finish_reason=stop`，但直接通过严格校验的数量为 **0/7**：五份首先暴露 JSON 问题，两份首先暴露元信息结构/证据问题。这一事实不因本地恢复成功而改变，也不是输出预留截断导致。

本地处理恢复明确缺失的括号/字段边界、将完全相同且在同章唯一出现的引文定位回原文、拒绝无出处的候选或引文、去除空的未请求区间。第七次响应实际含两份不同 JSON 和解释文字，取模型明确标为最终版本的第二份；同一区间的相邻两段详情只用换行无损拼接，仍校验合计不超过 1000 字。摘要正文没有被本地润色。七次修复分别记录 3、20、2、4、1、11、15 个动作，共 56 个动作；每次变动保存在 `repair-decisions/`，原请求、原输出、失败状态和用量记录保留。动作数量不等于独立语义错误数量。

有些 `coverage_notes` 实际写的是“没有穷举全部技能/神名/物品属性”或“现有译文存在疑点”。这些通过明确的局部备注审查分类，记录原文及哈希，不自动宣称缺失重要事件已解决。真实重大覆盖问题仍需重建，如初次 33–44。相关记录见 `coverage-reviews.json` 和各修复决定；这不是完整摘要语义审查。

抽查还发现一个有可定位引文的错误描述：把 `ドナドロンド` 称为行会长。相关原文区分行会的政策与该人物执行入会测试的职责，所引证据不足以支持该职位判断。汇总时通过 `metadata-description-reviews.json` 拒绝整条描述、不补写替代事实；原始候选保留，其他有出处的教官描述仍可用。

因此，本文验证的是有留痕的开发试验，不能将其表述为无人干预、自动高质量抽取。

总计 114 条块级实体候选、126 条译法记录、22 条固定表达；不是 114 个已消歧人物/实体。同名形式组成 134 个按类别和词形检索的候选组，列出 3 组潜在译法差异，没有已确认实体身份链接。为本章选择 61 条实体候选，53 条未命中省略。工作集元信息文本约 14828 本地 tokens，体积仍偏大：按目标及近章直接子串匹配会召回泛称，各块冲突备注也全部进入消息，且相同人物的多块卡没有语义压缩。

1000 字是上限，不是长度目标；整体摘要实际为 271–400 字，模型没有因提高上限而自动写出更长概括。元信息和证据占据了大量输出。

全文元信息在本试验中指允许的 41 章前缀范围，不是 1323 章全书已完成抽取。汇总不另调用模型；同名条目保留为候选组，没有建立已确认的全书实体合并关系。所有译法为 `observed` 软参考，没有自动升级成 `confirmed`。

元信息工作集按目标及完整近章中的原文形式匹配，并显式配置 `フラン` 为核心形式；未命中的项记录省略理由。保留块级描述、译法与范围，避免重要译名随块进入远层而消失。多张同名卡、同卡多形式以及抽取器自称“全篇固定”的范围均带候选提醒，不授权译文增加原句没有的身份解释。

## 6. 译文的局部检查

两组均为模型原始译文，没有根据目标参考译文修订。以下是日文依据下的局部检查，不是完整盲评或全文语义得分；逐项原句和输出见 [诊断 JSON](../artifacts/translation/tenken-cache-clean/verification/p4.1-v2-main-45/quality-review.json)。

| 检查项 | v2-summary | v2-metadata |
| --- | --- | --- |
| `ガルス` 的既有译名 | 加留斯 | 加留斯 |
| `ギルマス` 是职位 | 主要为行会长，一处简写“行长” | 行会长 |
| `長年E級から昇格できない` | “多年都升不上E级”，晋升方向错误 | “常年从E级升不上去”，方向正确 |
| `娘の間違いでしょ` | “应该是女儿才对吧”，正确 | “该说女儿才对吧”，正确 |
| 契约与誓约 | 保留一对多区别，但省略“一人”的明确限定 | “契约一人只能结一个，誓约则可以结多个” |
| `魔力量もよく分からない` | “魔力量也不清楚” | “魔石值也搞不清楚”，有概念漂移 |
| 状态表阿拉伯数字顺序 | 35 项与原文一致 | 35 项与原文一致 |

含元信息的一组仍有“擅自把我升职的”“疾风如者”“魔獣”等不自然或未简化表达。技能、装备的部分译名仍未与既有用法统一。不能因姓名改善或单句正确就认定全文达标。数字核对只覆盖状态表数字序列，不证明技能译法、全文遗漏或人物关系正确。

旧 H-tiered 曾把 `ガルス` 写成“加尔斯”、把 `ギルマス` 写成“吉玛斯”、把纠正“妹妹/女儿”的对白写成“女儿的错”；两组 v2 都没有复现这些具体错误。但本轮摘要资料增加了 36 章中文，且两组中无元信息的一组也修正这些用法，因此不能把旧新差异单独归因于元信息。

另一个边界是新登场人物 `アマンダ`：在本轮 41 章允许日文前文中没有出现，两组均生成“阿曼达”，而目标参考采用“艾曼达”。严格前缀知识无法提供这一未观察过的既有译名；若以后做允许后文的补缺协议，需独立构建有权限的术语来源，不能回填本折目标译文后再宣称无泄漏对齐。参考译文自身也有数值错误，例如腕力 364、灵巧 23，日文为 327、356；两组新译文保留日文数值。

本次结论仅为：双语信息已真实进入摘要及独立工作集，能够提供既有译名线索；一次未重复的开发章对照不足以证明元信息改善质量，且增加上下文后仍有新增错误。优先处理抽取可靠性、详情区间归属、候选去噪及语义审校，再扩大样本。
