# P6 剩余工作：最小可用方案

日期：2026-10-17。状态：最小实现与五窗口开发/回归验证已完成；工程结果与质量结论分别记录在 [实施报告](translation-p6-mvp-results.md)。实现路径和测试通过，但模型漏检、错误确认、格式阻断及零次自主工具调用意味着本轮不满足翻译质量验收。

本提案根据本轮讨论缩小 [P6原设计](translation-p6-design.md) 和 [剩余问题清单](translation-p6-open-issues.md) 的近期实施范围。历史实验结论保持不变；不把缩小范围记作原阶段验收通过。

## 1. 范围和取舍

保留当前分层索引、同父节点子块串行抽取、不同父节点并发的结构。近期只做三项：抽取失败恢复；翻译、审校、裁决共用的按需正文查证；数字信号检测与裁决闭环。

暂不新增逐条知识语义审查流水线，不把“全部候选已审”设为本最小方案的前置条件。抽取结果继续作为带来源的候选线索，程序仍校验字段、证据ID、范围和引用端点。允许在生成阶段使用候选，但它不能单独支持纠错裁决，不能因为译稿通过审校就自动变成确认事实。

同模型在相同资料上重复审查未必发现新错误。按需查证的作用是把相关正文和历史双语用法带入当前判断，并保留不确定性；它也不能保证模型能主动发现自己没有意识到的错误。为此保留少量明确触发条件和离线回归，不引入另一套全量审查。

暂缓：全局实体自动合并、全书状态推理、自动图补全、独立语义审查服务、递归动态拆块、数字语义专用模型、全面跨模型实验。已有时序／视角实现保留，本轮不扩大其设计范围。

## 2. 已核实的失败机制

| 现象 | 当前证据与解释 | 处理边界 |
| --- | --- | --- |
| 正常停止但缺少结束标记 | `571—580` 原响应 `finish_reason=stop`，实际输出7314 tokens，请求上限16384，thinking禁用；响应末尾有 `@@COVERAGE`，却无 `@@END`。没有证据表明本次因输出上限或思考过长截断。 | 归类为输出协议不完整。不能只提高输出预算，也不能据 `stop` 声称内容完整。具体漏标原因无法从一次响应确定。 |
| 标记粘连、引用列表、字段边界漂移 | 既有脚本已经处理末尾标记粘行、可唯一映射的引用别名、已有字段拆分等。 | 先做确定性的无损恢复；保留原响应及变换记录，不猜缺失事实或证据ID。 |
| 恢复缺少统一调度 | 当前脚本主要通过包装脚本恢复；已有保存响应会被缓存复用，`--retry-failed` 不等同于“解析失败后重新生成”。 | 增加节点级尝试序号和重试策略，避免反复解析同一个失败缓存。 |
| 真正长度截断 | 通用 provider 遇到 `finish_reason=length` 抛出 `truncated`；异常保留用量，正文不在返回结果内。实验 CaptureProvider 已在抛错前保存响应正文。 | 正式恢复路径需保留安全的原始正文、停止原因和用量；不能依赖实验包装脚本才有诊断材料。 |
| 个别引用或条目失败 | 当前解析器已有记录级 accepted/rejected 分区。引用存在也不证明语义正确。 | 一条坏记录不必触发整个节点反复重建；可用摘要和其他记录继续保留，明确局部缺口。 |

证据文件：`scripts/run_sequential_child_extraction.py`、`scripts/refine_sequential_child_extraction.py`、`scripts/settle_sequential_child_extraction.py`、`translation/providers/__init__.py`；历史响应位于 `artifacts/translation/tenken-cache-clean/verification/sequential-child-extraction-501-700-refined/io/parent-501/child-571/`。

## 3. 抽取失败：每节点最多重试两次

默认 `max_retries=2`，即首次加重试合计最多3次物理模型请求。格式修复调用、重新抽取和传输重试共用计数；不允许 SDK／HTTP 层再隐式叠加重试。还受实验总请求数、输入／输出预算限制。预算耗尽或永久错误可提前终止，并明确原因。

先解析原响应并执行无损规范化，不消耗模型重试次数。恢复后的完整结果直接复用；失败则按原因选择下一次尝试：

| 失败类型 | 下一次尝试 | 达到上限后的处理 |
| --- | --- | --- |
| 缺结束标记、格式漂移，已有记录看起来完整 | 至多一次格式转录：提供原响应及具体解析诊断，要求保留所有字段值，仅恢复格式。程序验证内容没有被增加、删除或改写；无法验证则不采用。缺结束标记的修复只恢复协议，不证明抽取全面。 | 若仍有次数，基于同一来源重抽；最终仅保留能独立使用的导航摘要，其他不完整知识隔离。 |
| 空响应、缺摘要、不可解析的主要结构 | 带精简诊断重新抽取当前子块；不重复发送同一个失败缓存。 | 有可用摘要则 `summary_only`，否则 `missing`。 |
| 明确 `length` 截断 | 在真实上下文和总预算允许时提高输出预留，例如从16k到32k，重新抽取同一子块；仍超限则进一步提高可用预留或明确失败，不要求凭空压缩事实以通过解析。 | 回退并标记 `output_limit`。本版不自动递归拆块；后续根据复发率决定是否增加固定分块策略。 |
| 429、服务端错误、网络失败 | 计入同一上限，尊重服务端等待提示并退避；传输超时的新请求使用独立尝试ID。 | 回退并保留诊断。远端结果未知的旧请求保持未知并保守占用预算，不冒充未收费或可免费重试。 |
| 认证失败、无效配置、来源不合法 | 不重试；明确报告运行配置／来源错误。 | 阻断受影响运行，不能伪装为正常索引缺失。 |
| 完整响应中个别坏引用／字段 | 隔离受影响记录及引用它的时间边，保留其他候选，状态为 `partial`。不因一条记录重新抽取整个节点。 | 缺口交给后续按需查证；必要时单独重建节点。 |

只有“输出可解析、摘要可用、协议结束及结构检查通过”才表示抽取任务在工程上成功，不要求每种记录均非空，也不把未发现记录当作该类事实不存在。仍有结构记录隔离时用 `partial`。

成功响应的缓存与失败尝试分开。每次保存 `attempt_id`、父尝试、请求／响应、失败类别、处理动作、预算和最终选用结果。采用新结果时替换该节点的选用版本，不合并不同尝试生成的事件ID集合。重试消耗必须跨进程重启持久化。

节点结果只需要四个工作状态：`extracted`、`partial`、`summary_only`、`missing`，另存 `failure_reason` 和 `semantic_status=candidate_unreviewed`。`extracted` 表示工程协议完整，并不表示所有语义事实均已覆盖。

同一父节点等待当前子节点恢复至成功或耗尽次数后再继续。回退有导航摘要就使用摘要；没有则在前文中显式列出缺口，继续处理后续子块。其他父节点独立运行。对后来补建的节点生成新版本，依赖旧摘要的后继结果标为旧快照；不静默重写或默认重跑整个父节点。

## 4. 按需查证：共用三个只读入口

复用 `translation/state/retrieval.py` 的正文搜索、证据读取，以及 `translation/review/lookup.py` 的节点读取和权限检查，扩展成三个角色共用的适配层。无需引入新的图数据库或通用 agent 框架。

| 接口 | 最小能力 |
| --- | --- |
| `search_evidence(query, range, languages, limit=5)` | 在允许历史范围内检索原文／译文，优先字面专名和别名；返回命中段落、来源和证据ID。 |
| `read_evidence(id, surrounding=2, include_translation=true)` | 返回命中段落及有限邻文、对应历史译文。只有章级对应时明确标为章级，不伪造句级对齐。 |
| `read_index(node_id)` | 返回已有摘要、候选和节点缺口；未构建返回 `not_built`，读取不隐式触发付费抽取。模型可改为读正文。 |

统一返回可见性状态、证据ID、原始文本、来源版本及覆盖缺口。搜索索引若跳过失败文档，必须返回 `partial` 和缺口，不能仍声称完整扫描。搜索没有命中不表示事实不存在。目标参考译文继续不可见。

三种角色均允许“请求资料 → 接收工具结果 → 继续作答”：翻译在最终译文前查证，审校在 findings 前查证，裁决在 decisions 前查证。现有自动循环只覆盖审校；裁决目前只复用已有 lookup，需补齐主动请求能力。

MVP 可沿用平面协议增加一种独立查询消息，包含动作、参数和目的。执行器只允许上述白名单动作，解析完后调用现有函数；不依赖供应商特定的原生工具调用，不把查询文字混进最终译文。旧审校协议通过适配保留。

默认每个角色最多2轮查证；同一章节及修订链共用最多6次不同工具动作与累计返回文本预算，重复相同读取复用缓存。建议返回文本初始软上限为32k tokens，可按实验配置调整；它只限制新增查证资料，不缩小原有模型上下文预算。返回超限时给出明确状态或段落分页，不静默截掉重要部分。修订或角色切换不能重置预算。

为降低“模型没有意识到需要查”的风险，仅增加三项直接触发条件：

- 目标专名没有历史译法时，先尝试一次历史双语查找；不能只依靠摘要实体卡。
- 准备因索引候选而改变说话人、施受方向、时间或知情判断时，须引用当前已见原文；证据不足再查证。
- 存在规则数字信号或正文／摘要冲突时，先核对对应段落，必要时读取历史用法。

无需为了形式重复调用工具；当前上下文已经包含有效正文证据即可引用。疑点未解决时保留歧义和 `unresolved`，不通过知识卡强行补出人名或事实。查证得到的局部结论可以保存为当前任务的证据记录，本版不自动改写全局知识库。

## 5. 数字：规则负责定位，现有审校和裁决负责判断

结构化日中词典与数字候选数据的检索结果见 [词典资源选型](translation-dictionary-resources.md)。本轮已验证小规模SQLite／JSON／JSONL数据可直接读取；词典适配层和数字视图尚未实施。

当前 `translation/review/checks.py` 提取全章数字并比较 Counter，没有保留单位或对象；中文数词只按后一段文字是否像单位来匹配。因此“十分抱歉”匹配为10，“一点”匹配为1，而中文“三十岁”缺少可识别单位。即使全章计数相同，两个对象的数值互换也可能漏过。

改为在现有 S/T 对齐组内提取候选，不再以全章数字多重集合是否相等判断异常。每项保留原始片段、字符位置、段落ID、规范数值、单位和邻近短语。只做 NFKC、阿拉伯数字／常见汉字数词和有限明确单位的规范化；小数用精确十进制，避免浮点比较。范围、约数、分数、日期及单位换算无法可靠解释时保留原表达并交给审校，不写一个完整语言解析器。

比较明确的数量表达时保留单位，必要时结合邻近对象。对齐组中存在多个可能配对项，不按出现顺序或“数值恰好相同”强配；提示模型核对对象归属。规则输出“待核差异”，不直接改文。

| 例子 | MVP处理 |
| --- | --- |
| `30歳 → 三十岁` | 值30、单位年龄，明确等价，不产生差异信号。 |
| `30歳 → 四十岁` | 同一对齐组产生带两侧片段的年龄差异信号，交给审校／裁决。 |
| `精一杯 → 竭尽全力` | 不扫描词内每个汉字数词；无明确数量结构，不发“缺少1”的告警。 |
| `十分抱歉／一点／一个` | 结合局部词形判断，保留少量已知非数量词例外。“一个”有时是真实数量，不能全局屏蔽；歧义表达交给普通语义审校。 |
| `【クアドラ】→【四】`（用户给出的作品用法） | 作为专名用法查证，不能靠通用数词表推导为4。历史双语证据支持时记录作品内译法；没有证据则是术语待查。 |
| `【四重斩】`、`【Lv30】` | 括号只提供术语线索，不整体跳过；明确等级数值仍检查。专名内部数词与外部数量分别处理。 |
| `二人 → 两人`、`三十 → 30` | 常见写法归一；第二例只有结合当前句法／对齐语境才能确认是不是同一数量。 |
| 范围、约数、倍数或单位换算 | 保存限定词和单位；不能只看裸数字集合。例如“约30”与“30”仍可能有语义差异。 |

规则只承诺覆盖明确数量表达。所有信号之外的词义和特殊命名继续属于完整语义审校范围；没有触发规则不能解释为数字语义已经全部检查。

低置信候选是诊断信息，不自动升级为接受阻断项；需要判断的具体差异才建立稳定 `signal_id` 并进入现有审校请求。首版保留少量常见单位和已知误报例外，用案例回归扩展，不追求穷尽词典。

目前裁决只处理 findings，而接受流程单独要求 `signal_decisions`。补齐这个连接：审校对每个正式 signal 给出处置，裁决核对；确认错译则关联 finding，经过修订再检查；可接受等价／规则误报则写入带理由和原文引用的 dismissed；无法判断保留 unresolved。规则本身不自动修改或替模型批准终稿。

通过适配写入现有 `signal_decisions`，不另建接受系统。修订稿重新运行检查，旧裁决仅在版本、片段和证据依赖仍匹配时复用，禁止按相同信号名称批量放行。

## 6. 实施顺序与最小验收

1. **恢复执行器**：统一节点尝试、原响应保存、失败分类、最多两次重试及回退；用缓存和假 provider 验证缺END、粘连、空响应、length、超时和永久错误。尤其验证失败缓存不会阻止新尝试、重启不重置计数。
2. **共用查证循环**：先复用搜索／读段／读节点，接入翻译和裁决，沿用审校流程；用合成角色响应验证查询可执行、证据可返回、预算可终止、未来和目标参考译文不可读取。
3. **数字信号闭环**：按对齐组和片段输出差异，补齐信号裁决；回归本节示例及对象数值互换、术语带数、真正漏译／错译等反例。修复误报不能以删除全部中文数词检测为代价。
4. **小规模真实验证**：先在开发窗口701和1200检查既有修复、译名查找和候选污染；再冻结配置，在三个新窗口做相同基础上下文、模型和采样设置的 B／D 配对。B保持旧分层基线，D使用本最小方案；该对照只能说明整套方案的净变化，不能单独归因于知识、工具或数字检查。

本最小方案验收分开报告：恢复与取证工程是否可用、数字告警是否能闭环、翻译是否有小样本收益。未开展逐条知识审阅时不声明“知识已审通过”。原设计中的 D-reviewed 人工审阅实验臂延后，独立知识审查和完整图谱查询不作为此版本上线前置条件。

真实验证同时统计正确修复、新增严重错误、未解决问题、查证命中、规则误报／漏报、回退率、调用量与tokens。已有修复应保留；若无净改善，只能交付可选的工程功能，不能宣布翻译质量提高。候选数量和格式成功率不替代质量指标。

实现入口位于 `translation/mvp/`，通过 `ReviewSession(evidence_broker=..., request_retries=2)`、`run_checks(profile='p6-mvp')` 和 `review_translation(checks_id=...)` 显式开启。旧默认路径保持兼容。实验命令见实施报告；读工具不会自动付费构建索引。
