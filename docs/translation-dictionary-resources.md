# 日中结构化词典：数字识别与通用检索选型

检索日期：2026-10-17。本轮只检索资源和下载小规模数据验证，未接入翻译管线，未调用模型。

## 结论

有可以直接导入的日中词典，无需先爬取词典网页。建议用 WikDict 日中 SQLite 验证通用查词，结合 Kaikki 的日语数词 JSONL 补充数字候选；扩展中文释义覆盖时再评估 Kaikki 中文维基词典导出。Tomoshi 是更大且字段丰富的候选，但其中文内容包含 LLM 辅助生成及模型审阅，须保留来源属性，不能作为独立人工金标准。

没有在本轮发现一份同时包含“完整日中释义、所有数字及助数表达、可靠数值标签、完整非数字固定词例外”的即用型成品。现成数据可以减少人工维护，但数字检查仍需结合义项、读音、上下文和作品历史用法。

## 3. 最小导入方式

先只导入本轮已验证的 WikDict 日中SQLite和小规模数词子集，建立本地词典适配层。保留完整词典用于通用查询，再从义项派生数字相关视图，不要在导入时把其他词条丢掉。

统一记录最少包含：`headword`、`readings`、`pos`、`senses`、`source_entry_id`、`source_version`、`license`。中文释义可以为空，保留原始释义语言。原词库的分数、标签、生成来源继续保留。

数字视图只需包含：数词、助数／单位、数量相关表达、非数字义项、歧义表达。分类属于义项，不属于整个词头；有可靠依据才填写确定 `numeric_value`，否则为空。前期只人工确认很小的核心值及单位映射，其他结果作为审校线索，避免再启动全词典LLM标注。

查词时优先匹配完整词和读音，再看数词／单位构词。整词匹配帮助避免将词内汉字误读为数字，但不能全局屏蔽所有复合词中的数量。例如“十分”“一杯”都存在真实数量解释。

对模型只增加一个复用现有检索风格的入口，例如 `lookup_dictionary(term, reading=None)`，返回有限义项、中文释义、来源和质量属性。它返回语言知识；作品索引返回人物、事件及本作译法。二者可由同一任务调用，但不混写作品知识卡。

## 4. 对后续通用术语检索的价值

同一词典层可查询固定表达、通用技能词汇、称谓、地名以及共享文化概念。没有证据支持将所有现实专名或每部作品的原创角色／技能名都交给通用词典。

遇到本作已经明确采用的译法，应返回该用法及来源；通用词典提供其他词义和译法候选，不能无条件覆盖本作历史译名。作品中 `クアドラ` 对应“四”的关系应留在作品译法层。
