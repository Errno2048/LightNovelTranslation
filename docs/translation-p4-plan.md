## 1. 本阶段目标与边界

完成一个可独立运行的闭环：从允许的可信双语范围抽取候选约定，审查并冻结折内 K0，通过标题/正文检索和本章实体匹配编译工作集，在相同条件下比较 B 与 C。

- B：邻近、已复核的双语 few-shot。
- C：B + 冻结术语、称谓、风格和简单人物表达卡。
- P4 不增加完整场景状态和人物知情推理；D 仍保留给 P6，不能把本轮检索功能另命名为 D 混淆实验。
- P4 不自动接受生成译文，不实现连续章节知识提交、上下文压缩、通用图数据库或全书摘要。
- 标题/正文索引默认不调用生成或向量模型；真实抽取与翻译单独执行，有硬预算。

### T0：固定输入与契约

实施：

- 读取现有 corpus manifest、quality holds、splits 和对齐审查记录，输出输入清单与哈希。
- 定义 `Evidence`、`Convention`、`Entity/Mention`、最小 `Assertion`、`CoverageRecord`、`Snapshot`、`ContextBundle`。
- 保存故事范围、揭示位置、知识修订三个独立字段；事件/知情结构只定义契约，不宣称已有推理。
- 将旧政策映射为显式的“原文可读/译文可读/用途限制”。目标原文可读、参考译文不可读；保留集边界不放宽。
- 将对齐、实体消歧、摘要、索引和规范名称纳入传递依赖；当前任务原文与参考知识依赖分开记录。

验收：相同输入产生相同指纹；来源变化拒绝沿用旧证据；合成目标原文允许而对应中文标题和正文均被禁止；非法时间/状态组合有明确错误。产物为 `knowledge/p4/input_manifest.json`、schema 版本和政策测试。

### T1：补齐 P4a 审查，建立可用证据

涉及：`translation/alignment/paragraphs.py`、对齐审查入口、`translation/knowledge/evidence.py`；后者在 T2 使用时落地。

实施：

- 增加版本绑定的范围审查补丁，允许接受、拒绝、部分可用、重划分及未决；原候选保留。
- 将“范围对应可信”“译法可作约定证据”“可作 few-shot”“可作评测参考”分别登记，不用一个 reviewed 标志批准所有用途。
- 对已知疑似漏译范围明确排除知识用途；不得把缺失段并入邻段后视为完整对应。
- 增加保守的中日数字等价规范化，覆盖已观察误报；近似量、单位差异仍提示复核，不以无数字告警自动通过。
- 复核三个开发章的拆并、低相似度、疑似遗漏范围及预先固定的普通范围样本；记录数量、方法和仍不确定的项目。
- 为每个目标选允许的 donor 章节/范围，提供知识和 few-shot。目标隐藏译文只能由评测侧读取。
- 现有候选入口仅允许开发集 1–3 章试点；扩展 donor 时需显式 allowlist、版本清单和预算，并继续拒绝保留集/质量阻断数据，不能直接取消限制。

验收：错版本补丁被拒绝；拆并、缺失、重复和跨章附记均保留真实来源；候选不能进入 K0。产物为 `alignment/paragraphs/reviews/`、`knowledge/p4/evidence_catalog.jsonl` 和问题报告。

完成本任务不要求全书段落对齐，也不要求把三个开发章全部认证为语义金标准。只有明确审查的范围具有相应用途资格。

### T2：知识存储与可见视图

涉及：`translation/knowledge/{schemas,store,visibility,evidence,review,service}.py`，迁移必要的 `translation/schemas.py` 与 `translation/evaluation/__init__.py` 政策入口。

实施：

- SQLite 保存版本化实体、约定、最小声明、证据、审查、覆盖状态、依赖与提交。
- 实现 `open_view`、`read_evidence`、`explain`、最小 `commit/freeze/fork/revise/retract`。
- 提交采用 `expected_head` 与幂等键；同键不同内容拒绝，事务失败不留半条接受记录。
- 实现依赖闭包和失效报告；JSON 导出可确定性比较，SQLite 与导出不做双向隐式同步。
- 提供范围适用性判断，未知返回 uncertain；复杂 `get_state/get_timeline/get_neighborhood` 保留到 P6，不放置返回假数据的占位实现。

验收：快照冻结后不能原地修改；修订后旧快照仍可复现；受影响知识和已编译上下文均被定位；未来身份映射不能改变早期视图中的显示名；失败提交、重复提交和旧 head 均有确定结果。

### T3：标题和正文的低成本导航

涉及：`translation/knowledge/retrieval.py`、service 和相关 CLI。

实施：

- 按允许范围建立章节标题、篇章、阅读顺序、正文段落组和邻接索引，保留每个命中的证据 ID。
- 精确别名和字符检索支持短日中名字；为后续 embedding 预留适配器，但默认不生成向量。
- 合并标题、正文、已知别名与知识证据候选。正文无需先命中标题；标题时间词仅作线索。
- 检索统计与 top-k 基于可见范围，不采用全书排序后过滤；隔离索引带政策与语料指纹。
- 返回命中理由、覆盖状态、未决项和邻近范围；陈旧索引拒绝使用。

验收：构建与查询的 provider 调用数均为 0；短名字、标题无关但正文相关、同名歧义和未知覆盖夹具通过；隐藏中文标题不影响结果或排序；相同输入结果稳定。

### T4：有界抽取、候选审查与简单人物卡

涉及：`translation/knowledge/extraction.py`、review、service，复用现有 provider。

实施：

- 实现 `plan_enrichment/run_enrichment`，P4 仅允许术语、称谓、风格和有出处的简单人物表达任务。
- 输入仅含政策允许且对应可信的范围；目标原文可用于列出需求，但生成译文和隐藏参考不得作为已存在的中文约定。
- 输出源形式、译法、别名候选、适用范围、合法变体、证据 ID 和不确定项；本地校验 ID、引用文本和来源资格。
- 相同表面名不自动合并；互相矛盾的译法先区分角色、时间、译者和用途，无法判断则保留冲突。
- 人物表达卡只保存观察到的自称/敬称/双语例句；说话者不明的例句不得直接绑定人物。
- 新增约定先进入 candidate；审查可人工或辅助完成，必须记录具体方法与证据。格式校验成功不等于语义审查通过。
- 格式纠错与重试计入请求预算；截断、非法证据、空结果和失败单独记录。缓存包含范围版本、政策、schema、prompt、模型和配置。

验收：隐藏/隔离证据在请求前被拒绝；伪造 evidence ID 无法接受；同名冲突不被多数表决消除；模型替换产生新缓存身份；相同成功任务重跑 0 新请求。产物为抽取计划、请求/用量日志、候选、决策及覆盖记录。

### T5：折内冻结与工作集编译

涉及：`translation/context/compiler.py`、知识 service、`translation/workflow/__init__.py`。

实施：

- 每个实验折从允许资料建立独立 K0；生产全书 K0 不可作为遮蔽实验输入。
- 编译固定规则、核心约定、本章相关词条、必要例句、B 的同一组 few-shot 和目标原文；保持确定顺序。
- 条件不明的称谓作为候选提示；不全局替换姓名或抹去原文歧义。
- 返回入选证据、未决项、因预算遗漏的候选、计数方式、依赖和指纹。
- 扩展 `build_messages` 支持 C；保留 A/B 入口。C 不增加 P5 修订或 P6 状态分析，确保差异可归因。
- 原文和必要约定装不下时显式失败/待处理；不截断原文。计数无可靠 tokenizer 时采用保守估算并标注，不冒充实测。

验收：相同快照与任务生成相同 bundle；超预算行为可验证；禁用知识时 B 保持原行为；任何注入约定可回查允许证据；修订不会悄悄改写已冻结 C 请求。

### T6：CLI 和小规模执行闭环

已实现 CLI 子命令：`knowledge-bootstrap`、`knowledge-index`、`knowledge-plan`、`knowledge-extract`、`knowledge-review`、`knowledge-freeze`、`knowledge-search`、`knowledge-explain`、`context-build`；现有 `prepare/run/report` 已集成 C 和知识快照身份。C 需显式选择。

实施：

- `knowledge-plan` 和所有 dry-run 不调用 provider，列明范围、缓存可复用项和预算估计。
- `knowledge-extract` 读取冻结的计划及显式请求/token 上限；超出计划不能自动扩大到全书。
- 读查询不触发抽取；工作流可在配置预算内显式发起补充任务。
- 模型请求与本地知识提交分离；超时远端结果未知时保存状态，不无限重试或声称不重复计费。
- CLI 成功、部分失败、政策阻断和预算耗尽可区分。请求日志不保存凭据。
- 知识构建输出与翻译运行输出分开；本阶段未实现译文接受事务，不将草稿变为连续知识来源。

验收：模拟 provider 下完整运行索引→抽取→审查→冻结→编译→B/C；中断后成功抽取结果可复用；只读查询与 dry-run 均 0 新模型调用；输出目录身份冲突拒绝覆盖。

## 5. 真实试验协议和成本上限

### 5.1 样本与参考

- 首批目标仍为 main:3、main:775、main:1233；每个目标单独建立 `single_gap` 折，隐藏其全部参考译文及派生资料。
- 知识 donor 和 few-shot 从该折允许的非保留资料选择；优先邻近范围，再按标题/正文定位术语相关范围。选择清单冻结后才执行抽取。
- 首批 donor 合计不超过 12 章，仅审查并抽取必要范围，不要求完整读完这 12 章。找不到可信范围时记录不足，不能使用隐藏译文补足。
- 原有三章对齐试点是对齐模块的开发证据，不意味着每章自己的参考译文可用于本章 K0。
- 第 3 章等疑似参考错误范围逐项标记；评分以原文忠实性和已审查约定为准，不能因生成没有复现原译错误而扣分。
- 三章 smoke 通过后，才在既有 12 个开发目标中按问题类型扩展；验证/盲测不参与调参。冻结配置后才运行单独验证，报告与开发结果分开。

### 5.2 对照控制

同一目标的 B/C 使用相同原文版本、同一组已复核 few-shot、同一生成模型配置和输出预算。C 只新增冻结约定。旧 P3 基线基于旧语料，不能直接作为本轮唯一 B；应在当前干净语料上重跑或证明所有输入身份完全相同后复用。

首批计划六次整章生成（三章 × B/C）。匿名展示输出并按固定标准审查；无法获得独立人工审查时明确标注审查方式，同模型评分仅作为辅助。保留逐项缺陷及原文依据，不只报告整体偏好。

### 5.3 预算和观测

首批默认上限是实施起点，不是本次文档变更触发的付费任务：

- 基础索引与离线测试：0 生成请求，0 新 embedding 请求。
- 术语/风格抽取：最多 48 个请求，格式修复和重试也计入；仅覆盖冻结 donor 计划。
- B/C 首轮：6 个整章请求；失败重试另记，不能悄悄扩展该六次预算。
- 每个请求的输入估算、输出保留量及整轮累计 token 上限在 dry-run manifest 中显式给出；不得只设置请求数而允许无限大的请求。
- 供应商不返回用量或价格未核实时记录 unknown，不编造费用；保留实际 tokens 和请求数即可比较。

上限不足时先完成可用子集、报告待处理范围，后续扩展形成新计划。全书摘要或全书向量构建不能作为预算耗尽后的自动回退。

记录抽取与翻译分别的输入/输出 tokens、请求数、失败重试、耗时、缓存命中、新增调用、接受知识数和复用次数；同时报告初次构建总成本与后续单章边际成本。

### 5.4 质量指标与通过条件

记录各项分母和逐例证据：术语机会数/误用数、合法变体误报、称谓/指代问题、无依据增义、漏译、适用约定覆盖率、入选证据可回查率、知识冲突和未决项。风格比较保留双语例句和具体差异，不只给总分。

硬门禁：禁用资料进入知识或 prompt 为 0；接受项和注入项证据有效率为 100%；质量阻断不得绕过；原文不静默截断；缓存/预算/失败可审计。真实长程语义召回率不作为 P4 已完成能力声明。

质量结论采用实测：C 应在目标约定错误上显示可回查的改善，且不得新引入经确认的严重语义错误。若 B 原本无对应错误，记录“无足够证据证明改善”；若 C 退化则定位知识/选择/提示原因，不默认启用。三章试验不用于统计显著性或全书泛化声明。
