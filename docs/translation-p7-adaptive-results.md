# P7 输出容错与版本冻结

日期：2026-10-18。本轮将可确定恢复的计数元数据和摘要长度目标改为非阻断处理，保留原响应与质量警告。未放宽引用绑定、语义覆盖、实际 token 硬预算或已确认严重错译的工作准入条件。P8 的长程实验另见 [P8 设计](translation-p8-design.md)。

## 1. 审校协议 audit-v6

旧 audit-v2–v5 的 prompt、few-shot 和读取规则保留。新建连续翻译默认采用 audit-v6，运行清单冻结实际 profile；旧 spec 仍按原版本读取。

新增样例说明正常意译不写 FINDING、只有身份疑点时使用 UNRESOLVED、存在 FINDING 时必须 `zero_findings: no`。规则误报使用 SIGNAL dismissed。裁决提示强调：不能默认接受审校员，修复建议不能重复它指责的主体关系，记录计数不能用来忽略已有问题。

v6 的 `records-v1` 计数策略以完整解析的 FINDING 数量决定有效 `zero_findings`，0 条为 yes，其余为 no。修复只针对 yes/no 计数冲突或缺少计数；未知值、重复 SUMMARY、缺少结束标记等仍报错。保存 `declared_summary`、有效 `summary`、`protocol_warnings`，不修改原响应、不删除或降级 FINDING。UNRESOLVED 和 SIGNAL 不计入 FINDING 数量。

这只是计数归一化，不证明全文没有漏检。`reviewed_all`、`semantic_coverage_complete` 仍由模型显式声明并单独校验；程序不会替模型推断已经检查完。所有实际 FINDING 仍须裁决，有效引用只是可定位，不代表语义正确。

## 2. 摘要长度改为软目标

索引摘要仍提示最多约 2500 字，远期短概括仍提示 400 字，但超长不再自动拒绝、截断或仅为字数再次付费。L2 摘要、L1 汇总和短概括记录 `length_info`：目标字符数、实际字符数、是否超出目标、警告及策略版本。L2 编解码器版本为 `p7-flat-evidence-v2-soft-length`。

L1 可以直接保存正常完成的 3631 字符候选。短概括按实际 tokenizer 估算比较候选与原规范摘要；如果候选反而更长，就保留原规范摘要作为上下文表示，另存模型输出与诊断。更短但超出 400 字的候选仍可使用。

**真实 token 预算仍是硬条件。** 完整索引请求及最终翻译上下文继续经过 1.05 先验、输出预留和固定余量检查；文字长到放不下时仍阻断并导出诊断，不能靠“软长度”绕过模型容量。引用错误、未知 ID、范围越界和缺失子块也继续隔离或阻断。

## 3. 保存结果的零调用回放

产物根：`artifacts/translation/tenken-cache-clean/verification/p7-adaptive-20261018/`。

- 原三个 DeepSeek 分支的 7 份审校报告全部重放，FINDING、段落绑定和证据逐项相等。两份原来仅因计数冲突失败的报告现在可继续进入裁决，警告仍保存。其余五份完整性不变。
- 原 128k 局部探针的 3631 字符父摘要从已落盘响应恢复，记录超长警告。原来已经花费的三次父汇总尝试不抹除，新调用为 0。
- 回放使用原 SQLite 的独立副本和派生输出，原数据库、原失败记录及当时的验收结论保持不变。回放不是把原 audit-v5 输出冒充成新生成的 audit-v6。

入口：`python scripts/verify_p7_adaptive_outputs.py offline`，结果为 `offline-report.json` 及 `summary-replay/parent.json`。

## 4. 三次真实审校验证

使用原失败案例的完整原文、草稿、历史资料与规则信号，替换成 audit-v6 指令及 few-shot；模型仍为本地网关 deepseek-flash。不把参考中文或人工修正答案加入模型输入。本次只审校，不重新翻译、不执行裁决或正式接受。

| 原分支案例 | 旧 FINDING 数 | 新 FINDING 数 | 新 UNRESOLVED 数 | 协议／计数冲突 |
| --- | ---: | ---: | ---: | --- |
| H-baseline 最后一次审校 | 12 | 4 | 1 | 无 |
| H-summary-rollup | 1 | 0 | 0 | 无 |
| U-baseline-rerun 最后一次审校 | 1 | 0 | 0 | 无 |

三次均正常完成，声明与实际记录数一致，不需要使用计数容错。H-summary-rollup 的旧意见本来就说译法可保留、无需修改，新输出仅处置规则信号；U 的同类无差异 FINDING 也未重现。

H-baseline 新输出仍有一条自己说“不构成含义差异、此条不成立、撤回”，却被写成 FINDING；另外几条意见和修复建议仍有主体解释、分段及措辞判断问题。程序保留这些候选供裁决处理，不靠中文关键词直接删意见。**协议稳定性改善不等于语义质量验收通过。** 每例一次调用，不能据此估计长期稳定率。

合计 3 次请求，输入 458,709、输出 1,394、总计 460,103 tokens；缓存命中输入 448,256，未命中 10,453。实际请求、原响应在 `live-http/`，每例完整 prompt、输出及解析报告在 `live/<分支>/`。`live-report.json` 汇总结果。已有输出恢复不会重新调用；请求已发送但结果未知时不自动重置实验。

## 5. 固定版本与边界

本次提交包含此前 P7 连续翻译、知识增量、分层规划、持久恢复、上下文压缩，以及本轮适应性处理和验证脚本。API key、语料、缓存和大体积实验产物继续忽略；用户已有爬虫改动不纳入本次翻译管线提交。

最终验证：`python -m pytest -q tests/translation` 为 **395 passed**，10 条既有第三方依赖警告。`compileall`、相关目录及暂存改动的 `git diff --check` 通过。示例配置可加载并明确选择 audit-v6，旧 profile 兼容和实际 token 硬预算相关回归均通过。

P8 将在该提交上新建独立运行，保持本轮模型、tokenizer、profile 与容量可追踪。不会为了让 51 章连续跑通而自动跳过已确认的严重错译、伪造完整覆盖或从现有中文参考补齐结果。
